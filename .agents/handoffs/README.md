# Agent 任务交接

接手任务时，从交接消息中的分支和文件路径开始。每个任务在工作分支上维护一份 Markdown，文件名使用可辨认的任务名，例如 `fix-session-replay.md`。本目录就是任务清单。

## 写给下一位 agent

1. 从[交接模板](TEMPLATE.md)开始，在仓库根目录运行 `cp -i .agents/handoffs/TEMPLATE.md .agents/handoffs/fix-session-replay.md`，将示例文件名换成当前任务名。已有同一任务的记录时更新原文件。
2. 用一句话写明用户要的结果和验收条件。记录代码所在的分支、最近核对的提交、相关路径和关键决定的原因。OpenSpec、issue 或 PR 已有的细节直接引用。
3. 写出实际运行的命令、结果和仍待确认的判断。给接手者一个能立即执行的下一步。只摘录恢复工作所需的信息，凭据、用户数据和私有终端输出留在原处。
4. 把状态改为 `ready`。跨 worktree 或机器交接时，在工作分支提交交接文件和要交付的改动，并让接手方可获取该提交。交接消息给出分支、交接提交和文件路径。同一工作目录内交接未提交内容时，逐项列明路径。

## 接手和结束

1. 在指定分支打开记录。也可在该分支根目录用下面的命令发现待接任务。
2. 用 `git status --short --branch` 和 `git log -1 --oneline` 核对现场；若代码已前进，用 `git diff <记录中的代码提交> HEAD -- <相关路径>` 检查原结论是否仍适用。
3. 确认自己是指定接手者后，更新负责人、日期和状态为 `active`，执行下一步。同一记录由当前负责人维护；并行子任务各用一份记录，相互引用文件名。
4. 再次交接时，把最新发现、验证结果和下一步写回原文件并恢复 `ready`。达成验收条件后写明结果或 PR，标记 `done`。再次查阅可按文件名使用 `git log -p -- .agents/handoffs/<任务名>.md`。

```sh
rg -l '^状态：ready$' .agents/handoffs -g '*.md' -g '!TEMPLATE.md'
```
