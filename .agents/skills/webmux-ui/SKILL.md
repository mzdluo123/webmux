# WebMux UI 设计与实现指南

适用于页面、组件、布局、交互、移动端、主题与 UI 证据。设计目标是帮助使用者看懂发生了什么、找到下一步，并顺手完成工作。
通用设计原则以[设计系统](../../../docs/design-system.md#design-principles)为准；信息密度、颜色、控件数量和界面形态由任务决定。

## 从用户任务开始

写清以下内容，再进入组件和样式实现：

- 使用者带着什么上下文进入，想了解什么、完成什么。
- 主要对象是什么，打开后默认看到什么，最常用的下一步在哪里。
- 一条完整路径如何完成：进入、判断、操作、结果、失败恢复，以及再次回来继续。
- 桌面如何利用并行空间，手机如何按自然顺序进入内容并返回。

终端围绕操作程序，Git 围绕理解和提交变更，消息围绕阅读与交流，设置围绕修改偏好。
资源模型提供实现依据，页面根据工作过程组织。创建和配置从明确入口按需展开，完成后回到工作对象。
空状态提供可执行的下一步；成熟状态以内容和正在进行的工作为主。正常反馈优先体现在对象变化中，异常提供就近恢复。

## 信息与视觉决策

- 高频操作通过可见名称、熟悉位置和清晰反馈建立直觉。次要操作的呈现方式取决于使用频率、发现成本和任务风险。
- 标题、头像、图标、颜色、表面、分组和动效帮助辨认身份、关系、状态与动作。界面可以丰富，每项表现都说明它服务的理解或操作。
- 操作放在作用对象附近；频道、消息、仓库、工作树各自承担自己的导航和动作。跨层操作标明作用范围。
- 重要上下文可以在导航与详情中重复以支持定位；根据阅读任务控制冗余。手机页头与内容区共同支持方向感。
- 未读、在线、参与者与送达状态来自实际数据。未具备的数据能力在设计说明中标明范围。
- 成熟产品用于验证用户习惯：消息参考常见频道聊天工具，代码和终端参考开发工具；说明借鉴的具体交互及它适合当前任务的原因。

## 实现顺序

1. 阅读相关页面、组件、故事和用户故事，定位当前任务受到的阻碍。
2. 按顺序复用：`web/src/lib/components/ui/` → 业务复合组件 → shadcn-svelte registry。用户已明确方向时直接实现；存在会改变主任务路径的取舍时简要比较方案。
3. 基础控件的外观通过 `ui/` 的 variant/size 扩展，并登记[前端架构守卫](../../../docs/frontend-architecture.md)。使用处的 `class` 控制布局；颜色与尺寸消费语义令牌。
4. 迁移入口、组件、测试与文档，保持同一任务的交互一致。聊天与快速开始共用已有 `ComposerCard`；其他输入体验按真实能力选择可复用控件。
5. 验证完整路径及失败恢复，再提交真实截图与交互证据。

## 组件和行为约束

- 遵循[前端架构](../../../docs/frontend-architecture.md)、[Svelte 规范](../../../docs/frontend-style.md)与[设计系统令牌](../../../docs/design-system.md#tokens)。
- `$state` 用于参与渲染的状态；计算值使用 `$derived`；副作用使用带清理的 `$effect`。`$props()` 显式类型，事件使用 `onclick`，动态列表以业务 ID 为 key。
- 可选功能通过静态可审计的动态入口加载；禁用时无实现 chunk、业务 I/O、计时器或后台探测。
- 所有输入、HTTP 与 WebSocket JSON 按现有 Zod / APIError 契约验证，保留认证与取消语义。
- 使用 Iconify `tabler` 本地图标。图标按钮同时提供可访问名称与可见提示；装饰图标标记 `aria-hidden="true"`。
- 同一行图标控件使用一致尺寸；主导航触控目标为 44px，信息密集区域可使用既有紧凑档位。焦点清楚，包含已有焦点反馈的容器维持一层焦点指示。
- 页面内导航在当前页完成。消息发送等键盘快捷操作处理输入法组合状态，保留换行与草稿，响应丢失时维持重试身份。
- `bind:ref` 使用确定存在的容器或元素；可能为 undefined 的 map 项会触发 `props_invalid_value`，使用容器查询或显式回调。
- 分组与折叠在设计说明中定义边界，使用交错的真实数据验证；方案说明可直接放在当前设计文档或代码注释中。

## 移动端与可访问性

- 为手机安排可完成的列表、详情与返回路径。导航与内容分栏使用断点，用户选择和返回属于业务状态。
- 手机输入至少 16px；软键盘弹出后，输入位置、发送动作与当前内容仍可到达。长内容支持换行和独立滚动。
- 浮层使用现有 Dialog / Drawer / Popover，设置可用视口高度与碰撞边距，验证关闭、返回和焦点恢复。
- 桌面与手机分别验证键盘、触控目标、错误提示和减少动态效果。颜色同时伴随文字或可访问名称。

## 验证与交付

独立检查并行运行，保留产物构建依赖；依据[测试规范](../../../docs/agent-rules/testing.md#agent-local-validation)选择行为测试。

- `pnpm --dir web check`、`lint`、`check:arch` 与 `pnpm --dir web exec vp fmt --check src` 通过。
- 修改控件或设计系统场景时更新 Storybook 并运行相关组件测试；交互变更运行对应 E2E。
- 真实页面或 Storybook 检查桌面、平板、390×844、375×667、320×568；涉及页头和浮层时增加 667×375。覆盖浅深主题、长文本、焦点与页面横向溢出。
- 按[UI PR 证据](../../../docs/agent-rules/testing.md#ui-pull-request-evidence)提供三种代表视口的真实截图；已有界面提供前后对比，交互提供正常速度 GIF。
- 行为变化同步用户故事，并在交付中列出故事 ID、已执行验证和实际限制。无头验证不代表真实悬停、粗指针或真机键盘验证。
