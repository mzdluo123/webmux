# git-workbench-context Specification

## Purpose

为 Git 工作台提供不依赖活动会话的仓库与工作树浏览、差异及历史对象比较上下文，使系统在零运行会话时仍能基于已登记仓库与显式工作树身份安全读取文件、状态快照与明确提交对象，并在不同工作树和仓库之间严格隔离状态与回收生命周期。

## Requirements

### Requirement: 独立于会话的仓库与工作树上下文绑定

系统 SHALL 支持仅凭已登记仓库标识与可选工作树标识建立独立的 Git 上下文，无需存在运行中或已归档的终端及聊天会话，也 MUST NOT 为此创建隐藏会话或进程。

- 仅指定已登记仓库、未指定工作树时，系统 SHALL 核实该仓库的共享 Git 目录身份仍然一致，并返回允许只读浏览提交历史、分支引用与历史对象比较的仓库级上下文，同时明确标记工作区浏览、修改枚举与暂存能力不可用及原因。
- 同时指定已登记仓库与显式工作树时，系统 SHALL 核实该工作树属于目标仓库、根目录为真实存在的常规目录且非符号链接伪造，并同时核实工作树根目录、Git 管理目录与仓库共享 Git 目录的文件系统身份一致。
- 系统 MUST 拒绝客户端直接上传任意文件系统路径猜测工作树或仓库目标；所有上下文均 MUST 通过服务端已登记仓库清单与经核实的工作树身份解析。

#### Scenario: 零活动会话时建立仓库级与工作树级上下文

- **WHEN** 已登记仓库下没有任何活动会话，调用方先后为该仓库本身及其下某个可用工作树请求上下文
- **THEN** 仓库级上下文返回历史与对象比较可读、工作区不可写的原因说明；工作树级上下文返回工作区与修改比较可用，且全程未创建任何会话

#### Scenario: bare 仓库或工作树已缺失锁定

- **WHEN** 已登记仓库为 bare 仓库，或所选工作树目录已被外部删除、移动或替换为其他目录
- **THEN** bare 仓库仅开放仓库级历史与对象读取，不伪造工作区或索引；失效工作树返回身份冲突或不可用状态并保留仓库级历史可读性

#### Scenario: 伪造未登记路径或跨仓库工作树标识

- **WHEN** 调用方传入属于另一已登记仓库的工作树标识，或尝试提交未登记的本地目录路径请求建立上下文
- **THEN** 系统拒绝请求且不读取目标目录内容

### Requirement: 历史提交对象解析与双版本比较边界

系统 SHALL 支持在同一仓库上下文内按两个明确提交对象标识（完整十六进制提交 OID）比较变更文件列表及单文件双侧内容快照，并支持读取指定提交对象下受限路径的完整文件快照。

- 客户端传入的版本标识 MUST 为完整十六进制提交对象 ID；系统 MUST 在服务端校验其确实解析为该仓库内的提交对象，MUST NOT 将分支名、相对修订表达式或命令行选项前缀直接传给底层版本库命令。
- 历史比较生成的文档与差异快照 SHALL 沿用文本大小（2 MiB）、行数（20000 行）、二进制识别、图片安全渲染及内容转换属性检测规则：配置了自定义过滤或工作区编码属性的路径在无法保证原始行映射时 SHALL 明确降级为元信息展示。
- 比较起点与终点顺序由调用方显式指定，系统 SHALL 按“起点为旧侧、终点为新侧”返回增删重命名状态与双方内容，且比较操作 MUST NOT 改变任何工作树的当前分支、`HEAD` 或索引。

#### Scenario: 合法双提交比较与起止交换

- **WHEN** 调用方传入同一仓库内两个存在的完整提交 OID（先后以 `A -> B` 与 `B -> A` 请求比较）
- **THEN** 两次请求分别返回方向相反的变更文件状态及冻结文本差异快照，仓库内所有工作树的 `HEAD` 与索引保持不变

#### Scenario: 非法修订表达式或越界路径被拒绝

- **WHEN** 调用方传入 `HEAD~1`、`--output=/tmp/x`、不存在的对象 ID，或请求路径包含 `..`、绝对路径及 `.git` 内部路径
- **THEN** 系统以参数无效或对象不存在拒绝请求，不执行任意修订解析，也不泄露管理目录内容

### Requirement: 跨上下文快照隔离与无会话回收生命周期

独立仓库/工作树上下文产生的目录游标、修改列表游标与文件/差异内容快照 SHALL 严格绑定所属上下文身份，与既有会话级代码工作区共享内存总预算（64 MiB）但彼此隔离访问权限与生命周期。

- 针对工作树 A 生成的快照标识或分页游标，在工作树 B、另一仓库或任意终端会话上下文中访问时 MUST 被拒绝。
- 工作树根目录、Git 管理目录或共享 Git 目录的文件系统身份发生变化后，旧上下文标识下的后续请求 MUST 返回上下文冲突，迫使调用方重新绑定核实，不得静默落到替换后的目录。
- 独立上下文及其快照 SHALL 按固定存活时间（10 分钟）与最近最少使用（LRU）字节上限自动回收，不因关联工作树下最后一个会话被删除而提前失效，也不因长期无会话而永久驻留内存。

#### Scenario: 切换工作树或删除最后一个会话后的隔离与存活

- **WHEN** 调用方先在工作树 A 获取差异快照，随后删除该工作树上的最后一个终端会话，并尝试从同仓库工作树 B 读取工作树 A 的快照 ID
- **THEN** 工作树 B 的跨上下文读取被拒绝；工作树 A 的独立上下文在未超期且工作树本身仍有效时继续可读，不受会话删除影响
