# repository-registry Specification

## Purpose

为用户提供独立于运行会话的持久仓库清单，通过明确的添加、识别和移除行为组织多个工作树。仓库清单不会成为普通终端启动的前置条件，也不会改变会话及终端缓冲仅存在于服务进程内的生命周期。

## Requirements

### Requirement: 显式注册并归一化仓库

系统 SHALL 接受本机仓库主目录、linked worktree 或其子目录作为注册入口，将共享同一 Git common directory 的路径识别为同一仓库，并返回稳定的仓库标识及规范化路径。添加仓库 SHALL NOT 扫描任意父目录之外的磁盘、自动 clone 或自动 init。

#### Scenario: 从不同 worktree 注册同一仓库

- **WHEN** 用户先添加主工作区，再添加同仓库的 linked worktree 子目录或符号链接别名
- **THEN** 系统返回同一个仓库条目，不产生重复分组，并展示该仓库已存在的 worktree

#### Scenario: 注册普通目录

- **WHEN** 用户尝试把非 Git 目录添加为仓库
- **THEN** 系统返回可理解的错误，不创建 Git 元数据，并保留在该目录直接启动会话的入口

### Requirement: 仓库清单独立持久化

系统 SHALL 在服务端持久保存显式注册的仓库，包括稳定标识和定位信息；注册成功必须表示保存已成功。无会话的仓库 SHALL 继续存在于首页。服务重启 SHALL 恢复仓库清单并重新读取 Git 状态，但 SHALL NOT 恢复 PTY、会话列表或终端缓冲。

#### Scenario: 重启后恢复空仓库分组

- **WHEN** 已注册仓库的所有会话结束，随后服务重启
- **THEN** 仓库和磁盘上仍存在的 worktree 继续展示，旧会话和旧终端缓冲不恢复

#### Scenario: 保存失败

- **WHEN** 添加或移除仓库时持久存储不可写
- **THEN** 操作返回失败，当前已确认的仓库清单保持不变，不向用户报告成功

#### Scenario: 清单损坏

- **WHEN** 服务启动发现仓库清单损坏或不可读取
- **THEN** 系统明确报告仓库管理不可用，不将损坏清单当成空清单覆盖，直接会话功能仍可使用

### Requirement: 移除注册不是删除文件

系统 SHALL 将“从列表移除仓库”与“删除 worktree”区分。移除注册 SHALL NOT 结束会话、删除仓库或工作树目录、删除分支；原有关联会话 SHALL 仍可在直接会话分组访问。

#### Scenario: 移除有运行会话的仓库

- **WHEN** 用户确认从仓库列表移除一个有运行会话的仓库
- **THEN** 仓库不再保留为持久分组，原有会话继续运行且可进入终端，磁盘文件和分支不变

### Requirement: Git 或仓库不可用时局部降级

系统 SHALL 区分 Git 不可用、仓库路径缺失、权限/信任错误和健康仓库，不将错误伪装成没有 worktree。已保存但不可用的仓库 SHALL 保留并展示原因，仓库功能失败 SHALL NOT 阻断其他仓库或普通目录的终端操作。

#### Scenario: 主机没有 Git

- **WHEN** 服务运行环境找不到 Git 可执行程序
- **THEN** 首页解释 Git 管理不可用，禁用依赖 Git 的操作，但用户可以选择存在的目录启动 Shell、agent 或自定义命令

#### Scenario: 仓库被外部移动或权限改变

- **WHEN** 刷新已保存仓库时其定位信息不可用
- **THEN** 系统保留该条目、显示不可用原因并允许移除注册，不擅自 prune、repair、删除文件或修改 safe.directory

### Requirement: 仓库接口沿用安全边界

所有仓库和 worktree 管理请求 SHALL 使用现有认证及 Origin 校验。路径和分支输入 SHALL 作为数据传递，不被解释为额外命令或 Git 选项；配置响应 SHALL NOT 泄露认证凭据。

#### Scenario: 未授权的写请求

- **WHEN** 客户端未通过认证或使用未允许的 Origin 添加仓库、创建或删除 worktree
- **THEN** 请求被拒绝，仓库清单、磁盘与会话状态均不改变

#### Scenario: 输入包含命令或选项字符

- **WHEN** 用户提交包含空格、引号、换行或选项前缀的路径/分支字段
- **THEN** 合法值按原始数据处理，非法值明确拒绝，系统不执行输入拼接产生的命令

### Requirement: 仓库初始化指令

系统 SHALL 允许每个已登记仓库保存一段可选的初始化指令：添加仓库时可填写，之后可修改或清空，最多 4000 个字符。指令与仓库登记一起持久保存，保存成功才报告成功。重复添加同一仓库 SHALL NOT 覆盖已有指令。指令只作为快速开始首条消息的前缀，不会被当作命令执行。

#### Scenario: 添加仓库时设置

- **WHEN** 用户在添加仓库弹窗中填写目录和初始化指令“先读 AGENTS.md，改完运行 make check”后确认
- **THEN** 仓库登记成功，仓库信息中带有这段指令，服务重启后仍然存在

#### Scenario: 修改或清空

- **WHEN** 用户在仓库菜单中打开“初始化指令”，把内容清空后保存
- **THEN** 仓库不再有初始化指令，之后的快速开始不再附带前缀

#### Scenario: 超出长度

- **WHEN** 提交的初始化指令超过 4000 个字符
- **THEN** 请求被拒绝并说明长度限制，已保存的指令保持不变

#### Scenario: 重复添加

- **WHEN** 已设置指令的仓库被再次添加，且这次请求带了不同的指令
- **THEN** 系统返回已有仓库条目，原指令不变，界面提示需要通过“初始化指令”菜单修改

#### Scenario: 旧清单兼容

- **WHEN** 服务读取到不含初始化指令字段的旧版仓库清单
- **THEN** 所有仓库视为没有初始化指令，清单正常加载，不被当成损坏
