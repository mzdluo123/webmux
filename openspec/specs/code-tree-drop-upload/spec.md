# code-tree-drop-upload Specification

## Purpose

支持在代码文件树中拖放上传文件，规定落点目录、上传进度、冲突处理和文件树刷新，使浏览器中的素材能够进入选定的工作目录。

## Requirements

### Requirement: 拖入文件或文件夹上传到文件树目标目录

代码工作区（主页面与独立窗口相同）SHALL 接受从系统拖入的文件与文件夹并上传到当前根目录（工作区或临时目录）下的目标文件夹：

- 落在文件夹行上：上传到该文件夹；
- 落在文件行上：上传到该文件所在的文件夹；
- 落在代码工作区其他位置（导航空白处、文档阅读区等）：上传到当前根目录。

拖动与上传 SHALL 遵循：

- 拖动经过时高亮将接收文件的文件夹行（目标为根目录时高亮根目录行），并提示“松开以上传到 <目录>”；
- 单文件与文件夹内文件使用与“上传到此目录”相同的接口、命名冲突规则、进度显示、取消与结果提示；
- 拖入文件夹时递归扫描目录树（保留嵌套子目录与空目录，跳过 `.git` 目录，受总条目数 10000 项与单文件 100 MiB 上限约束），通过新建目录与文件上传接口依次落盘，顶层目录重名时按 ` (n)` 后缀避让；
- 成功后（以及取消或部分失败前已创建条目时）刷新目标文件夹列表以显示新条目；
- 只处理包含文件或文件夹的拖动；拖动文本、链接或代码工作区内部元素时不触发上传。

#### Scenario: 拖到文件夹

- **WHEN** 用户把两个文件拖到文件树中的 `docs/` 行上并松开
- **THEN** `docs/` 行在拖动经过时高亮，两个文件依次上传到 `docs/` 并显示进度，完成后提示“已上传 …”，`docs/` 展开后可见新文件

#### Scenario: 拖入文件夹

- **WHEN** 用户把包含嵌套子目录、空子目录与 `.git` 目录的文件夹 `assets` 拖到 `docs/` 行上并松开
- **THEN** 系统跳过 `.git`，按原目录层级在 `docs/` 下创建 `assets` 及其子目录（含空目录）并依次上传其中的文件，完成后提示“已上传 assets”并刷新文件树

#### Scenario: 拖到文件行或空白处

- **WHEN** 用户把文件拖到 `src/main.go` 行上松开，再把另一个文件拖到文档阅读区松开
- **THEN** 第一个文件上传到 `src/`，第二个上传到当前根目录

#### Scenario: 独立窗口中拖放

- **WHEN** 代码工作区已弹出到独立窗口，用户把文件拖到独立窗口中的文件夹行
- **THEN** 行为与主页面相同，文件上传到该文件夹，主页面终端不接收该文件

#### Scenario: 重名文件或文件夹

- **WHEN** 拖入的文件或顶层文件夹与目标文件夹中已有条目同名
- **THEN** 按冲突规则取最小可用 ` (n)` 后缀保存（不覆盖已有条目），结果提示列出实际保存的名称

### Requirement: 拖放上传的限制与拒绝

系统 SHALL 在以下情况拒绝拖放上传并在代码工作区内给出明确提示，且 SHALL NOT 上传任何文件：

- 当前根目录不可写（与右键菜单中上传被禁用的条件相同）；
- 拖入内容仅包含 `.git` 目录或超出条目数 / 单文件体积上限；
- 已有代码工作区上传正在进行。

拒绝时拖动经过阶段（可提前判定的只读或上传进行中场景）SHALL 显示不可放置的指示。

#### Scenario: 只读根目录

- **WHEN** 当前根目录不可写，用户拖入文件或文件夹
- **THEN** 拖动经过时显示不可放置，松开后提示无法上传到只读目录，不发起上传

#### Scenario: 仅拖入 .git 目录

- **WHEN** 用户只拖入一个 `.git` 目录
- **THEN** 提示无法上传 `.git` 目录，不创建目录也不上传任何文件

#### Scenario: 上传进行中再次拖入

- **WHEN** 一次上传尚未完成，用户又拖入文件或文件夹
- **THEN** 提示请等待当前上传完成，原上传继续，新内容不上传
