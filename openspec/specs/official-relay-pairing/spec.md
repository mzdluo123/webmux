# official-relay-pairing Specification

## Purpose

规范宿主的全新 Relay 设备配对、机器身份、可恢复授权步骤与页内设置反馈，使本机用户在断线、导航和操作结果未知时仍可核对权威状态，并保持公网启用及安全边界独立。

## Requirements

### Requirement: 仅全新主机配对

WebMux SHALL 在本机生成并保存独立的 Ed25519 中继密钥对。配对 SHALL 使用 v2 接口、有效机器 ID 和新公钥，返回官方验证地址、一次性用户码和有效期供用户完成 GitHub 授权；WebMux 登录 Token MUST NOT 出现在请求中。
私钥、轮询句柄和 GitHub 凭据 MUST NOT 出现在状态响应、诊断、日志或浏览器持久化中。配对失败或过期 SHALL 允许重试，不得改写 WebMux 登录 Token。
已有绑定 SHALL 要求先通过已授权删除，再进行全新配对；客户端 MUST NOT 提供保留域名恢复、rebind 或同机自动换钥。明确拒绝 SHALL 清理待配对密钥及 pending 状态；不确定网络、上游或限流失败 SHALL 保留有效句柄、密钥和取消入口。

#### Scenario: 从设置页完成配对

- **WHEN** 用户打开 Relay 设置、开始配对并在官方页面完成 GitHub 授权
- **THEN** 显示已配对和固定公共地址，本机不保存 GitHub 访问凭据

#### Scenario: 配对接口不包含登录 Token

- **WHEN** 创建或轮询配对请求
- **THEN** 只包含机器 ID、公钥或配对材料，不包含 WebMux 登录 Token

#### Scenario: 账号已有绑定

- **WHEN** 同账号仍存在绑定，即使机器 ID 相同
- **THEN** 普通配对冲突，提示先删除旧绑定，不提供恢复按钮

#### Scenario: 轮询明确拒绝后重试

- **WHEN** 配对轮询返回当前尝试已失败的明确错误
- **THEN** 清理当前句柄和待配对密钥，允许用户重新发起全新配对

#### Scenario: 轮询遇到不确定网络失败

- **WHEN** 轮询遇到网络、上游或限流失败
- **THEN** 保留句柄、密钥和取消入口，不自动换钥

#### Scenario: 取消返回已终止

- **WHEN** 取消当前配对返回句柄已终止的明确错误
- **THEN** 清理当前尝试并刷新状态，允许重新配对；不因不确定取消失败丢弃句柄

### Requirement: 宿主拥有可恢复的设备授权流程

宿主 SHALL 拥有单个活动配对流程、创建及轮询生命周期。专用鉴权本机接口 SHALL 返回用户码、官方验证地址、有效期及明确阶段；公开状态、日志与浏览器持久化 MUST NOT 包含私钥、设备码或轮询句柄。
浏览器切标签、导航、刷新或重连 SHALL 恢复同一流程。初始读取 SHALL 使用稳定局部加载结构，创建 SHALL 防重复并有界等待。
临时网络、上游与限流失败 SHALL 保留同一尝试及取消入口，按返回间隔、Retry-After 与合理退避继续查询。结果未知 SHALL 先核对宿主操作，MUST NOT 自动重放创建。
明确拒绝、过期或取消 SHALL 清理该尝试，下一次创建必须由用户发起。成功 SHALL 以宿主保存的绑定为准并保持公网关闭。重启丢失授权上下文 SHALL 明确报告中断。

#### Scenario: 刷新及导航恢复

- **WHEN** 授权等待期间浏览器刷新或离开再返回
- **THEN** 恢复同一用户码与有效期，宿主继续查询，组件卸载不发送取消

#### Scenario: 临时断网与恢复

- **WHEN** 同一授权查询临时失败后网络恢复
- **THEN** 保留用户下一步及取消入口，退避后继续查询，成功后清除过期故障

#### Scenario: 重复创建与未知结果

- **WHEN** 用户重复点击或创建响应丢失
- **THEN** 核对已有宿主流程，不重复生成密钥或重放上游创建

#### Scenario: 明确终止与取消竞争

- **WHEN** 授权明确拒绝、过期，或取消与成功并发
- **THEN** 呈现串行核对后的权威结果，清理终止尝试，迟到响应不能覆盖新流程

### Requirement: 页内配对任务与渐进诊断

未配对主区 SHALL 展示配对用途、简短信任边界及「使用 GitHub 配对」，不展示不可用的公网开关。
取得验证码后 SHALL 原位展示大号等宽用户码、用户触发复制、GitHub 授权入口、剩余有效期、等待说明与取消；倒计时只表示失效时间。
完成后 SHALL 显示账号与公网开关；就绪时提供地址复制及打开。风险确认 SHALL 说明公网 Shell 和 Relay 可读取转发内容，MUST NOT 声称端到端加密。
WSS 角色数量、TURN、TCP、节点、版本、来源、数字账号 ID、候选路径及未分配端点 SHALL 收入明确次级「连接诊断」，按用途分组。正常流程自动查询，仅异常提供状态核对动作。

#### Scenario: 配对与启用独立

- **WHEN** GitHub 授权成功
- **THEN** 面板显示账号与关闭的公网开关，用户明确确认风险后才启用

#### Scenario: 桌面和手机操作

- **WHEN** 使用窄屏、键盘或读屏浏览配对步骤
- **THEN** 用户码、动作、有效期及错误可访问且无页面横向溢出

### Requirement: 操作核对与删除关闭证据

启停、重连、删除 SHALL 区分提交、待核对、完成与失败，超时后查询已有操作而非盲目重发。
删除 SHALL 位于次级危险操作区，说明旧地址失效与新配对取得新地址。deleted=true/accessClosed=false SHALL 表示记录已删除且旧直连关闭未确认，不无限等待，不阻止新配对，不削弱全局退出严格关闭语义。

#### Scenario: 删除记录与访问关闭独立

- **WHEN** 官方服务确认记录删除但未确认旧访问关闭
- **THEN** 清除本地身份，展示已删除及旧访问未确认关闭警告，并允许用户全新配对

#### Scenario: 变更响应丢失

- **WHEN** 启停或删除请求响应丢失
- **THEN** 可检查宿主已受理操作的真实结果，核对成功后清除旧错误

### Requirement: 独立持久机器身份

宿主 SHALL 首次配对前生成具有至少 128 位随机熵的机器 ID，并独立于 Relay 绑定与私钥持久化。解绑或重新生成中继密钥 SHALL 保留机器 ID。机器 ID SHALL 仅用于同账号判重，MUST NOT 来自硬件指纹或替代 GitHub 授权。损坏或不可写的机器身份 SHALL 阻止新配对并保留原文件。

#### Scenario: 丢失绑定后复用机器身份

- **WHEN** Relay 设置丢失而独立机器身份文件仍完整，用户重新完成同账号授权
- **THEN** 新请求复用原机器 ID；远端旧绑定仍存在时报告冲突，已授权删除后才允许全新配对并取得新地址

#### Scenario: 机器身份损坏

- **WHEN** 独立机器身份文件格式非法、被锁定或写入失败
- **THEN** 配对明确失败，不静默生成替代 ID，不影响现有本地 PTY

### Requirement: 设置操作与删除绑定

WebMux SHALL 在公网访问设置中提供开始配对、启停、自动查询和删除绑定操作，并显示期望开关、运行状态、地址及失败原因；异常处提供核对动作，MUST NOT 提供恢复或重新绑定入口。

删除绑定 SHALL 停止自己的连接与派生访问；官方 Relay 确认记录已删除后，SHALL 清除本地绑定、私钥和待配对密钥，即使旧访问关闭未确认。无法确认删除时 SHALL 保留本地身份以便重试。界面 SHALL 区分记录删除和旧 P2P 访问关闭，不伪造关闭证明，并明确告知新配对取得新地址。

设置操作 SHALL 保留现有 API 认证和 Origin 校验；界面在桌面与手机布局可用，并在当前操作会断开正在使用的公网页面时给出确认提示。

#### Scenario: 成功删除绑定

- **WHEN** 用户确认删除且官方 Relay 确认记录已删除
- **THEN** 自己的连接停止、公共来源撤权、本地私钥与绑定被清除；旧访问未确认关闭时明确警告

#### Scenario: 删除时官方服务不可达

- **WHEN** 用户删除绑定但 Relay 控制面无法确认记录已删除
- **THEN** 本地连接保持关闭，绑定信息保留用于重试，不声称删除或旧访问关闭
