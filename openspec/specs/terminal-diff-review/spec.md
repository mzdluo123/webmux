# terminal-diff-review Specification

## Purpose

让用户在终端旁像浏览代码托管网站一样导航当前工作树、打开多个完整文件、查看未提交差异并展开未修改上下文。代码审阅同时提供真实行号、明确内容版本和更新提示，使任意文件与普通代码行都能进入反馈流程，并保持原有终端交互与生命周期。

## Requirements

### Requirement: 浏览范围绑定会话启动目录或工作树

系统 SHALL 从会话真实启动目录定位当前 Git 工作树，子目录启动浏览所属工作树全貌，不要求注册仓库。非 Git 或 Git 不可用时 SHALL 以启动目录提供普通文件浏览并单独禁用差异能力。界面 SHALL 显示根路径；终端内 cd 不改变绑定，已绑定目标身份失效不得自动切到另一目录。

#### Scenario: linked worktree 中未注册的直接会话

- **WHEN** 用户进入从未注册 linked worktree 子目录启动的会话
- **THEN** 代码区显示该工作树根路径、文件和修改，不混入主工作区或其他工作树，不自动注册仓库

#### Scenario: 普通目录与无 Git

- **WHEN** 会话不在 Git 仓库中，或服务找不到 Git
- **THEN** 用户仍可浏览启动目录下的文件、搜索路径和发送位置，修改导航显示差异不可用的原因

#### Scenario: 已绑定目录被替换

- **WHEN** 根目录或 Git 管理目录被删除或身份改变
- **THEN** 代码区显示目标不可用并禁用位置发送，不悄悄重绑同名目录，终端按自身状态继续运行

### Requirement: 文件树与忽略项可按需浏览

系统 SHALL 提供目录逐层展开、折叠、路径面包屑和文件状态标记，支持未修改、已修改和未跟踪文件。Git 忽略项 SHALL 默认隐藏，并允许显式切换“显示忽略文件”；.git 文件、目录及已识别的 Git 内部管理数据 SHALL 始终不进入浏览与搜索。普通点文件和 .github 等代码目录 SHALL 正常可见。

#### Scenario: 浏览未修改代码

- **WHEN** 用户展开 src 目录并打开一个没有 diff 的文件
- **THEN** 文件正常显示完整内容和行号，不要求该文件出现在修改列表中

#### Scenario: 显示忽略文件

- **WHEN** .env 和 node_modules 被 Git 忽略，用户打开“显示忽略文件”
- **THEN** 文件树可以按需展开这些条目并标记忽略状态，.git 内部数据仍不可见；关闭开关只改变导航过滤，已打开的忽略文件标签仍标明其属性

#### Scenario: 跟踪文件匹配新忽略规则

- **WHEN** 已被 Git 跟踪的文件后来匹配 .gitignore
- **THEN** 默认文件树仍显示该已跟踪文件，不把它误当成被忽略的未跟踪文件隐藏

### Requirement: 路径搜索与文件内查找

系统 SHALL 支持在浏览根内按文件名或相对路径查找文件，结果显示完整相对路径并遵循忽略项开关。打开文本文件后 SHALL 提供文件内查找、上一/下一处匹配及跳转行。文件搜索 SHALL 有取消与结果限制；未完成或受限搜索不得显示为确定没有匹配。

#### Scenario: 同名文件定位

- **WHEN** 用户搜索 index，两个不同目录中都有 index.ts
- **THEN** 结果分别显示相对路径，打开后定位正确文件，并在导航中揭示其所属目录

#### Scenario: 查找完整文件中的普通代码

- **WHEN** 用户在完整文件中查找只存在于无修改区域的文本，或输入有效行号
- **THEN** 阅读器滚动到对应匹配或行号，保持真实文件行号且允许选择该位置

### Requirement: 完整文件只读且可辨识

系统 SHALL 显示所选文件的内容，阅读 SHALL 不编辑、保存或执行代码。

- 文本文件：SHALL 显示完整可读取内容、真实行号、语言高亮、读取时间和来源标签；不支持的语言降级为纯文本。
- 已识别的图片：SHALL 按图片预览能力展示，不受文本 2 MiB / 20000 行上限约束。
- 其余二进制、不可支持编码和超限文件：SHALL 给出文件信息与原因，不将部分内容标为完整。

#### Scenario: 新文件与纯净文件

- **WHEN** 用户打开未跟踪文本或没有任何修改的文本文件
- **THEN** 两者均可从首行阅读至末行，未跟踪状态独立标注，代码阅读不创建或修改 Git 索引

#### Scenario: 文件不可完整展示

- **WHEN** 文件是非图片二进制、编码无法可靠解码或超过读取上限
- **THEN** 展示路径、类型及受限原因，允许可表示路径的文件级引用，不伪造行号或提供未显示的行引用

#### Scenario: 图片文件

- **WHEN** 用户打开根内已识别的 PNG 图片
- **THEN** 面板显示图片预览与元信息而不是“二进制内容”，仍允许文件级引用，不提供行号或行引用

### Requirement: 多文件标签保留独立阅读状态

系统 SHALL 支持打开和关闭多个文件标签，以根、路径和来源区分文档；重复打开同一文档激活已有标签。标签 SHALL 保留各自视图模式、滚动位置、文件内查找及有效选区；切换标签不能将一个文件的选择应用到另一个文件。标签过多 SHALL 可滚动或通过列表切换，达到上限时明确提示，不自动关闭用户标签。

#### Scenario: 两个文件交替阅读

- **WHEN** 用户打开 A、B，在 A 滚到第 200 行，切到 B 后返回 A
- **THEN** A 恢复原阅读位置和仍有效的选择，B 的内容与状态独立，重复打开 A 不增加重复标签

#### Scenario: 同文件不同来源

- **WHEN** 用户打开当前工作区文件，又从已暂存 diff 打开该文件的索引版本
- **THEN** 来源标签明确区分两者，不用索引内容覆盖工作区标签，也不混用行号

### Requirement: 修改来源明确且只读

系统 SHALL 按未暂存、已暂存、未跟踪分组展示修改；同文件可以分别出现在不同来源组。未暂存比较索引与工作区，已暂存比较 HEAD 与索引，未跟踪文本按新增展示，无 HEAD 时索引相对空树。忽略项开关只影响文件浏览，不把忽略文件加入 Git 修改列表。

#### Scenario: 同文件暂存后继续修改

- **WHEN** 用户修改并暂存文件后再次修改
- **THEN** 两组各有对应条目与双方版本，用户可以切换来源但不会把两份差异混成一份

#### Scenario: unborn 仓库

- **WHEN** 仓库尚无 HEAD，索引中有文件且目录中还有未跟踪文件
- **THEN** 索引文件按相对空树的新增展示，未跟踪文件独立分组，不创建提交

### Requirement: 修改列表支持大仓库按需浏览

修改列表 SHALL 按页提供完整枚举能力，不因固定总项数或累计 Git 输出大小拒绝整个仓库；服务端 SHALL 流式读取 NUL 元信息，浏览器 SHALL 按需加载并虚拟渲染列表，避免一次创建全部条目 DOM。路径筛选、打开 / 切换 Diff、刷新及快照检查 SHALL 能访问尚未加载页的目标文件。

#### Scenario: 修改超过一千项

- **WHEN** 仓库存在超过 1000 项未提交修改
- **THEN** 第一页可正常显示，后续页均可加载，无重复 / 遗漏；第一页之外的文件可直接筛选、比较和刷新

#### Scenario: Git 列表累计输出超过两兆字节

- **WHEN** 大量长路径使修改或目录状态输出超过 2 MiB
- **THEN** 逐条处理元信息并提供分页，仍可导航文件和打开比较，不因累计输出大小拒绝整个列表

#### Scenario: 加载后续页时修改列表变化

- **WHEN** 下一页请求的游标版本或筛选条件与当前列表不符
- **THEN** 拒绝混合追加并提示刷新，保留已有可读内容；用户刷新后从一致的第一页继续浏览

### Requirement: Diff 行号与完整来源可互通

系统 SHALL 提供统一 diff、增删标记、双方行号、重命名双方路径及“查看完整文件”操作。新增行只有新行号，删除行只有旧行号；无末尾换行标记不计为代码行。完整文件操作 SHALL 打开明确所选比较侧的完整内容，删除文件仍可打开旧侧。

#### Scenario: 已暂存版本与当前工作区不同

- **WHEN** 用户在已暂存 diff 选择新侧“查看完整文件”
- **THEN** 展示与该 diff 一致的索引版本，而不是后来继续修改过的工作区内容，来源标签为索引

#### Scenario: 删除文件旧侧

- **WHEN** 整个文件被删除，用户选择查看旧侧
- **THEN** 显示对应 HEAD 或索引旧版本的完整文本和旧行号，当前文件树无需伪造该文件仍然存在

### Requirement: 浏览器计算冻结文本差异

服务端 SHALL 返回同一 snapshotId 的比较双方原始完整文本及来源元信息。浏览器 SHALL 使用成熟行级差异库在 Web Worker 中计算文本差异，保持原文件行号及末尾换行语义；上下文展开 SHALL 从已捕获局部模型完成，无需额外网络请求。系统 SHALL 保留虚拟渲染，避免大段删除导致全部代码行同时创建 DOM。

#### Scenario: 计算超限或 Worker 不可用

- **WHEN** 文本差异超过计算预算，或 Worker 启动 / 计算失败
- **THEN** 明确显示失败或受限原因，并提供重试及查看两侧冻结全文入口，不把截断差异称为完整结果

#### Scenario: 刷新或切换后旧计算结束

- **WHEN** 用户切换标签、隐藏代码区、刷新文档或离开会话
- **THEN** 终止对应未完成 Worker，旧计算结果不得覆盖新的活动文档或快照；已完成模型可供同版本标签再次阅读

### Requirement: 未修改上下文可以逐段或全部展开

Diff SHALL 为文件开头、块间和文件末尾省略的普通代码提供向上、向下或全部展开操作，并显示省略行数；展开后的上下文拥有双方真实行号且可选择、引用。无变化文件 SHALL 可直接进入完整文件视图。展开 SHALL 不改变既有增删行号或把普通行标为修改。

#### Scenario: 展开两个修改块之间的函数

- **WHEN** 两个 diff 块之间省略了 80 行，用户分段展开后选择其中未修改的函数行
- **THEN** 展开的代码来自正确版本、行号连续，用户能发送普通行位置，不必先让这些行产生修改

#### Scenario: 查看整份差异上下文

- **WHEN** 用户点击“展开全部”
- **THEN** 在支持的文件大小内展示从首行到末行的全部上下文和修改；若达到限制则明确提示，不将截断结果描述为全部

### Requirement: 后续展开与阅读保持同一内容版本

完整文件、Diff 及其后续上下文展开 SHALL 引用明确内容快照。外部修改发生后，展开已有 Diff SHALL 继续使用原比较双方；原快照失效时 SHALL 要求刷新，不静默混入新内容。旧版本只读期间 SHALL 标示状态，不声称是实时文件。

#### Scenario: agent 改写后展开旧 Diff

- **WHEN** 页面已经显示 Diff，agent 改写文件，用户随后展开省略区域
- **THEN** 新展开部分与原 Diff 属于相同快照，增删行与上下文不混用两个版本，页面提示存在更新

#### Scenario: 快照被回收

- **WHEN** 用户展开或打开旧侧完整文件时，该快照已过期或被内存上限回收
- **THEN** 页面保留已有可读内容并提示需刷新，禁用失效引用，不自动重读当前文件拼接旧 Diff

### Requirement: 桌面代码区与移动端嵌套导航

视口至少 1024 CSS px 时 SHALL 左终端、右代码区，代码区可折叠、可调整宽度；窄屏 SHALL 使用“终端 / 代码”切换，默认终端。代码区内 SHALL 提供“文件 / 修改”导航和文件标签；手机通过可收起的导航面板选择文件，为阅读内容保留空间。布局变化 SHALL 保留同一终端和文档状态。

#### Scenario: 桌面调整空间

- **WHEN** 用户打开文件导航，拖动终端与代码区分隔线，随后折叠并恢复代码区
- **THEN** 代码与终端按可用空间布局，终端收到有效尺寸，原 agent、文件标签和阅读位置保持

#### Scenario: 手机浏览并返回终端

- **WHEN** 用户在 390px 视口进入代码标签、用目录面板打开两个文件后返回终端
- **THEN** 导航选择后可收起，文件标签可以切换且不撑宽页面，后台终端持续接收输出，没有因切标签重建 PTY 或发送零尺寸

### Requirement: 自动检测更新但由用户刷新内容

代码区可见时系统 SHALL 周期检测打开文档和可见导航的变化，显示“内容已更新”及刷新入口，不自动替换已读内容或跳动阅读位置。返回前台、重连及重新显示 SHALL 立即检测；用户点击刷新后更新相关内容，清除失效选择，尽量保留原行附近位置。隐藏代码区或后台 SHALL 暂停周期检测。

#### Scenario: 阅读时 agent 持续写文件

- **WHEN** 当前打开文件被 agent 修改
- **THEN** 可见代码区在下一次成功检测后显示更新提示，原文本、滚动和选区保持，但变旧文档的发送动作暂停；用户刷新后获得新内容并清除旧选区

#### Scenario: 检测失败与响应乱序

- **WHEN** 检测请求失败，或 A 的旧响应在用户切到 B 后才返回
- **THEN** 失败显示状态未知/检测失败，不显示为最新或干净；旧响应只能更新仍匹配的文档，不覆盖 B，下一次成功检测可恢复状态

#### Scenario: 文件被删除后刷新

- **WHEN** 打开的工作区文件被删除，用户点击刷新
- **THEN** 标签显示文件已不存在，不自动关闭标签或改读另一个文件；需要旧内容时明确标为保留快照

### Requirement: 浏览和比较采用有界读取及局部降级

系统 SHALL 限制目录/搜索工作量、内容大小、行数、请求期限、并发和快照内存，逐层读取目录而非首次递归装载全库。单个目录/文件/差异失败 SHALL 不影响其他文档或 PTY。符号链接 SHALL 展示链接本身而不递归读取目标；子模块与嵌套仓库作为边界条目展示，不隐式切换浏览根。

#### Scenario: 大依赖目录与失败文件

- **WHEN** 用户显示忽略项并展开大目录，另一个文件读取失败
- **THEN** 目录采用有界分页或明确的受限状态，失败局限于该文件，终端和已有文档可继续使用

#### Scenario: 链接和仓库边界

- **WHEN** 文件树中存在外部符号链接、子模块或嵌套仓库
- **THEN** 显示链接目标文字或边界摘要，不隐式遍历该目标，其他普通目录正常可浏览

### Requirement: 代码读取沿用会话访问边界

目录、搜索、文件、差异、快照、原始字节和检测接口 SHALL 沿用认证与 Origin 策略，并验证会话、绑定根、路径及来源。

- 完整文件读取 SHALL 允许无修改文件，但拒绝越界、Git 内部数据和跨会话快照引用。
- 文本内容 SHALL 以代码文本渲染，不执行 HTML、脚本或终端控制序列，也不写入日志。
- 已识别图片（含 SVG）SHALL 仅在禁止脚本与外部资源的图片上下文中渲染。

#### Scenario: 未修改文件与非法目标

- **WHEN** 用户读取根内正常未修改文件，或客户端尝试 ../、绝对路径、.git、另一会话的 snapshotId
- **THEN** 前者成功，其余被拒绝且不返回目标内容，不以“仅修改文件白名单”阻挡合法浏览

#### Scenario: 文件包含主动内容

- **WHEN** 源文件包含 HTML、脚本或 ANSI 控制字符
- **THEN** 阅读器作为源码或可辨识转义显示，不执行内容、不改变终端状态

#### Scenario: SVG 包含脚本

- **WHEN** 用户预览含 `<script>` 与外部资源引用的 SVG
- **THEN** 只显示静态图形，脚本不执行、外部资源不加载，源码视图仍按文本显示

### Requirement: 代码区控件按宽度精简

代码面板 SHALL 将导航开关、文件标签条、刷新全部和独立窗口入口放在同一行，标签过多时标签条在该行内横向滚动。

- 代码根路径 SHALL 作为刷新全部按钮提示的一部分，并在导航状态正常时显示在导航面板顶部。
- 导航状态异常（目录或修改列表已更新、检测失败）时，导航面板顶部 SHALL 以该提示和“刷新导航”替代根路径。
- 导航状态异常且导航收起时，导航开关 SHALL 显示提醒标记并在提示中给出状态。

文档栏在宽屏 SHALL 保持单行：文档路径（过长时保留末尾）、“查看 Diff / 返回文件”、SVG 的“预览 / 源码”、图片 Diff 的预览来源，以及 Diff 的“完整文件”菜单。重命名双方路径可另起一行。

视口宽度小于 640 CSS px 时：

- 独立窗口入口 SHALL 不显示。
- 文档栏的上述操作 SHALL 收进标签行末尾的代码区菜单。菜单 SHALL 显示文档完整路径（重命名时同时显示双方路径），并提供“查看 Diff / 返回文件”、SVG 显示方式单选、图片 Diff 预览来源单选、“修改前的文件 / 修改后的文件”和“刷新文档”。各项与宽屏控件使用同一处理函数和禁用条件。
- 文档的提示信息 SHALL 继续直接显示，不收进菜单：图片变化与大小、内容已更新/文件已不存在/快照已过期/检测失败及其“刷新文档”、不可完整展示的原因、SVG 预览回退说明。
- Diff 工具栏 SHALL 保持单行：增删统计、查找与自动换行。
- 菜单 SHALL 避开状态栏与主屏幕指示条，内容超出可用高度时在菜单内滚动。来源选择使用菜单单选项，不使用会让 iOS 聚焦放大页面的小号 `<select>`。

主屏幕 Web App（`display-mode: standalone`）中，浏览器不支持 Document Picture-in-Picture 且设备带触摸屏时，独立窗口入口 SHALL 不显示（任何宽度），因为弹出的页面会以 App 内浏览器形式覆盖终端。没有触摸屏的桌面 Web App（如 macOS Safari 的 Web App）SHALL 继续按现有规则提供普通弹出窗口。

#### Scenario: 手机 Diff 视图的内容空间

- **WHEN** 在 393×851 视口打开一个文本 Diff
- **THEN** 终端顶栏下方依次为单行标签栏、单行 Diff 工具栏、代码内容和单行操作栏，无横向溢出；代码内容区高度不少于视口高度的 70%

#### Scenario: 手机从菜单打开完整文件

- **WHEN** 手机用户在 Diff 中打开代码区菜单，选择“修改前的文件”
- **THEN** 菜单显示该文件的完整路径；修改前的完整内容在新标签中打开并激活，原 Diff 标签保留

#### Scenario: 手机仍能看到文档提示

- **WHEN** 手机上已打开的文档被外部修改，或打开二进制文件
- **THEN** 文档上方直接显示“内容已更新”和“刷新文档”，或不可展示的原因；无需打开菜单

#### Scenario: 桌面文档栏单行

- **WHEN** 在 1440 px 视口、代码区默认宽度下打开一个 Diff
- **THEN** 标签栏与刷新全部在同一行，文档路径与“完整文件”在同一行，根路径显示在导航面板顶部，不显示代码区菜单

#### Scenario: iOS 主屏幕 Web App 中的代码区菜单

- **WHEN** iOS 27 iPhone 主屏幕 Web App 中打开一个 Diff，再打开代码区菜单
- **THEN** 菜单完整位于状态栏与主屏幕指示条之间，项目过多时可在菜单内滚动；切换预览来源时页面不放大

#### Scenario: iPad 主屏幕 Web App 隐藏独立窗口

- **WHEN** 连接触控板的 iPadOS 27 设备在主屏幕 Web App 中以宽屏打开代码区
- **THEN** 不显示独立窗口入口；同一设备在 Safari 标签页中按现有规则显示

#### Scenario: 桌面 Web App 保留独立窗口

- **WHEN** macOS Safari 用户在没有触摸屏的 Mac 上从 Dock 中的 Web App 打开代码区
- **THEN** 独立窗口入口照常显示，点击后打开普通弹出窗口
