# quick-start-chat Specification

## Purpose

快速开始聊天让用户在一个聊天式输入框里写下任务、选择仓库和 agent，按一次发送即在新 worktree 中启动聊天会话并开始工作，省去手动创建 worktree、选启动配置和等待聊天就绪这几步。

## Requirements

### Requirement: 快速开始页面

系统 SHALL 提供快速开始页面 `/new`，作为聊天模式的主区域（见 `app-shell`）。入口是左上角的“聊天”模式按钮和聊天侧栏的“新聊天”，都在当前标签页打开。

- 页面底部 SHALL 是消息输入框，附近放仓库、工作树方式（新建 worktree 与基准分支，或已有工作树）、agent、agent 会话配置和权限模式的选择控件，窄屏下也都能直接操作、不被截断。
- 仓库列出全部已登记仓库。
- 工作树方式弹出面板顶部提供“新建 worktree | 已有工作树”切换：选择“新建 worktree”时列出本地与远程基准分支，选择“已有工作树”时列出所选仓库的工作树（不可用的禁用并说明原因）。
- agent 只列出勾选了混合模式的已保存启动配置，与新建会话弹窗中可以从聊天开始的配置相同。

#### Scenario: 打开快速开始

- **WHEN** 用户在工作台模式点击左上角的“聊天”按钮
- **THEN** 当前标签页显示快速开始页面，焦点在消息输入框，仓库、工作树方式（基准分支或已有工作树）和 agent 已按上次的选择或默认值填好

#### Scenario: 没有可用仓库或 agent

- **WHEN** 没有可用的已登记仓库，或没有勾选混合模式的启动配置
- **THEN** 发送按钮禁用，输入框上方说明缺少什么，并提供“添加仓库”或“新建启动配置”入口

#### Scenario: 不可用的仓库

- **WHEN** 某个已登记仓库当前不可用（路径缺失、Git 不可用或无权限）
- **THEN** 仓库菜单中该项禁用并显示原因，不能被选中

### Requirement: 选择记忆与默认值

系统 SHALL 在本设备记住上次快速开始成功时选择的仓库、agent 以及工作树方式（新建 worktree 或所选的已有工作树），作为下次的默认值：

- 记住的仓库或 agent 不存在或不可用时，回退到第一个可用项。
- 记住的已有工作树不存在或不可用时，回退到所选仓库的主工作区（或第一个可用工作树）。
- 新建 worktree 模式下基准分支默认取所选仓库主工作区当前的分支，切换仓库时重新计算。

#### Scenario: 记住的 agent 已被删除

- **WHEN** 上次使用的启动配置已被删除，用户再次打开快速开始
- **THEN** agent 选择回退到第一个勾选混合模式的启动配置，且不报错

#### Scenario: 切换仓库

- **WHEN** 用户在仓库菜单中改选另一个仓库
- **THEN** 新建 worktree 模式下基准分支改为该仓库主工作区当前的分支，已有工作树模式下改为该仓库的主工作区，初始化指令提示随之更新

#### Scenario: 切换为已有工作树

- **WHEN** 用户在工作树弹出面板中切到“已有工作树”并选择某个工作树后发送
- **THEN** 系统不创建新 worktree，直接在该工作树中启动会话并发送首条消息，并记住下次默认使用该工作树

### Requirement: 启动前展示 agent 会话配置

选定 agent 后，系统 SHALL 在输入框下方展示该启动配置最近一次聊天会话报告的配置项（如模型、思考强度、模式）及其可选值，默认值为该次会话最后使用的值。

- 还没有记录时，配置区 SHALL 说明“首次启动后可选”。
- 页面显示的配置值 SHALL 就是新会话实际得到的值：会话按 argv 播种配置之后，系统把显示的每一项（预选值或用户改过的值）与播种结果比较，对不同的项应用显示的值。
- 权限模式由 WebMux 提供，始终可选。

#### Scenario: 有配置清单

- **WHEN** 用户选择以前用过的 agent，并把“思考”改为 high
- **THEN** 新会话启动后、首条消息发送前，思考配置已是 high

#### Scenario: 没有配置清单

- **WHEN** 用户选择一个从未以聊天端启动过的 agent
- **THEN** 配置区只显示权限模式和“首次启动后可选”说明，发送仍可用，会话按 argv 播种和 agent 默认值配置

#### Scenario: 记住的配置值已失效

- **WHEN** 预选的配置值不在 agent 本次启动报告的可选值内
- **THEN** 系统保留 agent 的当前值，照常发送首条消息，并在聊天中显示一条说明哪项配置未能应用的提示

### Requirement: 一次发送完成创建与开工

用户发送非空消息后，系统 SHALL 依次完成：在所选仓库基于基准分支新建 worktree（自动生成不冲突的分支名和路径）、以 `startSide: acp` 创建混合会话、应用预选配置和权限模式、把首条消息作为第一轮提示发送。首条提示由服务端发送，浏览器在过程中断开也不影响。全部成功后，页面在当前标签页进入新会话的聊天视图。

#### Scenario: 成功开工

- **WHEN** 用户输入“修复首页排序”，选择仓库 webmux 和 agent Claude Code 后按发送
- **THEN** webmux 多出一个基于基准分支的新 worktree，新会话以聊天端运行在其中，第一条用户消息已发出，页面进入该会话的聊天视图

#### Scenario: 发送过程中关闭页面

- **WHEN** 用户按发送后、页面跳转前关闭了浏览器
- **THEN** worktree、会话和首条消息照常完成，用户稍后在首页的该仓库下能看到正在工作的会话

#### Scenario: 会话名称

- **WHEN** 快速开始创建会话
- **THEN** 会话不带显式名称，标题按现有规则跟随 agent 报告的标题

### Requirement: 快速开始只是混合会话的另一个入口

快速开始创建的会话 SHALL 是标准混合会话，与在新建会话弹窗中选择“新建 worktree + 混合配置 + 从聊天开始”再手动发送第一条消息的结果一致。会话列表、会话详情和混合会话记录 SHALL NOT 带有“由快速开始创建”的字段或其他差异；之后的切换、恢复、关闭、归档和删除 worktree 都按现有规则进行。

#### Scenario: 切到终端

- **WHEN** 用户在快速开始创建的会话中切到终端，再切回聊天
- **THEN** 切换按 `hybrid-sessions` 的规则进行，配置与聊天记录的表现和其他混合会话相同

#### Scenario: 首页与归档

- **WHEN** 快速开始创建的会话运行一段时间后被关闭
- **THEN** 它运行时出现在首页对应仓库的 worktree 分组里，关闭后作为归档记录出现在原处，可以按现有流程恢复

#### Scenario: agent 需要登录

- **WHEN** 首条提示发出后 agent 返回 `auth_required`
- **THEN** 快速开始视为已完成并进入聊天视图，由聊天视图按现有规则显示提示和“切到终端登录”按钮

### Requirement: 首条消息合并仓库初始化指令

所选仓库设置了初始化指令时，输入框上方 SHALL 提供“使用初始化指令”选择：从聊天开始时默认选中，从终端开始时默认不选中，因为初始化指令通常是给 agent 的自然语言。用户的手动选择 SHALL 在该次发送内保留；发送成功后或切换仓库时 SHALL 恢复按起始端的默认值。

只有选中时，首条提示 SHALL 是初始化指令、一个空行、用户输入，三者按此顺序拼接。点击提示 SHALL 可查看全文。聊天记录中的第一条用户消息 SHALL 显示实际发送的完整文本。

#### Scenario: 聊天开始附带初始化指令

- **WHEN** 仓库的初始化指令是“先读 AGENTS.md”，用户从聊天开始，保持默认选中，输入“修复首页排序”后发送
- **THEN** agent 收到的第一轮提示是“先读 AGENTS.md\n\n修复首页排序”，聊天中第一条用户消息显示同样的文字

#### Scenario: 终端开始默认不附带初始化指令

- **WHEN** 仓库的初始化指令是“先读 AGENTS.md”，用户从终端开始并保持默认不选中
- **THEN** 首条提示只有用户输入，agent 不会收到初始化指令

#### Scenario: 仓库没有初始化指令

- **WHEN** 所选仓库没有初始化指令
- **THEN** 输入框上方不显示提示，首条提示就是用户输入

### Requirement: 重复提交不产生重复资源

每次快速开始请求 SHALL 带客户端生成的请求 ID。同一请求 ID 在第一次执行进行中或完成后 10 分钟内重复提交时，系统 SHALL 等待并返回第一次执行的结果，不得再创建 worktree、会话或提示。超出这个窗口的同 ID 请求按新请求执行。发送期间输入框和发送按钮禁用，并显示“正在创建 worktree 并启动 agent”的进行中状态。

#### Scenario: 网络重试

- **WHEN** 首次请求已在服务端执行，响应丢失，前端用同一请求 ID 重试
- **THEN** 服务端返回同一个会话，仓库中只有一个新 worktree

### Requirement: 失败时报告进度并保留输入

任一步骤失败时，系统 SHALL 停止后续步骤，页面保留在快速开始并保留输入文字，说明失败的步骤和原因。已完成步骤创建的资源 SHALL 保留且不自动删除：已创建的 worktree 在错误中可直接打开；会话已启动但首条提示发送失败时，提供进入该会话的入口，文字留在输入框中供手动发送。

#### Scenario: 创建 worktree 失败

- **WHEN** 基准分支已被删除，worktree 创建失败
- **THEN** 页面显示“创建 worktree 失败”和 Git 给出的原因，没有启动会话，输入文字保留

#### Scenario: agent 启动失败

- **WHEN** worktree 已创建，但 agent 的 ACP 进程在初始化阶段退出
- **THEN** 页面说明 agent 启动失败及原因，并显示已创建的 worktree 路径和“在此 worktree 新建会话”入口；worktree 不被删除

### Requirement: 快速开始沿用安全边界

快速开始接口 SHALL 使用现有认证和 Origin 校验。仓库、启动配置、基准分支和配置项都按标识或数据传递，不拼接成命令；请求 SHALL NOT 携带任意命令或环境变量，agent 只能来自已保存的启动配置。能在创建前判断的条件（仓库可用、启动配置勾选了混合模式、第三方连接器已安装）SHALL 在创建 worktree 之前校验。

#### Scenario: 未授权请求

- **WHEN** 未通过认证或 Origin 不被允许的客户端提交快速开始
- **THEN** 请求被拒绝，不创建 worktree、会话或提示

#### Scenario: 未勾选混合模式的启动配置

- **WHEN** 请求的启动配置没有勾选混合模式
- **THEN** 请求被拒绝并说明原因，不创建 worktree

#### Scenario: 连接器未安装

- **WHEN** 所选 agent 需要第三方 ACP 连接器但尚未安装
- **THEN** 请求按 `hybrid-sessions` 的规则返回 `connector_missing`，页面显示安装指引，不创建 worktree
