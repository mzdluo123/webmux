# workbench-navigation Specification

## Purpose
工作台导航树在工作台模式的侧栏中按“仓库 → worktree → 会话”展示全部运行中的会话，让用户不离开当前页面就能看到每个 agent 在哪个仓库和工作树里、处于什么状态，并直接跳转。

## Requirements

### Requirement: 树的结构

工作台侧栏 SHALL 显示一棵导航树，取代现有首页左侧的仓库筛选列表：

- 第一层：“全部仓库”、每个已登记仓库，最后是“直接会话”。
- 第二层：仓库下的主工作区和 linked worktree，顺序与首页分组一致。
- 第三层：该工作树下运行中的会话，包括终端会话和混合会话，与首页卡片一样按创建时间从新到旧排列，会话输出不改变顺序。

已归档的会话记录不进树，仍在主区域的归档分组中显示。仓库和工作树的顺序 SHALL NOT 因会话输出而变化。

#### Scenario: 同一工作树有两个 agent
- **WHEN** webmux 主工作区里同时运行一个 Claude Code 混合会话和一个 Shell
- **THEN** 树中 webmux → main 下有两行会话，各自显示 agent 或命令图标和状态

#### Scenario: 不可用的仓库
- **WHEN** 某个已登记仓库当前不可用
- **THEN** 树中该仓库保留，标出不可用并在提示中说明原因，下面不显示工作树

### Requirement: 节点的行为

点击节点 SHALL 在当前标签页导航，并与现有首页的仓库视图保持一致：

- 点“全部仓库”、某个仓库或“直接会话”时，进入工作台首页并选中对应视图，效果与现有仓库筛选相同。
- 点工作树时，进入工作台首页，主区域只显示这个工作树下的会话和归档记录，标题为“仓库 · 工作树”。
- 点会话时，按下一条“从工作台打开会话”的规则进入 `/s/{id}`。

当前所在的视图或会话 SHALL 用 `aria-current` 标记。

#### Scenario: 从会话页回到某个工作树
- **WHEN** 用户在会话页点击树中另一个仓库的 feature 工作树
- **THEN** 当前标签页进入工作台首页，主区域只显示这个工作树下的会话

#### Scenario: 当前会话高亮
- **WHEN** 用户打开某个会话
- **THEN** 树中该会话所在的仓库和工作树自动展开，会话行标为当前项

### Requirement: 从工作台打开会话

在工作台模式下打开会话时（点击树中的会话行，或主区域的会话卡片），系统 SHALL 按会话当前所在的端决定模式：

- 混合会话处于聊天端（`acp`）：自动切到聊天模式，侧栏换成聊天历史并选中该会话，主区域显示它的聊天视图；记住的模式随之改为聊天。
- 其他会话（普通终端会话、处于终端端的混合会话、切换中的混合会话）：保持工作台模式，主区域显示该会话的终端，侧栏仍是导航树并选中该会话。

模式只在打开时决定一次。打开后会话在两端之间切换，SHALL NOT 再自动改变模式。通过地址直接打开或刷新会话页时，使用记住的模式，不自动切换。

#### Scenario: 打开运行中的终端会话
- **WHEN** 用户在工作台树中点击 webmux → brisk-otter 下运行中的 `pnpm dev`
- **THEN** 侧栏仍是导航树并选中这一行，右侧主区域显示该会话的终端

#### Scenario: 打开处于聊天端的混合会话
- **WHEN** 用户在工作台树中点击正在聊天端工作的 Claude Code 会话
- **THEN** 整个界面切到聊天模式：左上角“聊天”按钮为选中态，侧栏显示聊天历史并选中该会话，主区域显示它的聊天视图

#### Scenario: 打开处于终端端的混合会话
- **WHEN** 用户在工作台树中点击一个已切到终端的混合会话
- **THEN** 保持工作台模式，主区域显示它的终端；会话页仍可按现有规则切回聊天，切回后模式不变

### Requirement: 仓库节点操作菜单

工作台侧栏导航树中，每个仓库节点 SHALL 在行尾提供一个“⋯”操作菜单按钮，可用仓库的菜单依次提供：

- “新建工作树…”：打开现有的新建工作树弹窗，预选该仓库，默认只创建工作树，勾选“创建后启动会话”后才启动会话；
- “主页显示…”：打开该仓库的主页工作树选择弹层；
- “管理工作树…”：打开该仓库的仓库面板并定位到“工作树”分区；
- “仓库详情…”：打开该仓库的仓库面板并定位到“概览”分区。

交互与可用性规则：

- 菜单按钮 SHALL 具备“仓库操作：{仓库名}”的可访问名称与可见提示；
- 桌面端在仓库行悬停、获得焦点或菜单展开时显示，触屏设备上始终显示；
- 仓库不可用时，菜单 SHALL 只提供“仓库详情…”，以便查看原因并移除登记；仓库清单或 Git 不可用时，按钮不显示。

#### Scenario: 从会话页新建工作树

- **WHEN** 用户在会话页的工作台侧栏打开 `webmux` 仓库行的“⋯”菜单并选择“新建工作树…”，填写分支后确认
- **THEN** 打开现有的新建工作树弹窗，创建成功后新工作树出现在树中 `webmux` 下；当前会话页保持不变

#### Scenario: 勾选创建后启动会话

- **WHEN** 用户通过侧栏仓库菜单打开新建工作树弹窗，勾选“创建后启动会话”并选择一个启动配置
- **THEN** 结果与从仓库标题栏进入时相同：创建工作树并启动会话，进入该会话

#### Scenario: 从侧栏打开批量工作树管理

- **WHEN** 用户在工作台侧栏打开 `webmux` 仓库行的“⋯”菜单并选择“管理工作树…”
- **THEN** 打开 `webmux` 的仓库面板并停在“工作树”分区，展示该仓库全部工作树供查看、筛选与批量清理，不离开当前页面

#### Scenario: 不可用的仓库

- **WHEN** 仓库路径缺失
- **THEN** 该仓库节点的“⋯”菜单只有“仓库详情…”，节点提示中说明不可用原因

### Requirement: 展开状态与计数

仓库和工作树节点 SHALL 可以单独展开和收起，展开状态保存在本设备。节点 SHALL 显示下层运行中会话的数量；有等待中的会话时，即使节点收起，也 SHALL 显示等待数量和注意色。新出现的仓库默认展开，工作树默认收起。

#### Scenario: 收起的工作树里有会话进入等待
- **WHEN** 一个收起的工作树下的 agent 请求权限
- **THEN** 该工作树和所属仓库节点都显示等待数量，不需要展开就能发现

### Requirement: 会话行的内容

会话行 SHALL 显示标题、图标和状态。混合会话用 agent 图标，其他会话用启动配置图标，没有图标时用终端图标。状态与 `chat-sidebar` 相同（工作中、等待、空闲、已结束），用颜色加文字或可访问名称表达。标题过长时截断，并保留完整标题的提示。

#### Scenario: 已退出的终端会话
- **WHEN** 一个 Shell 会话已退出但还没被关闭
- **THEN** 树中该行显示“已结束”，点击仍进入会话页查看最后输出

### Requirement: 键盘与读屏

导航树 SHALL 使用 `tree`/`treeitem` 语义：上下方向键在可见节点间移动，左右方向键收起或展开，Enter 激活节点。

#### Scenario: 键盘浏览
- **WHEN** 键盘用户在树中按右方向键展开仓库，再按下方向键
- **THEN** 焦点移到该仓库的第一个工作树，读屏会读出它的层级和展开状态

### Requirement: 工作树节点操作菜单

工作台侧栏导航树中，每个工作树节点 SHALL 在行尾提供“⋯”操作菜单，取代原有的单一删除按钮。菜单 SHALL 提供：

- “工作树详情…”：打开该工作树的详情；
- “删除 worktree…”：仅对可删除的 linked worktree 提供，进入现有删除确认流程。

菜单按钮 SHALL 具备“工作树操作：{工作树名}”的可访问名称与可见提示，显隐规则与仓库节点菜单一致。

#### Scenario: 从侧栏查看工作树详情

- **WHEN** 用户在侧栏打开 `webmux → feat-login` 行的“⋯”菜单并选择“工作树详情…”
- **THEN** 打开 `feat-login` 的工作树详情，显示分支与上游、最近提交、修改统计和会话统计，当前页面不变

#### Scenario: 主工作区没有删除项

- **WHEN** 用户打开主工作区节点的“⋯”菜单
- **THEN** 菜单只有“工作树详情…”，没有“删除 worktree…”
