# Proposal

## Why

运行中的会话页同时在页顶与停靠组显示「聊天 / 终端」。当两个会话并排时，用户难以判断按钮作用于哪个会话。首次浏览文件还要从「打开面板 → 代码」进入，未选文件就出现空阅读器并挤窄文件树。

## What Changes

- **BREAKING**：会话页的停靠单位改为会话窗格。聊天与终端是同一窗格的显示方式，切换入口随窗格移动。迁移已保存的双视图布局。
- 工作区顶栏负责导航、文件浏览、布局和当前会话的视图切换及操作；手机会话标题行保留名称和连接状态。
- 一步打开来源会话的文件树，选择文件后才显示阅读器。每个文件独立停靠，常规打开在同会话阅读组中新增或定位文件标签，显式「在右侧打开」支持并排比较。
- 桌面会话工作区可将窗格收起到边栏，点击带名称的标签直接恢复原分组与比例。
- 手机保留单面板浏览与返回路径；新建、加入、分屏、收起与恢复仍可达。

## Capabilities

### New Capabilities

无。沿用既有顶栏能力及两份在途变更的能力路径。

### Modified Capabilities

- `session-panel-workbench`：修订会话侧停靠单位、布局与视图的边界、文件阅读以及手机投影；Git 工作台沿用原契约。
- `terminal-header`：区分工作区顶栏与窗格标题栏，调整桌面和窄屏的操作归属。
- `terminal-side-panel`：文件浏览与布局选择分为两个入口，替换固定「代码 / 分屏」选择页。

## Impact

前端涉及会话页面、停靠布局恢复、混合视图控件、代码导航与阅读器。保留现有会话协议、控制权、代码访问边界及独立代码窗口行为。
依赖 `mobile-panel-picker-sheet`、`dock-session-panels` 的规格基线；归档顺序和旧布局处理见设计。
受影响故事：US-D13、US-D14、US-H08、US-I01、US-I04、US-Q01。本次仅生成规划文件。
