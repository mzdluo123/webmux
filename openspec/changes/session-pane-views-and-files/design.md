# Design

## Context

`Terminal.svelte` 维护路由下的会话列表与活动会话；`session-dock.ts` 将同一会话映射为终端、聊天、文件树、阅读器四个停靠标识。`TerminalHeader` 显示活动会话的切换器，停靠组另显示聊天和终端标签。`SessionTerminal.openCode()` 会在宽屏同时显示树与阅读器。改动动机见[提案](proposal.md)。

## Goals / Non-Goals

- 会话身份、视图与停靠位置分别由会话、混合会话控制器和布局持有。文件操作始终携带来源会话，避免异步结果被投递到后来激活的窗格。
- 保留共享停靠组件及 Git 工作台的布局契约。沿用文件只读预览、独立代码窗口与现有代码根；本次不引入编辑器、任意目录授权或服务端布局同步。

## Decisions

1. **按会话登记停靠项。** 使用稳定会话 ID 表示会话窗格，在同一内容槽呈现它的实际视图。终端实例、草稿和聊天订阅的生命周期继续由会话管理；布局不根据选中的控件自行推断会话视图。深链打开消息仍定位到目标会话，沿用既有消息展示与授权流程。
2. **按动作拆标题栏。** 工作区顶栏承载导航、文件、布局和当前窗格提供的会话操作。手机将会话操作合入顶栏「⋯」，标题行保留名称、详情和状态；收起及恢复由「打开面板」抽屉提供。桌面标题行保留窗格名称或堆叠标签及状态，移动、放大和还原复用现有停靠菜单及键盘路径。
3. **文件入口捕获所属会话。** 由被激活的会话或文档解析其 owner；工具栏获取焦点不清空 owner。文件树和文档实例分别登记。展开树不注册空阅读组；选择文档、文件引用或 Diff 深链才显示阅读器。已有有效文档仍可随已保存布局恢复。
4. **文档独立停靠。** 同一会话共享文件上下文，每个文件或 Diff 有独立窗格。普通打开优先定位已有文档，否则与最近阅读的文档并为停靠标签；组内的文件、终端和聊天标签共用一个标签栏。显式「在右侧打开」以来源阅读组为锚，从树发起则以该会话当前阅读组或会话窗格为锚。比较组独立保留滚动与选区。
5. **按视口投影。** 手机导航记录实际的窗格实例，回退优先回到打开文档的树或来源窗格。与桌面几何分开，不为前进、返回或取消操作请求终端焦点。保留当前桌面布局命令，不用手机抽屉作为找文件的必经步骤。
6. **桌面会话工作区使用边栏收起。** 顶栏「窗格」菜单收起时默认将文件树放在左侧、阅读器放在右侧、会话窗格放在底部；窗格操作菜单可选择任一边缘，后续收起沿用显式选择。
   收起时仅从可见布局中隐藏窗格，停靠树保留其分组、位置和比例。激活边栏标签直接恢复该窗格并移除标签；焦点变化与 Esc 不改变展开状态。手机继续使用单面板选择器，Git 工作台继续使用原有收起与恢复入口。

## Risks / Trade-offs

- 把旧标签改名仍会留下两个可分别停靠的视图 → 从会话布局模型合并身份；验证切换前后同一会话仅一项，且切换失败时显示服务端实际状态。
- 用户操作 A 后立即聚焦 B，异步目录读取或打开文件晚到 → 文件动作捕获来源 ID；来源已移除时丢弃该动作，不重定向到 B。
- 比较组增多会占用终端空间 → 常规打开将新文档并入已有组，仅在显式分屏时占用更多空间，关闭最后一个窗格后释放组。
- 旧规范要求聊天独立停靠、固定「代码 / 分屏」两项 → 本变更在相同能力路径替换冲突要求；Git 模式和服务端混合会话协议继续沿用原规格。
- 刷新应延续上次布局 → 本机保存停靠树、所选边缘和窗格收起状态，边栏恢复时清除收起状态。

## Migration Plan

1. 规格合并顺序：先归档 `mobile-panel-picker-sheet` 和 `dock-session-panels` 建立对应能力，再归档本变更。本变更内提供完整替换条目，不直接改写另外两份提案或主规格。
2. 仅为会话布局使用新版本键。新版本不存在时一次读取旧树：两旧视图中优先保留与实际视图匹配且可见的位置，否则保留可见项，再回退到树序第一项。两项均收起才合并为收起。
3. 删除重复叶、压缩空分支，保留其他会话、文件树、有效文档和可表达的比例；旧阅读器映射为所属会话的首个阅读组。旧手机活动项按所有者映射，损坏布局回到默认排列。未记录边缘的已收起窗格按类型显示在默认边栏。恢复不发送切换或新建会话请求。
4. 回退前端继续使用旧版本键；服务端会话记录、文件内容、授权及进程不参与迁移。
