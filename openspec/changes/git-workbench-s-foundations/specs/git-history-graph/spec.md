# Spec Delta

## Purpose

定义仓库级按需分页的提交历史、真实父子拓扑图与提交详情检索契约，确保合并分叉、分页截断与条件筛选场景下的拓扑边始终忠实于真实 Git parent 关系，并保持无副作用的只读执行边界。

## ADDED Requirements

### Requirement: 按需分页历史与快捷范围语义

系统 SHALL 在仓库或工作树上下文内按页返回提交历史列表，支持指定每页条数上限与分页游标，无需预先构建全仓库常驻索引。

系统 SHALL 支持以下历史范围，并对前置条件缺失的场景给出明确状态而非伪造空列表：

- **所有历史**：遍历仓库全部本地分支、远程跟踪分支与标签可达的提交；空仓库（尚无任何提交）返回明确的“尚无提交”空态。
- **当前分支**：需要已指定工作树且存在可解析 `HEAD`（含游离 `HEAD` 所指提交）；未选工作树或工作树处于未诞生 `HEAD` 状态时 SHALL 返回明确原因。
- **待推送**与**远端新增**：基于目标分支与本地已有远程跟踪引用的对称或单向差集计算，并附带上次获取远程时间；无上游、上游引用已消失或未指定目标分支时 SHALL 返回明确不可用原因，MUST NOT 将未知或未配置上游返回为零条差异。

系统 SHALL 支持按提交消息/文本关键字、作者、起止时间与仓库内相对路径筛选提交；筛选参数 MUST 作为字面数据传递，不得被解释为命令选项。

#### Scenario: 无上游或空仓库的范围查询

- **WHEN** 用户在新初始化尚无提交的仓库查询“所有历史”，或在尚未配置上游的新分支上查询“待推送”与“远端新增”
- **THEN** 前者返回明确的空仓库未诞生提交状态，后者返回“当前分支尚未配置上游”说明及上次获取时间（如有），均不伪装为已同步的零条结果

#### Scenario: 连续分页遍历不重不漏

- **WHEN** 仓库包含超过单页上限的提交且分页期间引用未变化，调用方携带上一页返回的游标继续请求下一页
- **THEN** 后续页按一致拓扑时间顺序返回紧接的提交记录，不重复上一页末尾提交且不遗漏中间提交；若引用已变化且导致游标锚点失效，则明确提示刷新或按不可变提交锚点续读

### Requirement: 真实 parent 拓扑车道与隐藏/截断延续标识

历史查询返回的每条提交记录 SHALL 包含完整提交 OID、短 OID、真实父提交 OID 列表（按第一父、第二父顺序保留）、标题、作者、提交时间及指向该提交的本地分支、远端跟踪分支、标签和工作树 `HEAD` 引用标记。

拓扑图模型 SHALL 遵守以下真实性约束：

- 图形中的实线父子连接 MUST 仅存在于真实直接 parent OID 关系之间。
- 当某条提交的某个真实父提交尚未在当前已加载分页内出现（位于后续页）时，拓扑模型 SHALL 为该父分支保留开放车道或输出明确的“分页待续”边标识，直至对应父提交加载完成。
- 当启用文本、作者、日期或路径筛选导致中间提交被隐藏时，若可见提交 `C` 与后续可见提交 `A` 之间仅存在间接祖先关系而非直接 parent 关系，系统 MUST 以“省略/延续”标识（如虚线或断口标记）或断开表达，SHALL NOT 将 `C` 与 `A` 绘制成直接父子实线边。

#### Scenario: 含分支合并的分页边界

- **WHEN** 第一页末尾的合并提交拥有两个真实父提交，其中第一父位于第一页内、第二父位于第二页
- **THEN** 第一父在当前页内绘制完整连线，第二父指向页底延续标识并携带真实父提交 OID；加载第二页后该车道精确衔接至第二页中的对应父提交

#### Scenario: 路径筛选隐藏中间提交

- **WHEN** 线性历史 `C -> B -> A` 中仅 `C` 和 `A` 修改了筛选路径 `cmd/main.go`（`B` 被筛选隐藏）
- **THEN** 返回的列表中 `C` 仍携带真实父提交 `B` 的 OID，拓扑关系标记 `C` 的直接父节点不在当前可见结果中，绝不把 `A` 伪造为 `C` 的直接父提交

### Requirement: 提交详情、合并父节点选择与只读无副作用

系统 SHALL 为任意存在的完整提交 OID 返回完整提交详情与变更文件清单：

- 详情 SHALL 包含完整提交消息（标题与正文）、作者姓名/邮箱/时间、提交者姓名/邮箱/时间（与作者不同时明确区分）、完整 OID、全部父提交 OID 与摘要，以及关联引用列表。
- 普通单父提交与根提交（无父提交，相对空树比较）SHALL 直接返回变更文件列表（区分新增、修改、删除、重命名、复制、模式变化与二进制）。
- 合并提交（两个及以上父提交）SHALL 默认相对第一父（`parent 1`）返回变更文件列表，并允许调用方显式指定任一真实父提交 OID 计算相对于该父节点的变更文件列表与单文件差异。
- 所有历史列表、拓扑、提交详情与历史文件差异读取 MUST 保持严格只读：不触碰工作树文件、不刷新或写入 Git 索引、不执行用户自定义外部 diff/textconv 驱动，也 MUST NOT 自动发起网络 `fetch`。

#### Scenario: 切换合并提交的比较父节点

- **WHEN** 用户查看包含两个父提交 `P1`、`P2` 的合并提交 `M`，先默认查看相对 `P1` 的变更文件，再显式选择相对 `P2` 查看变更文件与单文件差异
- **THEN** 两次请求分别返回 `P1 -> M` 与 `P2 -> M` 的精确文件变更集合及对应双侧文本快照

#### Scenario: 只读浏览不污染索引与不触发外部驱动

- **WHEN** 仓库配置了自定义 `diff.external`、`textconv` 过滤器，且工作区存在未刷新 stat 的脏文件，调用方执行历史分页、查看提交详情与打开历史文件差异
- **THEN** 自定义外部脚本一次也不会被执行，`.git/index` 文件内容与修改时间保持原样，且不产生任何出站网络请求
