# Spec Delta

## Purpose

定义 Git 工作台专属的 IntelliJ 风格双主题语义令牌、设计系统受控组件变体，以及覆盖桌面多栏与平板/手机单栏的 `Log`、`Commit`、`Branches`、`Push` 预览交互布局骨架与 Storybook 视觉防溢出核对规范。

## ADDED Requirements

### Requirement: 兼容前端架构守卫的 Git 工作台双主题令牌与组件变体

系统 SHALL 在全局设计令牌体系中提供面向 Git 工作台的双主题（浅色与深色）语义令牌，并在设计系统基础组件中通过显式变体（variant/size）消费这些令牌，使 IntelliJ New UI 风格的中性面板表面、1px 分隔线、蓝色选中行背景与蓝色主要操作按钮完全遵守前端架构守卫：

- 浅色与深色主题下的 Git 工作台表面、选中行、主要操作及次要说明文字对比度 SHALL 满足可读性要求，且颜色绝不作为唯一状态识别手段（新增、删除、冲突、分支占用与上游差异均 MUST 伴随符号、图标或文字标签）。
- 所有圆角 MUST 遵守设计系统既有圆角刻度（紧凑行与徽标使用 `rounded-sm` 4px，按钮与输入控件使用 `rounded-md` 6px，弹层使用 `rounded-xl` 12px），业务组件调用处 MUST NOT 使用原始调色板颜色、非布局任意值或内联尺寸样式。
- 新增令牌与基础组件变体 MUST 同步登记于设计系统与前端架构守卫规范，确保 `pnpm --dir web check:arch` 零违规通过且存量抑制基线保持为空。

#### Scenario: 明暗双主题下的令牌与架构守卫校验

- **WHEN** 在浅色与深色主题下渲染 Git 工作台组件与设计系统变体并执行前端架构检查
- **THEN** 选中行呈现高对比度蓝色选中态、主要提交/推送确认呈现蓝色主按钮外观、面板保持 1px 细分隔线，且 `check:arch` 全部五项子检查零报错通过

### Requirement: 桌面多栏可调骨架与核心操作语义分离

可用内容宽度不少于 `1280 CSS px` 时，Git 工作台骨架 SHALL 呈现 IntelliJ Git 参照的紧凑多栏分区结构，自上而下包含顶栏上下文与动作区、主工作区（左侧窄模式工具栏 `Log` / `Commit` / `Branches` 及对应多栏面板）与底部连续可见的操作状态栏：

- **顶栏上下文区分**：顶栏 MUST 同时清楚区分“正在操作的工作树及其真实当前分支/`HEAD`”与“正在浏览或筛选的历史分支/提交”；尚未选择工作树时明确提示仓库级只读状态。
- **`Log` 视图联动与单击过滤约束**：
  - 桌面端左列为可折叠分支/引用树、中列为筛选栏与拓扑提交列表、右列上为变更文件列表且下为提交详情、底部为可展开/放大的差异预览；
  - 单击分支行 MUST 仅过滤历史列表而不改变工作树检出分支，切换分支 MUST 通过显式的 `Checkout` 预览确认动作触发。
- **`Commit` 视图三种状态独立与完整预览**：
  - 左列上部按 `Conflicts`、`Unstaged`、`Staged`、`Untracked` 分组展示文件及计数，左列下部为提交说明输入、作者摘要与 `Commit` / `Commit & Push` 入口；
  - 右列占据剩余空间展示双栏或统一差异及行内可触达的逐块/整文件 `Stage`/`Unstage` 按钮（不依赖纯鼠标悬停才可操作）；
  - “正在阅读高亮”“已审阅标记”与“真实 `index` 已暂存”MUST 使用彼此独立的视觉表达，点击提交动作 MUST 先进入展示完整真实 `index` 的提交预览。
- **`Branches` 与 `Push` 预览**：
  - 分支树、顶栏分支弹窗与 `Branches` 视图共享同一分支状态模型（当前标记、收藏、本地/远端、上游差异、占用工作树及受影响会话），已被其他工作树检出的分支优先提供打开已有工作树而非冲突检出；
  - `Push` 采用宽对话框，左列展示仓库、`源分支 -> 远程/目标分支` 与全部待推提交，右列联动文件列表、提交详情与差异。
- **分隔条无障碍与未交付阶段诚实表达**：桌面多栏分隔条 SHALL 同时支持鼠标拖动、键盘方向键调整及恢复默认比例；归属 V2/V3 的能力（如 `Stash`、三方冲突解决器、`Merge`/`Rebase` 闭环）SHALL NOT 在 V1 正式骨架中渲染为可执行的假按钮。

#### Scenario: Log 单击分支仅过滤且联动提交详情与文件差异

- **WHEN** 用户在 `1440×900` 桌面视口的 `Log` 视图单击左侧非当前分支 `feat/sync`，再依次选中一条合并提交及其变更文件
- **THEN** 中列历史按 `feat/sync` 过滤，顶栏显示的当前工作树检出分支保持不变；右列同步更新该提交的变更文件、完整详情及合并父节点选择器，底部差异区展示所选文件对应版本的比较

#### Scenario: Commit 视图阅读、审阅与暂存三态分离及完整预览

- **WHEN** 用户在桌面 `Commit` 视图选中一个部分暂存文件、将其标为“已审阅”、点击其中一个未暂存代码块的 `Stage` 按钮，再点击 `Commit & Push`
- **THEN** 行选中态、已审阅标记与 `Staged`/`Unstaged` 分组各自独立显示；打开的提交预览同时列出终端原有暂存文件与刚暂存的代码块，确认语义写明先完成本地提交再进入包含全部待推提交的 `Push` 预览

### Requirement: 平板与手机视口单栏步进适配及 Storybook 矩阵核对

Git 工作台布局骨架 SHALL 按可用宽度响应式重组，绝不在窄屏硬压桌面三栏，并通过 Storybook 故事覆盖桌面、平板、手机、横屏、大字号与双主题的可交互评审矩阵：

- `1024–1279 CSS px` 时收窄次要列并允许将右侧详情折叠为抽屉；`640–1023 CSS px` 时将分支树与辅助面板收入抽屉，按空间切换列表与详情。
- `320–639 CSS px` 手机视口下 SHALL 采用单栏步进流：
  - `Log` 为“提交列表 -> 提交详情/文件 -> 统一模式 Diff”并保留返回上下文；
  - `Commit` 为“变更列表 -> 统一模式 Diff -> 完整提交预览”；
  - `Push` 为全屏确认视图；
  - 对象菜单统一提供行尾 `…` 按钮等价入口，可编辑输入字号不少于 `16px`，底部保留当前步骤主要动作与状态提示。
- 所有评审故事 SHALL 接入 Storybook 自动布局与防溢出检查：
  - 场景覆盖常规浏览、合并拓扑与分页延续、部分暂存与完整预览，以及无工作树/空仓库/锁冲突/需要复核等关键空态与异常态；
  - 在 `320×568`、`390×844`、`768×800`、`1280×900`、`667×320` 及 `320×568` 下 `200%` 根字号均无页面级横向溢出，弹层完整落在视口内且主要确认/取消按钮可达；
  - 所有交互仅变更内存演示数据，不发起真实 `/api/` 请求。

#### Scenario: 320px 与 390px 手机单栏完成审阅暂存到推送预览步进

- **WHEN** 在 `320×568` 或 `390×844` 视口打开 Git 工作台 `Commit` 与 `Push` 评审场景，依次从文件列表进入文件统一 Diff、执行块暂存、打开提交预览并进入全屏 `Push` 预览
- **THEN** 每一步均为无页面级横向溢出的单栏视图，返回操作保留原选中对象，输入框字号至少 `16px`，确认与取消按钮在视口内完整可见且可触达
