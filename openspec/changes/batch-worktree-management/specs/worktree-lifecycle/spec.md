## MODIFIED Requirements

### Requirement: 安全删除保护目录和运行会话

默认删除 SHALL 要求目标是未锁定的 linked worktree，没有尚未退出的 WebMux 会话，且满足以下两种可验证状态之一：

1. 目录存在、身份与 Git 状态可验证，且没有未提交修改或未跟踪文件（存在忽略文件时在预览中给出丢失警告，不阻止安全删除）；
2. 目录经确认已不存在（`os.ErrNotExist`）且在 Git 清单中处于 `prunable` 待清理状态。

保护范围 SHALL 包含启动目录位于目标及其子目录的直接会话，不仅限于带关联标签的会话。删除行为遵循以下边界：

- 删除 SHALL 仅通过 Git 移除工作树及管理登记，不执行任意递归目录删除，也不清理未选中的其他 `prunable` 登记；
- 删除 SHALL 保留本地分支与已退出普通会话记录；
- 删除 SHALL 保留已归档混合会话记录，并在 `HEAD` 提交可解析时标为已释放空间（目录已缺失的 `prunable` 目标回退使用 Git 登记记录的 `HEAD` 校验提交）。

#### Scenario: 删除干净且空闲的工作树

- **WHEN** 用户确认安全删除符合条件的 linked worktree
- **THEN** 工作树目录及 Git 登记被删除，其分支仍存在，已退出会话仍可查看缓冲并手动移除

#### Scenario: 存在忽略文件但无修改与未跟踪文件

- **WHEN** 用户对仅包含 Git 忽略文件（如 `node_modules`）且无活动会话的 linked worktree 预览并确认安全删除
- **THEN** 预览展示忽略文件将随目录一并丢失的警告但不阻止安全删除；确认后工作树被删除且保留分支

#### Scenario: 清理目录已缺失的未锁定 prunable 登记

- **WHEN** 某 linked worktree 目录已被外部删除、Git 标记为 `prunable` 且未锁定、无运行中会话，用户在页面预览并确认安全删除
- **THEN** 系统移除该条失效的 Git 工作树登记而不影响仓库内其他 `prunable` 项；其分支保留，原路径下的已归档混合会话记录按登记中的 `HEAD` 提交标为已释放空间

#### Scenario: 有修改、未跟踪文件或运行会话

- **WHEN** 用户对包含未提交修改、未跟踪文件或运行中会话的工作树执行默认删除
- **THEN** 系统拒绝并说明阻塞原因，不关闭会话或删除文件，用户可取消、手动处理或进入独立的强制删除流程
