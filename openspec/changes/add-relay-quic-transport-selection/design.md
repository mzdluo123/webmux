# Design

## Context

`internal/relay/frpc.go` 启动固定版本的 frpc；`frp_bridge.go` 在 WSS Upgrade 上附加桥接凭据并验证节点身份。`protocol/relay/frp.go` 只接受受信的 `wss://` 分配。原生 QUIC 没有这次 HTTP Upgrade。
节点当前的真实回源探针与管理授权独立。试连必须有自己的探针目标，否则旧 WSS 返回的 204 会把坏的候选误报为可用。

## Goals / Non-Goals

- 允许在同一宿主与节点间手动对照；其他设备看到同一个生效选择。
- 浏览器 HTTP/3、WebRTC 选路、自动择优以及更换节点均在范围外。

## Decisions

1. 通过已有认证管理连接协商版本和能力。旧端继续收到旧格式分配；协商成功后才下发节点 UDP 端点、身份约束与短期候选授权。宿主不接受用户指定目标地址。
2. 在隔离节点先验证固定版本 frpc/frps 原生 QUIC：外层验证受信节点，登录及工作连接绑定宿主、分配和代际，内层仍验证原有回源 mTLS。WSS 桥密钥不挪作通用 UDP 口令。无法达到同等隔离时不发布能力。
3. 节点为同一分配保留一个有期限的候选槽，使用独立注册名和私有回源目标。候选只允许受限探针流量，活动与候选合计执行配额。直接改写正在使用的 frpc 配置会先拆除旧链路，无法满足失败保留要求。
4. 按操作 ID、授权代际和旧路由版本比较并提交。节点确认切换后宿主才持久化；响应丢失时按操作 ID 查询结果再完成保存，不猜测成功、不重新执行业务。宿主重启时用当前有效授权重新验证持久化偏好。
5. 切换只影响数据连接。旧连接允许有界收尾，撤销立即关闭两侧；终端进程继续运行。候选失败清理只影响该候选。
6. 设置页使用现有单选控件和单独的「测试并应用」动作。最近一次试连有独立时间戳与阶段；活动链路回源观测沿用现有新鲜度语义。断开时生效协议为空，不用保存的偏好填充。

## Risks / Trade-offs

- [UDP 可达性随网络变化] → 失败展示实际阶段；提供本机 WSS 恢复入口，不静默回退造成比较失真。
- [短暂双注册扩大资源占用] → 节点限制并行候选数、生命周期、速率及总连接数；入口不得暴露通用代理或公共回源端口。
- [QUIC 未必降低按键尾延迟] → 固定浏览器到节点的路径，在同 PTY 输出下测量真实回显，连同失败、超时和恢复记录。

## Migration Plan

先完成双仓库隔离验收，再发布默认关闭 UDP 能力的节点及兼容宿主；运营者按节点发布能力。生产开放需要单独授权。
回滚先停止签发新 QUIC 候选，保留 WSS 与本机操作入口，通知已选 QUIC 的宿主切回并确认后再关闭 UDP 监听。紧急撤权按现有授权生命周期立即生效。
