## Context

托盘转发监听用户勾选的 Windows 地址（`windows-tray-forwarding`）。Windows Defender 防火墙对首次监听非回环地址的程序弹出原生提示，规则按程序路径生效。安装程序按用户安装、全程不请求管理员权限（`windows-installer`），托盘自更新以 `/S` 静默覆盖原路径（`windows-tray-self-update`）。

## Goals / Non-Goals

**Goals:**

- 在第一次交互安装时一次性完成防火墙授权，之后的自更新不再弹窗。
- 只放行专用网络与域网络，公用网络保持 Windows 默认行为。
- 卸载时清理安装程序添加的规则。

**Non-Goals:**

- 托盘运行时修改防火墙，或在开启转发时临时提权。
- 删除或改写 Windows 原生提示留下的规则（包括用户关掉提示时生成的阻止规则）。
- 便携版托盘的防火墙规则。

## Decisions

### D1 由安装程序在交互安装时可选提权

安装选项页增加默认勾选的复选框。勾选时，安装完成后运行 `"$INSTDIR\webmux-tray.exe" firewall allow`，由它以 `runas` 启动 `netsh` 并等待退出码。比较过的方案：

- 托盘首次启动时主动监听一次以触发原生提示：不用转发的用户也会被打扰；直接关掉提示会生成阻止规则，之后转发被静默拦截。
- 整个安装程序以管理员运行：违背按用户安装的设计，也会让安装目录、注册表落到错误的用户上下文。

静默安装从不提权：托盘自更新不能弹窗，脚本化安装可以之后手工运行 `firewall allow`。

### D2 提权只运行 netsh，参数由托盘生成

`webmux-tray firewall allow|remove` 先以普通权限运行 `netsh advfirewall firewall show rule name=<名称>`，按退出码判断规则是否存在；已是目标状态时直接返回 0，不弹窗。否则用 `ShellExecuteExW` 的 `runas` 动词运行系统目录下的 `netsh.exe`（参数逐个转义，不经 shell），等待退出码后再次查询确认。

退出码：0 已是目标状态，1 失败，2 参数错误，3 用户取消管理员确认。

### D3 规则名称绑定托盘路径

名称为 `WebMux tray forwarding <路径小写的 SHA-256 前 12 位十六进制>`，只含 ASCII，避免 netsh 输出的代码页问题，也不需要解析本地化输出。

- 同一路径的静默自更新沿用规则；
- 不同安装目录各有各的规则，卸载其中一个不影响另一个；
- 规则内容：入站、允许、TCP、`program=<托盘路径>`、`profile=private,domain`。

### D4 卸载按记录删除

`firewall allow` 成功后在卸载项写入 `FirewallRule=1`。卸载时只在该值为 1 时运行 `firewall remove`，因此从未添加规则的安装卸载时不会弹窗；用户取消时提示到防火墙设置中手工删除。

## Risks / Trade-offs

- [安装目录可被当前用户写入] → 规则按路径放行，同一用户的其他程序替换 `webmux-tray.exe` 后也能接受入站连接。替换托盘本身已等同于控制该用户的 WebMux，规则没有扩大这一边界；公用网络不放行。
- [Windows 原生提示留下的阻止规则优先于允许规则] → 以前关掉过提示的用户，添加本规则后转发仍被拦截。文档说明在防火墙设置中删除名为 `webmux-tray.exe` 的阻止规则。
- [静默卸载可能弹出管理员确认] → 只发生在交互安装时添加过规则的安装上，属于用户自己授权过的内容。
- [当前网络被识别为公用网络] → 规则不生效，Windows 仍可能弹出原生提示；文档建议把可信网络设为专用网络。
