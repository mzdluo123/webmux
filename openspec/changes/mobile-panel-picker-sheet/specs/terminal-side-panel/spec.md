# Spec Delta

## Purpose

规定会话页右侧栏面板的统一入口、选择页在桌面与手机上的呈现形态、面板视图切换与关闭路径，使两个面板目的地的选择过程在各视口下都保持单次、可取消、可辨识。

## ADDED Requirements

### Requirement: 单一「打开面板」入口

会话页顶栏 SHALL 提供唯一常驻的「打开面板」入口，可访问名称与提示一致；桌面与手机均经此入口选择面板，SHALL NOT 提供第二个常驻面板入口。侧栏已打开时再次点击该入口 SHALL 重新呈现选择页。

#### Scenario: 打开选择页

- **WHEN** 用户在会话页点击「打开面板」
- **THEN** 按当前视口呈现选择页（见「选择页按视口呈现」），同一时刻只出现一种选择页形态

#### Scenario: 面板打开时重新呈现选择页

- **WHEN** 侧栏面板已打开（代码或分屏视图），用户再次点击「打开面板」
- **THEN** 重新呈现选择页，当前所在面板视图被标记为当前项

### Requirement: 选择页按视口呈现

视口宽度至少 640 CSS px 时，选择页 SHALL 作为右侧栏内页面呈现，包含标题「打开面板」、「代码」项（启用 `code` 时）与「分屏」项（存在窗格操作时），提供 C/S 键盘快捷键与可见按键提示，以及「关闭侧栏面板」按钮。

视口宽度小于 640 CSS px 时，选择页 SHALL 以底部抽屉浮层呈现，终端或当前面板保留在遮罩后方；抽屉 SHALL 包含与页内选择页相同的选择项，SHALL NOT 显示键盘按键提示。点遮罩、下滑或取消 SHALL 关闭抽屉且不改变面板状态；侧栏已打开时抽屉 SHALL 提供「关闭侧栏面板」项。

#### Scenario: 手机打开抽屉选择页

- **WHEN** 手机视口用户在会话页点击「打开面板」
- **THEN** 底部升起抽屉，列出「代码」（启用 `code` 时）与「分屏」，终端仍在遮罩后方可见

#### Scenario: 抽屉取消不动作

- **WHEN** 抽屉打开时用户点击遮罩、下滑或选择取消
- **THEN** 抽屉关闭，终端或先前所在面板视图保持原状，侧栏展开状态不变

#### Scenario: 从代码页打开抽屉并关闭侧栏

- **WHEN** 侧栏处于代码视图，用户点击「打开面板」再选择「关闭侧栏面板」
- **THEN** 抽屉与侧栏一同关闭，回到终端视图，焦点回到「打开面板」入口

#### Scenario: 抽屉标记当前面板

- **WHEN** 侧栏处于分屏视图，用户点击「打开面板」
- **THEN** 抽屉中「分屏」项被标记为当前项

#### Scenario: 桌面页内选择页

- **WHEN** 桌面用户在会话页点击「打开面板」
- **THEN** 右侧栏展开并显示标题为「打开面板」的选择页，选择页获得焦点时可按 C 选择代码、按 S 选择分屏

### Requirement: 选择后的面板视图

选择「代码」SHALL 以代码工作区替换侧栏内容（桌面并排、手机整屏覆盖终端），代码页不新增侧栏头部；选择「分屏」SHALL 以分屏操作列表替换侧栏内容，头部提供返回选择页与关闭侧栏面板。分屏操作沿用原有禁用条件与执行行为。

#### Scenario: 手机选择代码

- **WHEN** 手机用户在抽屉中选择「代码」
- **THEN** 抽屉关闭，代码工作区整屏覆盖终端，会话顶栏保持可见

#### Scenario: 手机选择分屏

- **WHEN** 手机用户在抽屉中选择「分屏」
- **THEN** 抽屉关闭，侧栏整屏显示全部分屏操作

#### Scenario: 分屏页返回选择页

- **WHEN** 分屏视图打开时用户点击头部返回按钮
- **THEN** 手机重新打开抽屉选择页，桌面回到页内选择页；面板与分屏状态不被销毁

### Requirement: 关闭路径保持可达

任一视口下关闭侧栏面板 SHALL 有可达的可见操作：桌面选择页与分屏页头部的关闭按钮、手机抽屉的「关闭侧栏面板」项。代码页保持原布局不加头部，其关闭经「打开面板」入口的选择页完成。

#### Scenario: 手机从代码页关闭侧栏

- **WHEN** 手机用户处于代码视图，点击「打开面板」并在抽屉选择「关闭侧栏面板」
- **THEN** 侧栏关闭并回到终端，不要求先返回分屏或选择页
