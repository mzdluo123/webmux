## Context

当前实现与启动命令相关的路径：

- `internal/config/config.go` 在启动时加载 `[[presets]]`，默认生成 `shell`、`claude`、`codex`、`omp` 四条预设；`Validate` 会把 `shell` 预设解析为实际的 `shell -l -i`。修改预设后需要重启服务。
- `web/src/components/NewSessionSheet.svelte` 从 `GET /api/presets` 读取预设，并额外支持“追加参数”和自定义命令；上次预设与自定义命令分别保存在浏览器 `localStorage` 的 `webmux.lastPreset`、`webmux.customCommand`。追加参数由 `web/src/api.ts` 的 `parseArgs` 按 argv 规则切分，不经过 shell。
- `POST /api/sessions`（`internal/api/router.go`）已接受 `cwd`、`preset`、`cmd`、`args`、`name`、`workspace`、`env`。`env` 由 `session.ValidateEnv`（`internal/session/env.go`）校验名称、NUL 与保留变量 `WEBMUX_SESSION_ID`；前端从未发送该字段。
- `workspace.Service.CreateSession` 已经接受完整 argv 与 `env`，并负责目录、工作树、并发启动与仓库关联校验；`session.Manager.Create` 不需要为启动配置做任何改动。
- 服务端状态目录来自 `state_dir`，默认 `~/.local/state/webmux`（`XDG_STATE_HOME` 优先）。`internal/push/store.go` 已确立原子写入方式：同目录临时文件、`chmod 0600`、写入、`fsync`、关闭、`rename`、目录同步，并在保存失败时回滚内存状态；`internal/workspace/registry.go` 也采用相同的落盘模式。
- 设置页 `web/src/pages/Settings.svelte` 目前声明“设置仅保存在当前浏览器”，并按卡片分组；`NewSessionSheet` 在桌面用 Dialog、移动端用 Drawer，二者共用同一表单片段。
- `/api/*` 已有统一认证、Host 与 Origin 校验；请求体使用 `decode`，拒绝未知字段并限制为 64 KiB。启动配置可以执行任意命令，这与现有自定义命令接口的权限边界相同，不新增授权模型。

本变更只保存规划工件，以下设计与任务供后续实现 PR 使用。

## Goals / Non-Goals

**Goals:**

- 用服务端持久化的“名称 + 完整 argv + 环境变量”替代浏览器本地的启动命令复用方式，使配置跨重启、跨浏览器与设备可用。
- 保存时把预设与追加参数固化为完整 argv；TOML 预设后续变化不影响已保存配置。
- 复用现有 `POST /api/sessions`、`session.ValidateEnv`、`workspace.CreateSession` 与终端生命周期，不建立第二套 PTY 启动路径。
- 沿用状态目录的原子写入、0600 文件权限、进程内互斥与失败回滚约定。
- 存储损坏或不可用时只禁用启动配置功能，不影响会话与终端。
- 设置页与新建会话页在桌面、移动端与明暗主题下都可完成配置管理和启动。

**Non-Goals:**

- 首页一键启动、配置级默认工作目录、工作树绑定。
- 在 `SessionInfo` 中增加配置 ID 或配置名称。
- 配置导入/导出、变量或占位符模板、按 agent 或目录过滤、排序、标签、共享链接。
- 将配置写回 `config.toml`，或让 TOML 预设与已保存配置保持同步。
- 多用户权限、配置级访问控制或加密存储；沿用单用户与已认证 API 的安全模型。

## Decisions

### 0. 已采纳的产品取舍

| 问题 | 结论 |
|---|---|
| 配置是否包含默认工作目录 | 否；每次启动仍选择目录，配置级 `cwd` 留到下一期 |
| 是否保留“临时命令（不保存）” | 是，折叠为高级入口；主路径只选启动配置 |
| 首次启动是否按 TOML 预设生成默认配置 | 是；仅在状态文件不存在时生成一次 |
| 持久化格式 | 状态目录 JSON；不写回 `config.toml` |
| 环境变量值是否默认遮挡 | 是，提供显示切换 |
| 首页一键启动 | 下一期，直接复用 `POST /api/sessions {configId}` |

以上为 issue 计划中的推荐默认，并记录在 draft PR 中供评审；若评审改变取舍，先更新本工件再实现。

### 1. 数据模型与文件格式

`<state_dir>/launch-configs.json`：

```json
{
  "v": 1,
  "configs": [
    {
      "id": "k3m9q2x7",
      "name": "Claude 恢复会话",
      "cmd": ["claude", "--resume"],
      "env": { "ANTHROPIC_BASE_URL": "https://example.test" },
      "createdAt": "2026-10-23T12:00:00Z",
      "updatedAt": "2026-10-23T12:00:00Z"
    }
  ]
}
```

- `id` 由服务端生成，8 位小写 base32（字符集 `a-z2-7`），与现有会话 ID 的格式一致；生成后与现有配置比较，冲突时重新生成。客户端不能指定或修改。
- `name` 去除首尾空白后按 Unicode 字符计 1–64 个字符，并在同一文件内唯一（去空白后精确比较，区分大小写）。重名返回 409。
- `cmd` 是保存时从预设或自定义命令解析出的完整 argv，包含追加参数；长度 1–128 项，第一项非空，单项 UTF-8 不超过 8 KiB。除第一项外允许空字符串参数，以保留 `parseArgs` 的空参数语义。
- `env` 是字符串到字符串的映射，最多 64 项；名称与值必须满足 `session.ValidateEnv`（名称 `^[A-Za-z_][A-Za-z0-9_]*$`、值不含 NUL、`WEBMUX_SESSION_ID` 保留），值不超过 8 KiB。空映射序列化为 `{}`，不能为 `null`。
- 时间在 JSON 中使用 UTC RFC 3339；`createdAt` 创建后不变，`updatedAt` 每次成功更新刷新。
- 配置最多 100 条。`POST`/`PUT` 请求体沿用现有 64 KiB 上限，因此各项上限之外还受整体请求大小约束。
- `configs` 按创建顺序（最旧在前）返回；更新不改变顺序。空列表序列化为 `[]`。

完整 argv 是命令快照，不保存预设名与参数列表。这样 TOML 预设被修改或删除后，已保存配置仍按原命令启动；代价是界面必须明确提示“保存的是创建时的命令副本”。

### 2. 存储服务与故障处理

新增 `internal/launch` 包：

- `types.go`：配置结构、输入校验、规范化、ID 生成；`cmd` 与 `env` 在保存和启动时都做防御性复制，避免共享切片或映射被调用方修改。
- `store.go`：`Service` 持有进程内互斥锁、文件路径、配置切片与不可用状态。启动时由 `cmd/webmux/main.go` 在配置校验后创建，并注入 `api.New`。
- 加载流程：确保状态目录存在且为 0700 → 读取文件 → 文件不存在时按当前 TOML 预设生成默认配置并保存 → 解析失败时仅记录不可用原因，不修改文件。
- 保存流程与 `internal/push/store.go` 一致：同目录临时文件、`chmod 0600`、写入、`fsync`、关闭、`rename`、目录同步。保存失败时回滚内存状态并返回错误。
- 所有 CRUD 在同一互斥锁内完成，先修改内存副本、落盘成功后再替换可读状态；读取返回副本。
- 文件损坏时保留原文件并让存储进入不可用状态。与 push 存储不同，启动配置是用户数据，不能像可重建的推送密钥那样改名重建。
- 损坏或不可用状态在进程生命周期内保持；手动修复或删除文件后需要重启服务重新加载。API 的 503 错误文本包含 `<state_dir>/launch-configs.json`，供设置页提示。
- 首次种子：仅当文件不存在时，为当前生效的每条 TOML 预设生成配置，名称取预设的 `name`（与旧 `lastPreset` 的值一致），`cmd` 取预设校验后解析出的完整 argv，`env` 为空。若预设名已满足唯一性（`config.Validate` 已保证），种子不会产生重名。种子保存失败时服务进入不可用状态，但会话服务继续工作。
- 沿用“同一 `state_dir` 只允许一个实例”的部署约定；本变更不新增跨进程文件锁。

### 3. API 契约

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/launch-configs` | 返回配置数组；存储不可用时 503 |
| POST | `/api/launch-configs` | 请求体 `{name, cmd, env}`；201 返回新配置 |
| PUT | `/api/launch-configs/{id}` | 全量更新 `name`、`cmd`、`env`；200 返回配置 |
| DELETE | `/api/launch-configs/{id}` | 删除；204；不存在 404 |

- 创建与更新使用现有 `decode`：拒绝未知字段、只接受一个 JSON 对象、请求体上限 64 KiB。`env` 缺省视为空映射；`cmd` 缺失或为空、名称为空均为 400。
- 状态码：校验失败 400；名称冲突 409；ID 不存在 404；存储不可用或文件损坏 503；落盘失败 500 且内存回滚。错误沿用 `{"error": "..."}`。
- 更新为整体替换：未提供的 `env` 清空，未提供的 `name`/`cmd` 视为无效而不是“保留原值”。`id`、`createdAt` 由服务端保持，`updatedAt` 刷新。
- 读取顺序稳定，便于设置页展示与测试。`GET` 返回已认证用户可见的完整 `env`，因为编辑对话框需要回填；错误与日志中不输出环境变量值。
- 路由注册在 `Server.routes`，自动继承 `/api/*` 的认证、Host、Origin 与 panic 恢复；不新增权限边界。
- 并发写入由存储互斥锁串行化；本期的并发编辑采用后写覆盖，不做版本号或冲突合并。

### 4. `POST /api/sessions` 的 `configId`

请求结构增加一个可区分“未提供”和“空字符串”的字段（Go 侧使用 `*string`）：

```json
{ "configId": "k3m9q2x7", "cwd": "/home/u/proj", "name": "可选" }
```

- `configId` 非空时，`preset`、`cmd`、`args`、`env` 必须都不存在或为空；否则 400。空字符串 `configId` 也返回 400，避免静默回退到其他启动方式。
- 校验顺序：解码（400）→ 字段互斥（400）→ 读取配置（404）→ `session.ValidateEnv`（400）→ 现有目录/工作树校验（400/409/503）→ 启动会话。
- 启动时把配置的 `cmd` 与 `env` 复制后传给 `Workspace.CreateSession(ctx, cwd, "custom", cfg.Cmd, nil, name, workspace, cfg.Env)`。`args` 必须为 `nil`，因为完整 argv 已包含追加参数。
- 会话信息记录 `preset: "custom"` 与完整 `cmd`；`env` 不进入会话信息。本期不增加 `configId` 字段，避免改变 `SessionInfo` 契约。
- 删除或更新配置不会影响已启动会话，因为 argv/env 已在启动时复制并传入 PTY。
- 现有 `preset`/`cmd`/`args`/`env` 路径保持原样；CLI 与脚本无需改动。后续 CLI 可在需要时直接使用 `configId`。

### 5. 设置页管理

- `Settings.svelte` 新增 `id="launch-configs"` 卡片，位置在“快捷指令”之后；`#launch-configs` 作为深链接滚动目标。页面顶部的“设置仅保存在当前浏览器”改为区分说明：快捷指令与输出预览留在浏览器，启动配置保存在服务端并跨设备共享。
- 列表展示名称、命令预览与环境变量数量；提供新建、编辑、删除（确认对话框）与空状态。达到 100 条时禁用新建并提示上限。加载失败或 503 时显示存储不可用与文件路径，禁用写操作，但页面其他设置仍可用。
- 编辑器组件 `LaunchConfigDialog.svelte`：名称 `Input`、命令等宽 `Textarea`、环境变量行编辑器。命令在保存时用 `parseArgs` 解析；从预设快速填入时读取 `GET /api/presets`，把预设 `cmd` 与用户追加参数合并成完整 argv 后填入。保存后是独立副本，不再关联预设。
- `parseArgs` 只负责“文本 → argv”。新增 `quoteArg`/`joinArgs` 纯函数负责“argv → 可再次解析的文本”：对含空白、引号、反斜杠、`$` 或空字符串的参数加引号并转义，保证编辑往返后 argv 完全一致。该函数放在前端工具模块中，供设置页、新建会话页与 Node 单元测试共用。
- 环境变量行：名称输入、值输入（默认 `type="password"` 遮挡，提供可访问名称明确的显示/隐藏按钮）、添加与删除。名称前端即时校验同一正则并拒绝 `WEBMUX_SESSION_ID`，值与数量上限与服务端一致；服务端仍做最终校验。
- 命令预览不包含环境变量值；列表和截图不得展示密钥。删除确认只显示名称与命令预览。
- 保存失败时对话框保持打开并显示错误；409 提示重名并保留输入；503 提示存储不可用。
- 设置页的快捷指令、预览等浏览器本地设置保持不变。

### 6. 新建会话页

- `SessionList.svelte` 与预设一起加载 `GET /api/launch-configs`，传给 `NewSessionSheet`。加载失败时仍允许使用临时命令，并显示存储不可用提示。
- 表单主路径改为“启动配置”选择：展示名称、命令预览与环境变量数量；目录/工作树/会话名仍按当前逻辑选择。提交时发送 `{configId, cwd | workspace, name}`，不再发送 `preset`/`cmd`/`args`/`env`。
- 记住上次选择：只把配置 ID 写入浏览器本地键 `lastLaunchConfig`，不缓存配置内容。首次加载时若 `lastPreset` 存在，选择同名种子配置（种子名称取预设 `name`）；否则选中第一条配置。
- 保留折叠的“临时命令（不保存）”入口，继续支持预设 + 追加参数 + 自定义命令，用于一次性启动和存储不可用时回退。临时路径保持现有 `lastPreset`/`customCommand` 行为，不写服务端。
- 没有可用配置时显示空状态与“前往设置创建启动配置”链接（`/settings#launch-configs`）；存储不可用时说明原因，同时提供临时命令入口。
- 桌面 Dialog 与移动 Drawer 共用同一表单，选择控件需在窄屏可操作；加载配置时禁用提交，避免发送空 `configId`。

### 7. 校验与安全

- 认证、Host、Origin 校验与单用户模型不变；启动配置接口只通过已认证的 `/api/*` 暴露。
- 启动配置可以执行任意命令，与现有自定义命令接口一致，不新增提权或沙箱承诺。部署仍应限制在 loopback 或可信 VPN。
- 环境变量可能含密钥：文件权限 0600、目录 0700；API 只返回给已认证请求；服务端不记录请求体或配置中的值；设置页默认遮挡；命令预览和 E2E 截图不得包含值。
- 显式 `env` 覆盖服务进程环境中的同名变量，`WEBMUX_SESSION_ID` 不可覆盖；不复制调用方环境。
- 请求体严格 JSON、64 KiB 上限、数量与单项长度限制共同防止无界存储与超大响应；读取时也校验文件内容，损坏文件不进入可用状态。
- 不新增 CORS 例外、静态文件或未认证的诊断端点。

### 8. 备选方案

- 写回 `config.toml`：会破坏注释和手写格式，且需要重启才能生效；不采用。
- 仅保存在 `localStorage`：无法跨设备，与“服务端持久化”的需求冲突；不采用。
- 只保存预设名与追加参数：预设变化或删除会让已保存配置失效，且无法表达完全自定义命令；不采用。
- 损坏文件自动改名并重建（push 存储的做法）：会静默丢失用户配置；不采用。
- 单独的秘密存储或加密：本期单用户与 0600 文件边界足够，增加复杂度且没有明确威胁模型；不采用。
- 在 `SessionInfo` 中加 `configId`/配置名：本期没有必要，且会扩大契约面；后续需要时再加可选字段。

## Risks / Trade-offs

- [命令快照与 TOML 预设漂移] → 设置页与新建会话页明确提示“保存的是创建时的命令副本”；预设修改不会回写配置。
- [环境变量以明文保存在状态文件] → 文件 0600、目录 0700、API 仅认证可见、值默认遮挡、日志不记录；但这仍不是加密存储，拥有服务账户文件访问权的用户可以读取。
- [损坏文件导致功能不可用直到重启] → 保留原文件优先于可用性，避免用户配置丢失；错误信息给出路径，会话服务不受影响。
- [`api.New` 增加必需参数会波及大量测试与调用点] → 以编译错误为准逐个更新，并保留一个不依赖启动配置的测试构造路径；主要改动是机械接线。
- [64 KiB 请求上限小于“128 项 × 8 KiB”的理论上限] → 这是有意的整体边界；前端提前限制并在超限时给出可读错误。
- [删除配置后无法从会话反查配置] → 本期通过 `cmd` 完整值仍可还原命令；配置名与首页一键启动留到下一期。
- [并发编辑后写覆盖] → 本期单用户场景接受；后续如需多端同时编辑再增加版本号或冲突提示。
- [环境变量拼写错误不会在启动时被程序发现] → 与现有 `env` 接口行为一致，只校验名称与 NUL；不尝试解释变量语义。

## Migration Plan

- 首次启动且 `launch-configs.json` 不存在时，按 TOML 预设生成默认配置；没有旧服务端数据需要迁移。
- 浏览器端保留旧的 `lastPreset`/`customCommand`：`lastPreset` 用于首次选中同名种子配置，`customCommand` 继续作为临时命令内容；不把浏览器旧值自动上传为服务端配置。
- 现有客户端与脚本继续使用 `preset`/`cmd`/`args`/`env`；服务端保持兼容。
- 回滚：停止使用前端入口即可，状态文件可原样保留；服务端回退版本会忽略该文件，不影响会话创建。若文件损坏，可手动修复或删除后重启以重新种子。
- 实现顺序：M1 存储 → M2 API 与接线 → M3 前端 → M4 测试与文档；每步保持可编译、可回滚。
