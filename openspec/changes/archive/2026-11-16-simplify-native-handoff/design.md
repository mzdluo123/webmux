## Context

动机见 proposal.md。规划基线为 origin/main `cda9edff`，已包含九个 reader 和 Snapcompact 文本交接。
`cmd/webmux/feature_start.go` 同时把 conversation 注入 hybrid 和 handoff；`native_history.go` 的 historyimport 也依赖该存储。
因此删除 SQLite 必须覆盖普通聊天、原生历史、归档浏览与恢复的消费者，不能仅移除交接按钮或数据库构造。

当前并非所有 SQLite 都是 WebMux 状态：agy、Devin、OpenCode 的原生 reader 依赖只读 SQLite。
最终目标是不存在 WebMux 自有 SQLite 状态与写入，而不是全项目禁止 SQLite。

## Goals / Non-Goals

**Goals:**

- 原生历史、机械投影和一次投递形成唯一交接路径；现有 reader 与中立边界继续复用。
- 删除 conversation 数据库和专为持久交接、独立快照、覆盖对账建立的链路。
- 服务重启使预览和未完成交接失效，不恢复、不重发、不重建资源。
- 保留普通聊天、队列、TUI/ACP 切换、Agent 原生恢复和进程内单写者保护。

**Non-Goals:**

- 不建立 JSON 操作日志、快照对象库、替代事务层或后台恢复任务。
- 不承诺跨进程恰好一次，不自动修复发送结果不明。
- 不提供完整独立 Fork、增量覆盖或生产图片交接；既有独立图片实验不阻塞文本路径。
- 不删除用户原生会话，也不自动删除旧 WebMux 数据库备份。

## Decisions

### 1. 保留轻量原生身份，不保留第二套会话树

运行身份直接使用现有 hybrid 记录的 runtime ID、Agent、native ID、HistoryRoot 与 cwd。
不为每次交接建立 Conversation、ProviderThread、Run 或父子关系。
保留精确来源绑定和原生占用检测，不用标题、cwd 或文本相同猜测身份。
归档历史继续从对应原生来源读取；无精确身份时明确报告不可读。
普通 hybrid 自动恢复不等于交接恢复，恢复后不得重建或重发旧交接。

### 2. 冻结范围仅在本进程有效

historyimport 去掉 Store 接口中的持久 manifest、retain/release、导入元数据及 dispatch 覆盖依赖。
保留发现、只读解析、来源边界校验、分页和 Snapcompact 投影，不重复实现九个 reader。
预览记录固定来源、分支、边界、解析版本、hash、目标身份、投影参数和确切发送文本。
旧范围后的追加不影响预览；范围内变化、源文件消失、目标改变或参数改变要求重新预览。
每次预览有效期五分钟，最多保留 32 个；预览文本及 manifest 总计最多 64 MiB，单请求沿用现有较小预算。
过期条目按请求惰性清理，达到上限拒绝新增，不淘汰发送中的操作，不增加清扫 goroutine。
原文补查只在有效快照范围内执行；服务重启或过期后明确失效，不回退读取当前完整来源。
当前任务不参与预处理，历史包装明确为参考而非指令。

### 3. 一次性普通文本投递

所有交接通过现有 hybrid 普通 prompt 能力发送机械投影和独立用户任务，不走 HistoryInjector。
同 Agent 和跨 Agent 均使用同一机制；不自动选择复用旧线程以获得增量收益。
创建新聊天仍可选择既有目录或创建 worktree，但仅在确认发送后执行，预览不产生资源。
各目标创建与发送只执行一次；失败时返回已知目标和已创建资源，不后台重试、不自动删除用户目录。
取消前检查发送是否开始；一旦外部调用可能发生，就不能宣称未发送。

### 4. 防重复只覆盖本进程，不建立持久状态机

预览 ID 绑定随机服务实例标识；发送必须使用有效预览和操作 ID。
同操作 ID、相同 payload 复用本进程结果；不同 payload 返回冲突，不再次调用目标。
用锁把操作登记与发送权领取组成一次内存状态转换，已有 actor 继续管理目标写者。
内存结果只有准备中、发送中、成功、明确失败、结果不明，不持久化资源阶段或逐项回执。
结果缓存最多 256 项、完成后保留十五分钟；满额拒绝新增，过期 ID 不可恢复或再次消费同一预览。
预览第一次接受发送即被消费，后续不同操作 ID 也不得再次发送该预览。
请求断线不释放发送权，未取得明确结果时显示“可能已发送，请检查目标会话”。
浏览器刷新后不得从本地草稿恢复待发送命令；重新连接发现服务实例改变时清空操作句柄。
旧实例的请求返回失效；不得静默创建新操作。用户检查目标后可以主动重新预览发送，不保证跨进程去重。

### 5. 明确停止独立快照 Fork 保证

新的“交接到新聊天”只有投递文本，不是完整历史分支。
保留真实目标 Agent 原生 session ID；目标如何保存收到的文本由 Agent 决定。
不复制模型内部状态、正在运行的工具或后台进程。
没有 retained exports、前缀引用、引用计数和父子删除传播；原生来源消失后补查可以失败。
不把截断投影标成完整原文，也不把普通新聊天恢复说成恢复独立完整快照。

### 6. 干净删除与协议切换

删除 `internal/conversation` 的数据库、迁移及旧行为测试；将仍需要的中立值移到真实消费领域，不保留兼容 re-export。
删除 hybrid 的 conversation 同步、持久 Run/receipt、原生历史注入、覆盖与恢复 gate，保留一般 prompt 的本进程防重复。
handoff 只保留预览、预算、一次投递；删除旧 delivery/checkpoint/reconcile/provider-switch 事务编排。
更新 featureapi、featurewire、contract、MCP thread_read 和客户端，使用短期快照/操作句柄，不再暴露 conversation/run 身份。
删除 `handoff-draft.ts`、`handoff-recovery.ts` 中持久恢复职责，重组表单及预览组件；不保留旧模式切换开关。
原生端点去掉 import、retain、release 与独立备份语义；旧请求明确拒绝，不成功空返回。
统一更新 REST、MCP 和 CLI 的错误及 Zod/wire 契约；认证、Origin 和文件访问授权保持现有入口。

### 7. 旧数据只保留离线原件

新版不打开、加锁、迁移、修复或删除 `conversations.sqlite`、其 journal/WAL/SHM 与旧生命周期锁。
损坏或锁冲突的旧库不再阻止新建聊天、原生恢复或交接；不通过删除文件达成此行为。
启动提供不含正文的废弃存储提示，说明旧草稿、独立快照及回执不再可在线访问。
升级前停旧进程并备份完整 state_dir；用户需要旧的仅存 SQLite 正文时，在升级前用旧版本检查和导出。
回滚必须停止新进程并恢复旧版及匹配备份；不把旧 pending 操作解释为可自动重发。
删除 statefile descriptor、持久化清单、契约适配器与 runtime 打开路径；保留原生只读 SQLite 依赖和其他 JSON 存储。

## Risks / Trade-offs

- 崩溃后发送结果无法自动恢复：接受人工检查，不增加替代账本掩盖这一限制。
- 重复完整投影可能增加输入成本：用户选择范围和查看预算，不恢复增量对账。
- 仅存在于旧 SQLite 的历史或 retained 前缀不再在线可读：保留原文件并明确升级警告，不伪称原生库一定有副本。
- 多浏览器仍可能产生不同的新操作：不做跨设备草稿协作，但共享进程内预览消费与目标写者保护。
- 删除旧测试可能误伤普通会话恢复：按行为保留并改写测试，只有已撤销能力的契约测试可删除。

## Validation

- 证明本进程同一预览并发发送、相同操作重试、修改 payload、取消和断线不会产生第二次调用。
- 证明服务重启后旧句柄失效且普通 hybrid 恢复不发送旧交接；只读原生历史不创建 WebMux 状态库。
- 覆盖冻结范围追加、前缀修改、删除、未知格式、身份不符和分页 Unicode。
- 用隔离后端与浏览器验证新流程、结果不明提示、新聊天和 worktree 边界；原生 SQLite 三种 reader 必须继续通过夹具。
- 按依赖运行定向 race、wire snapshots、前端架构、文档/持久化守卫及完整 CI；不以 fake 测试声称九 Agent 真实模型全部验收。
