## MODIFIED Requirements

### Requirement: 仓库节点操作菜单

工作台侧栏导航树中，每个可用仓库节点 SHALL 在行尾提供一个“⋯”操作菜单按钮（替代原有的单一“+”按钮），菜单内依次提供：

- “新建工作树…”：打开与仓库标题栏“新建工作树”相同的现有弹窗，预选该仓库，默认只创建工作树，勾选“创建后启动会话”后才启动会话；
- “管理工作树…”：打开该仓库的“管理工作树”批量管理弹窗。

交互与可用性规则：

- 菜单按钮 SHALL 具备“仓库操作：{仓库名}”的可访问名称与可见提示；
- 桌面端在仓库行悬停、获得焦点或菜单展开时显示，触屏设备上始终显示；
- 仓库不可用、仓库清单不可用或 Git 不可用时，按钮不显示。

#### Scenario: 从会话页新建工作树

- **WHEN** 用户在会话页的工作台侧栏打开 `webmux` 仓库行的“⋯”菜单并选择“新建工作树…”，填写分支后确认
- **THEN** 打开现有的新建工作树弹窗，创建成功后新工作树出现在树中 `webmux` 下；当前会话页保持不变

#### Scenario: 勾选创建后启动会话

- **WHEN** 用户通过侧栏仓库菜单打开新建工作树弹窗，勾选“创建后启动会话”并选择一个启动配置
- **THEN** 结果与从仓库标题栏进入时相同：创建工作树并启动会话，进入该会话

#### Scenario: 从侧栏打开批量工作树管理

- **WHEN** 用户在工作台侧栏打开 `webmux` 仓库行的“⋯”菜单并选择“管理工作树…”
- **THEN** 打开 `webmux` 的“管理工作树”弹窗，展示该仓库全部工作树供筛选与批量删除，不离开当前页面

#### Scenario: 不可用的仓库

- **WHEN** 仓库路径缺失或 Git 不可用
- **THEN** 该仓库节点不显示“⋯”操作按钮，节点提示中说明不可用原因
