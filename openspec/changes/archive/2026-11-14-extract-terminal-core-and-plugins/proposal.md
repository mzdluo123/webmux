## Why

WebMux 的终端会话生命周期与仓库、代码、聊天等业务共同装配，当前 API 构造甚至要求 Workspace、Code、Files 同时存在，无法只运行终端核心。
需要按完整功能纵向拆分，使每个内置插件同时拥有前端界面、后端业务和状态，禁用时真正停止其运行，而不只是隐藏按钮。

## What Changes

- 保留 PTY、输入输出、回放、控制权、基础会话列表、浏览器终端、移动端输入、原生附着与安全传输为核心。
- 保留服务运行、本机控制面、基础偏好及配置/更新基础设施；将其他业务划归具名内置插件，完整归属见 design.md。
- 插件可以贡献独立页面、导航、会话面板、菜单操作、设置分区、API、WebSocket 与后台任务。
- 使用静态注册、显式依赖注入和同一二进制分发；不引入 Go 动态库、远程脚本、外部插件进程或插件市场。
- 服务启动时解析插件启用集和依赖；配置变更重启生效，不实现热卸载。
- 增加经过鉴权的能力发现契约；前端验证后只加载已启用插件的本地模块。
- 禁用插件不构造服务、不注册业务路由、不打开其专属状态、不执行其后台任务，保留已有数据。
- **BREAKING**：显式禁用插件后，对应业务路由返回 404；依赖被禁用插件的请求字段被明确拒绝，不能静默降级或产生部分副作用。
- 未声明插件启用集的既有配置保持现有功能组合及各功能原有安全开关；新生成配置显式选择纯核心。

## Capabilities

### New Capabilities

- `terminal-core-host`：零插件的完整终端工作流、安全边界、非阻塞扩展和现有功能的插件归属。
- `builtin-plugin-lifecycle`：内置插件标识、依赖解析、配置默认规则、启动/停止、路由挂载与状态保留。
- `plugin-ui-contributions`：服务端能力发现、前端惰性加载、页面/面板/操作/设置贡献及能力不可用行为。

### Modified Capabilities

- `app-shell`：按启用能力提供终端、工作台与聊天导航，清理不再可用的本机导航选择。
- `new-session-dialog`：没有仓库、启动配置、聊天或文件插件时仍可通过目录和自定义命令创建纯终端。
- `effective-configuration`：区分磁盘插件选择与运行时启用结果，展示安全来源及不可用原因。

## Impact

- Go：`cmd/webmux`、`cmd/internal/assemble`、`internal/api`、`hub`、`session`、`config`、`contract`、`wire` 及全部可选服务装配。
- 浏览器：`web/src/App.svelte`、页面、shell、终端/会话 hooks、platform API、contracts 与各 domains 的启动入口。
- 客户端：CLI、Windows 控制台和托盘按能力隐藏或拒绝可选操作；普通 run/attach/ls/open 与本机服务控制保持可用。
- 线上契约：增加能力快照；保留启用插件的既有业务路径、请求形状及安全约束，不并行维护第二套兼容 API。
- 架构：服务仍仅由 cmd 构造，HTTP 属于 Controller，线上 JSON 属于 contract/wire；增加核心不得依赖插件实现的守卫。
- 验证：零插件、单插件、声明依赖组合和原功能组合；真实 PTY/浏览器/CLI 场景及禁用后的路由、文件和进程副作用。
- 本变更仅规划，不把尚未实现的能力写成已完成 User Story；实施时更新受影响故事并新增插件管理故事。
