# Design

## Context

`SessionPanelDock.svelte` 目前从代码与分屏操作页中选择一种侧栏内容，手机用 `SessionPanelPickerSheet`。`TerminalSplitPanel` 提供新建、加入、放大和移除窗格。分屏操作页是命令列表，承载 PTY 输出的是终端窗格；迁移时应分别处理。

## Goals / Non-Goals

- 同一套布局操作可以移动聊天、代码导航、阅读器和多个终端；保留原有内容组件与领域状态的所有权。
- 停靠范围是当前会话页或 Git 页的当前模式。全站导航、跨模式混排、浏览器全屏、自由浮窗与跨设备布局同步不在范围内。

## Decisions

1. 使用分割树：分支记录轴与比例，叶组记录有序面板标识和活动项。终端标识关联已有会话，标题仅供显示；同一面板在布局中只有一个位置。相同名称的终端在选择器中加窗格序号区分。
2. 最小化保留逻辑占位；渲染时压缩无可见内容的组。最大化只记录一个临时目标，取消时直接展示底层树。此设计避免把还原实现成一串逆向拖动。
3. 从同一个布局命令入口处理拖放、菜单和现有终端缩放快捷键。拖动从标题栏开始，保留文本选择、终端鼠标协议和文件树拖动行为。移动焦点时优先定位标题栏控件，输入区仅由显式输入操作聚焦。
4. 文件树与阅读器共享当前代码工作区上下文；打开文件只更新阅读器。聊天草稿、PTY 输出订阅及终端尺寸归各自领域管理，面板布局只持有引用。隐藏尺寸不发送给 PTY，还原后按可见区域重新适配。
5. 手机渲染单面板投影，单独记录最近访问顺序；跨断点复用实例。宽屏布局按浏览器和主会话保存，版本化校验后恢复；失效的终端引用剔除，非法布局回到可用默认布局。
6. Git 工作台复用停靠命令和标题栏。按 Git 页面与模式区分布局存储键；只持久化几何、标签及收起状态。工作树、选中提交、暂存区、贮藏条目和草稿由 Git 控制器按原作用域管理，布局恢复不写入这些字段。
7. `GitWorkbenchWorkspace` 的四个模式保留顶部导航。现有桌面多栏骨架用作各模式默认排列；进行中横幅、操作账本、冲突解决器和确认对话框位于停靠树之外，放大面板仍能识别工作树与操作状态。Git 沿用自身内容宽度断点。

## Risks / Trade-offs

- 后台混合会话抢焦点 → 保留显式视图切换和控制授权，面板事件只操作布局；继续覆盖后台请求不抢前台的场景。
- 对话框、拖拽与终端热键争用 → 仅标题栏或已聚焦的布局菜单接收相应布局命令；底部抽屉取消时归还入口焦点。
- 在途 `mobile-panel-picker-sheet` 规定固定「代码 / 分屏」目的地 → 复用单入口、可取消抽屉和可用性筛选，实例列表接替固定二选一。两份规范归档前须统一该契约，避免同一入口同时被要求展示不同列表。

## Migration Plan

原有分屏布局首次进入时映射为终端叶组，保留会话引用和可表达的排列；未设置布局的会话按能力采用默认布局。移除旧的独立缩放和侧栏选择状态入口，保留新建、加入及显式退出会话操作。

布局数据使用独立版本，不改写服务端记录。回退前端仅忽略新版布局，运行中的会话继续沿用现有协议。
