# Spec Delta

## Purpose

用户可在会话内排列聊天、文件与终端，也可在 Git 工作台的当前模式内排列列表、详情与差异。两处共用停靠操作，独立恢复布局；手机按任务逐步查看内容。

## ADDED Requirements

### Requirement: 按内容实例组织工作区

工作区 SHALL 将可用的聊天、文件树、文件或 Diff 阅读器以及各终端实例作为可分别停靠的面板。入口 SHALL 按会话能力呈现；新建或加入终端沿用现有权限和数量限制。

#### Scenario: 左聊右看时运行测试

- **WHEN** 宽屏混合会话使用默认布局，用户打开代码并新建第一个辅助终端
- **THEN** 左列保留聊天，右列上方保留文件树和阅读器，新终端停靠于右列下方；输入草稿仍在原聊天面板

#### Scenario: 纯终端会话

- **WHEN** 用户在不支持聊天且未启用代码功能的会话打开选择器
- **THEN** 只列出可用终端和可执行的终端操作，不出现空聊天页或文件树

### Requirement: 分组停靠与空间分配

用户 SHALL 能调整相邻组之间的比例，将面板停靠到目标组的四条边，或并入该组的标签栏。拖动时 SHALL 预览落点；同一组操作 SHALL 可用键盘通过菜单完成。

#### Scenario: 比较两个终端

- **WHEN** 用户将测试终端拖到构建终端所在组右边并释放
- **THEN** 两个终端左右并列；用户可调整它们之间的分隔线，两个终端的身份和输出各自保持

#### Scenario: 并为标签或取消移动

- **WHEN** 用户经面板菜单选择目标组和「并为标签」
- **THEN** 目标组同时列出两个标签，移动的面板成为当前标签；若用户在提交前取消，原布局保持不变

### Requirement: 最小化与原位恢复

每个面板 SHALL 可单独最小化，释放其占用的空间，并保留带实例名称的恢复入口。恢复 SHALL 回到原组；若原组已被其他布局操作移除，则并入当前组。隐藏面板 SHALL 保留草稿、文件位置和运行中的会话。

#### Scenario: 收起运行测试的独占面板

- **WHEN** 用户最小化独占一组的测试终端，待测试完成后从工作区边缘点其名称恢复
- **THEN** 相邻组先取得空出的空间；恢复后测试终端回原位并能看到完成结果，进程未被重新启动

#### Scenario: 最后一个面板

- **WHEN** 用户最小化最后一个可见面板
- **THEN** 工作区仍有可聚焦的面板入口，可直接恢复已收起的实例

### Requirement: 标题栏最大化与精确还原

双击面板标题栏空白处 SHALL 切换工作区内最大化；可见、可键盘操作的最大化或还原按钮 SHALL 提供等价操作。最大化保留会话顶栏，暂时隐藏其他组。标题栏按钮、标签及内容区的双击 SHALL 不触发布局切换。

#### Scenario: 临时专注 Diff

- **WHEN** 用户在已有多个标签、非等比分屏和已收起终端的布局中双击 Diff 标题栏，再使用还原按钮
- **THEN** Diff 先独占工作区，随后恢复先前分组、比例、活动标签和收起状态，阅读位置不变

### Requirement: 布局操作独立于输入权

移动、收起、恢复、最大化及查看面板 SHALL 不改变混合会话的活动视图或终端控制权，不提交输入或中断回合。只有显式切换视图或取得控制后才允许相应输入。

#### Scenario: 聊天中查看同一会话的终端

- **WHEN** Agent 正在处理聊天请求，用户放大同一会话的终端观察输出
- **THEN** 聊天回合继续，终端保持其既有输入权限；还原后用户仍可在原聊天中继续工作

### Requirement: 手机单面板与宽屏布局隔离

小于 640 CSS px 时 SHALL 一次显示一个面板。顶栏唯一面板入口 SHALL 打开底部选择器，按实例名称列出当前与已收起面板。手机切换或最小化 SHALL 不覆盖宽屏布局；平板横屏空间可容纳两组时 SHALL 支持并排。

#### Scenario: 手机查看文件再返回

- **WHEN** 用户从文件树打开文件并返回
- **THEN** 阅读器先占满内容区，返回后文件树保留原展开项、选中项和滚动位置

#### Scenario: 只看日志

- **WHEN** 用户在手机从聊天切到测试终端，再最小化该终端
- **THEN** 查看时软键盘保持收起；最小化后回到上一个可见面板，聊天草稿保留；无可返回项时呈现选择器

#### Scenario: 取消选择并回到桌面

- **WHEN** 用户缩窄已排好两组的桌面工作区，在手机选择器中切换一次、再次打开并取消，随后恢复原宽度
- **THEN** 取消时当前面板不变；回到宽屏时恢复原分组、比例、各组活动标签与最小化状态

### Requirement: Git 模式内自由停靠

Git 工作台 SHALL 保留历史、提交、分支、贮藏四个模式。每个模式内的内容面板 SHALL 支持边缘分屏、中央合组、键盘菜单、最小化恢复和双击标题栏最大化还原。目标组和选择器只列当前模式的面板。模式导航、当前工作树和进行中操作提示保持可达。

#### Scenario: 在历史中专注一个文件的差异

- **WHEN** 用户在历史模式选择一条提交及其文件，将历史 Diff 移到提交列表右侧，再双击标题栏放大并还原
- **THEN** 提交、文件、阅读位置保持不变；还原后保留调整过的排列，检出分支不变

#### Scenario: 切换模式后恢复各自布局

- **WHEN** 用户收起历史模式的引用树，切到提交模式重新排列提交输入区，再返回历史
- **THEN** 历史模式仍收起引用树，不显示提交输入区；再进提交模式保留输入区位置。两次操作均不改变会话页布局

#### Scenario: 分支和贮藏独立查看

- **WHEN** 用户在分支模式合组列表与详情，随后在贮藏模式放大所选条目的详情
- **THEN** 分支布局保持原状，显示的贮藏详情仍对应所选条目；布局操作不执行检出、应用或删除

### Requirement: Git 布局不改变操作对象与确认流程

Git 面板的调整、收放与恢复 SHALL 只改变可见空间。提交草稿、阅读选中项、审阅标记与真实暂存状态保持各自语义。冲突处理及提交、推送等预览和确认 SHALL 继续沿用 Git 专用流程。

#### Scenario: 收起草稿检查部分暂存文件

- **WHEN** 用户写入提交说明，收起输入区并放大部分暂存文件的 Diff，随后恢复输入区
- **THEN** 草稿与暂存内容保持不变；显式点击提交才进入完整暂存区预览

### Requirement: Git 手机保留单栏步进

Git 手机布局 SHALL 在当前模式内提供选择器，并保留历史与提交的单栏前进和返回路径；切换手机面板 SHALL 不改写该模式的宽屏布局。

#### Scenario: 从手机历史 Diff 返回宽屏

- **WHEN** 用户在 390px 手机上从提交列表进入详情、文件与 Diff，再返回并扩大窗口
- **THEN** 手机上返回原选中对象及列表位置；宽屏恢复历史模式原有分组、活动标签、比例与收起状态
