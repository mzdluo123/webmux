## Why

agent 在任务中途请求授权或提问时，用户很容易错过提醒，agent 因此长时间空等：

- 页面右上角的提醒没有声音，用户切到其他窗口或离开屏幕时注意不到。
- 系统通知依赖 Web Push，而 Web Push 只在 HTTPS 入口或本机回环地址可用。经 `http://<Tailscale IP>:7681` 或局域网地址远程访问的设备既不能订阅推送，也不能调用浏览器通知接口。

浏览器在 HTTP 页面中仍可播放声音，因此需要页面提示音，并允许用户换成自己熟悉的声音。

## What Changes

- **页面提示音**：打开着的 WebMux 页面在会话出现新的关注时播放提示音，判定沿用页内弹窗的去重规则：同一信号只响一次，初始快照只建立基线，重连快照补报断线期间的新信号。
  - 不依赖 HTTPS、通知授权或 Web Push，HTTP 远程访问同样可用；页内弹窗关闭时仍可单独使用。
  - 关注分两组设置：紧急（需要回答、等待授权、出错停止）与普通（本轮完成、有通知、响铃提醒），每组可选静音、内置音色或自定义音频；默认紧急组播放内置音色、普通组静音。
  - 提供音量调节与试听。
- **内置音色**：几种由浏览器实时合成的短音，不随前端打包音频文件，同时作为自定义音频不可用时的兜底。
- **自定义音频**：每台设备可上传一个音频文件，两组共用。
  - 文件只保存在当前浏览器，不上传服务端、不跨设备同步。
  - 上传时校验大小（不超过 1 MiB）、时长（不超过 10 秒），并要求当前浏览器能够解码，不合格时拒绝并说明原因。
  - 文件被浏览器清除或无法播放时退回内置音色，并在设置中提示重新上传。
- **多标签页去重**：同一浏览器打开多个 WebMux 页面时，同一关注只播放一次；同时到达的多条关注合并为一次播放。
- **设置卡片**：“通知推送”卡片新增“提示音”设置；卡片在非安全上下文中说明推送不可用的同时，提示页内弹窗与提示音在当前地址仍然可用。
- **文档与用户故事**：说明提示音的设备本地范围、HTTP 远程访问的提醒能力，以及同一浏览器从不同地址订阅推送会收到重复通知。

不在本次范围：

- 页面在后台时由页面直接弹出系统通知：远程设备当前经 HTTP 访问，无法使用；HTTPS 场景已由 Web Push 覆盖。
- Windows 托盘原生通知。
- 修改系统通知或 Web Push 通知的声音：浏览器不支持为通知指定音频。
- 跨设备同步提示音设置或自定义音频。

## Capabilities

### New Capabilities

- `attention-sound`：浏览器页面在会话出现新关注时播放提示音，涵盖触发与去重、按关注分组的音色选择、内置音色、设备本地的自定义音频及其校验与失效兜底、音量与试听、多标签页合并播放，以及浏览器自动播放限制下的行为。

### Modified Capabilities

- `push-notification-client`：非安全上下文提示在说明推送需要 HTTPS 的同时，指出页内弹窗与提示音在当前地址仍可使用。

## Impact

- **前端**：
  - 新增提示音模块：设置读写、内置音色合成、播放与跨标签页去重。
  - 新增自定义音频的 IndexedDB 读写模块（前端首次使用 IndexedDB）。
  - 修改 `web/src/attention-toast.svelte.ts`，在判定出新关注时通知提示音模块，与弹窗开关无关。
  - 在 `web/src/components/PushSettings.svelte` 中加入提示音设置（新组件）；更新卡片说明与非安全上下文提示。
- **后端**：无改动。会话列表 WebSocket、`SessionEventSchema`、`internal/contract` 与 wire 快照不变，也不新增服务端存储。
- **依赖**：不新增 npm 依赖；使用浏览器自带的 Web Audio、IndexedDB 与 `localStorage`。
- **文档**：`docs/usage/attention.md`、`docs/deployment/pwa-and-push.md`、`docs/usage/sessions.md`（跨设备偏好表）；用户故事修改 US-C06、US-C12，新增 US-C19。
