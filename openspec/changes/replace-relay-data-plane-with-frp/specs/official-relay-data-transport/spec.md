# Spec Delta

## Purpose

定义官方自营中转在宿主与数据节点之间建立、验证、监督和撤销受管反向业务隧道的契约，保证用户在固定浏览器入口上的访问仍受原有身份边界控制，并且能区分连接进程存活和真实业务可用。

## ADDED Requirements

### Requirement: 受管上游 frpc 制品与进程生命周期

WebMux SHALL 随安装和更新交付原版 `frpc` v0.72.0、许可证及签名发布清单，覆盖 Linux/macOS amd64、arm64。WSL 使用发行版内的 Linux 制品。启动前核对受管绝对路径、平台、版本和 SHA-256；缺件或不符仅使 Relay 业务未就绪，不搜索 PATH 或在线补件。
每个活动 Scope SHALL 最多运行一个受管子进程。运行目录权限 SHALL 为 0700，文件权限为 0600；子进程仅取得受限配置与业务令牌。宿主配对、桥接、回源私钥不传给 frpc；凭据不进入 argv、环境或日志。分配、桥接密钥、业务令牌及回源材料仅用于当前运行代际，MUST NOT 写入持久绑定状态。
关闭（包括启用意图写盘失败时的关闭）、撤权、停服回滚及退出 SHALL 关闭监听和关联连接、收割子进程并清理运行文件。异常恢复只清理可证明归属的资源，无法排除重叠时保持未就绪；重启不得复用上一代际。业务中断先清就绪，按当前租约取得新登录许可并有界退避、抖动和冷却；管理失效则重新持钥认证并取得新代际分配。

#### Scenario: 各宿主平台从安装包启用

- **WHEN** Linux、macOS 或 WSL 用户安装或升级配套发布件后启用 Relay
- **THEN** 宿主无需预装 frp 或联网下载制品即可启动一个受管 `frpc`；WSL 中运行的是 Linux 制品，Windows 侧不出现额外隧道进程

#### Scenario: 受管制品缺失或不匹配

- **WHEN** 发布清单所列 `frpc` 缺失，或其摘要、平台或版本不匹配
- **THEN** Relay 业务保持未就绪并报告脱敏配置错误，不启动替代程序；本机 HTTP、PTY 与其他入口保持可用

#### Scenario: 业务进程崩溃后恢复

- **WHEN** `frpc` 异常退出，管理 WSS 仍有效且宿主仍启用 Relay
- **THEN** 撤销业务就绪，清理该子进程资源，限速取得新登录许可并启动至多一个替代进程；当前实际回源重新通过后才恢复业务，既有 PTY 不退出

#### Scenario: 停止期间出现重连事件

- **WHEN** 整代撤权、用户关闭或整版回滚与重连、续期或进程退出通知并发
- **THEN** 停止旧监听和连接，收割所属子进程并清理其文件；旧通知不能恢复授权、写回凭据或重启旧实例

### Requirement: 宿主固定 WSS Upgrade 桥与出口门禁

宿主桥 SHALL 只在本机 loopback 接受匹配 Host 的 `GET /~!frp` WebSocket Upgrade；拒绝查询、其他路由和普通代理。桥固定拨号至当前分配的受信 WSS/443 路径，重写 Host、SNI、Origin，清除外来认证/转发头，只向该入口交付桥接密钥；密钥不入 URL、不交给 frpc。
每条出站连接 SHALL 在发送 Upgrade 认证头或 frp 凭据前验证 TLS 1.3、CA、有效期、主机名和分配的 P-256 SPKI pin。桥只传递标准 Upgrade 字节，不附加自定义业务帧；限制连接数、拨号率、头大小和握手期限，撤权时关闭两端，不接受重定向、环境代理或公网明文。
发行门禁 SHALL 使用真实制品分别验证仅 DNS 与 TCP/443 可用、TCP 被阻和 Upgrade 被拒；记录阶段与目的地，不从超时推断拦截原因。检查公网 IPv4/IPv6 均不可达节点私有端口。

#### Scenario: 只开放 TCP/443 的受限出口

- **WHEN** 隔离宿主仅可使用受控 DNS 和所需 TCP/443，无法出站 UDP 或 frp 原生 TCP 端口
- **THEN** 通过实际 WSS 验证管理、受管登录及工作连接，并以真实应用 HTTP、WebSocket 和回源探针证明基线可用；不等待 UDP 或开启额外监听

#### Scenario: HTTPS 正常但 Upgrade 被拒

- **WHEN** 普通 HTTPS 与 TLS 校验成功，但出口策略或入口拒绝业务 WSS Upgrade
- **THEN** 报告脱敏 Upgrade 失败且不置 `dataReady`；不切换到公网明文 WS、原生 TCP、UDP、未知地址或旧业务传输

### Requirement: 管理代际与短期传输授权隔离

宿主 SHALL 经原持钥认证管理流获取当前 Scope、节点、分配和修订专属的业务授权。控制面签发短期 JWT，绑定 issuer、节点 audience、分配、角色、代际、期限和 jti；节点确认新修订后宿主原子替换受限令牌文件，普通续期不重启进程。
节点 SHALL 在上游 OIDC 核验之外，以私有 Login/NewProxy/NewWorkConn/Ping 门禁校验用途、当代授权和会话归属；新注册仅允许授权的唯一 TCP 代理名和节点 loopback 端口。
登录、工作和心跳凭据来自当期文件，服务端分配的 run ID 不接受客户端指定。旧登录票据不能重新登录，错误受众、代际或角色均拒绝；验证服务故障不得放行。
管理撤权、失联或授权过期 SHALL 以先到者为准，停止新工作并关闭对应连接。普通换签交接 MUST NOT 延长管理租约、撤权或令牌到期边界。业务票据不能变成浏览器、ICE、节点管理或代际恢复凭据；认证错误不得改用共享 Token。

#### Scenario: 普通续约保持现有长连接

- **WHEN** 当前管理会话仍有效且节点确认新授权修订
- **THEN** 宿主原子更新受限令牌文件，后续工作与心跳使用当前授权，已有长连接不因普通续期重启；任何超期或被撤销修订均不能继续准入

#### Scenario: 旧代际的合法签名不能继续使用

- **WHEN** 绑定、连接或节点代际已更新，但旧 JWT 尚未到期，旧进程尝试注册、工作或心跳
- **THEN** 节点拒绝其所属会话及操作，宿主关闭旧路径；按当前认证分配重新恢复，不能复用旧 run ID 或授权文件

### Requirement: 回源专用入口与真实数据就绪

宿主 SHALL 为当前代际提供专用 loopback HTTPS 入口，frpc 仅转至该入口。网关只拨已分配的节点 loopback 端口，经 TLS 1.3 双向验证专用 CA、期限、用途、角色、Scope 和确切对端公钥；两端私钥不交给 frp，不复用配对、WSS 或 OIDC 密钥。
宿主 SHALL 仅在已验证回源上接受可信网关上下文，继续执行 Host、Origin、Cookie、CSRF 和会话校验；头部和端口可达性不证明授权。代际撤销关闭现有连接。
网关 SHALL 在当前注册首次取得真实工作连接上的 mTLS `HEAD /_webmux/relay-origin/ready` 响应 `204` 后才允许业务；注册或分配重建须重新验证。周期探测失败或通知迟到只改变诊断，单个业务请求失败不重放。探针不创建用户 grant，公网请求返回 404。
宿主 SHALL 仅展示来自当前认证管理流、匹配 Scope、分配和修订的有效观测。观测过期不改变独立的管理租约、传输票据、回源身份或应用会话期限。

#### Scenario: 私有端口可达但回源身份错误

- **WHEN** 实际代理端口已经监听，但连接到旧代际、通用本机监听或未持有当前回源凭据的进程
- **THEN** 双向 TLS 或专用探针不能成功，`dataReady=false`；不转发应用头、Cookie 或终端数据，不把端口可达误判为就绪

#### Scenario: 回源探针与浏览器登录分离

- **WHEN** 当前管理流和租约有效，网关通过当代 mTLS 获得 `204`，但尚无用户登录
- **THEN** 可公布原固定访问地址，但仍拒绝无有效登录凭据的受保护应用请求，不能领取 TURN 或复用回源身份作为浏览器 grant
