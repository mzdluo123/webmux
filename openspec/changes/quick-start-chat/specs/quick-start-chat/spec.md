# Spec Delta

## Purpose

快速开始聊天让用户在一个聊天式输入框里写下任务、选择仓库和 agent，按一次发送即在新 worktree 中启动聊天会话并开始工作，省去手动创建 worktree、选启动配置和等待聊天就绪这几步。

## ADDED Requirements

### Requirement: 快速开始页面

系统 SHALL 提供快速开始页面，入口位于首页工具栏和仓库侧栏，并在当前标签页打开。页面底部 SHALL 是消息输入框，附近放仓库、基准分支、agent、agent 会话配置和权限模式的选择控件，窄屏下也都能直接操作、不被截断。仓库列出全部已登记仓库；agent 只列出支持聊天端的已保存启动配置。

#### Scenario: 打开快速开始
- **WHEN** 用户在首页点击“新聊天”
- **THEN** 当前标签页显示快速开始页面，焦点在消息输入框，仓库、基准分支和 agent 已按上次的选择或默认值填好

#### Scenario: 没有可用仓库或 agent
- **WHEN** 没有可用的已登记仓库，或没有支持聊天端的启动配置
- **THEN** 发送按钮禁用，输入框上方说明缺少什么，并提供“添加仓库”或“新建启动配置”入口

#### Scenario: 不可用的仓库
- **WHEN** 某个已登记仓库当前不可用（路径缺失、Git 不可用或无权限）
- **THEN** 仓库菜单中该项禁用并显示原因，不能被选中

### Requirement: 选择记忆与默认值

系统 SHALL 在本设备记住上次快速开始成功时选择的仓库和 agent，作为下次的默认值。记住的仓库或 agent 不存在或不可用时，回退到第一个可用项。基准分支默认取所选仓库主工作区当前的分支，切换仓库时重新计算。

#### Scenario: 记住的 agent 已被删除
- **WHEN** 上次使用的启动配置已被删除，用户再次打开快速开始
- **THEN** agent 选择回退到第一个支持聊天端的启动配置，且不报错

#### Scenario: 切换仓库
- **WHEN** 用户在仓库菜单中改选另一个仓库
- **THEN** 基准分支改为该仓库主工作区当前的分支，初始化指令提示随之更新

### Requirement: 启动前展示 agent 会话配置

选定 agent 后，系统 SHALL 在输入框下方展示该启动配置最近一次聊天会话报告的配置项（如模型、思考强度、模式）及其可选值，默认值为该次会话最后使用的值。还没有记录时，配置区 SHALL 说明“首次启动后可选”，会话按 agent 默认值启动。权限模式由 WebMux 提供，始终可选。

#### Scenario: 有配置清单
- **WHEN** 用户选择以前用过的 agent，并把“思考”改为 high
- **THEN** 新会话启动后、首条消息发送前，思考配置已是 high

#### Scenario: 没有配置清单
- **WHEN** 用户选择一个从未以聊天端启动过的 agent
- **THEN** 配置区只显示权限模式和“首次启动后可选”说明，发送仍可用，会话使用 agent 默认配置

#### Scenario: 记住的配置值已失效
- **WHEN** 预选的配置值不在 agent 本次启动报告的可选值内
- **THEN** 系统保留 agent 的当前值，照常发送首条消息，并在聊天中显示一条说明哪项配置未能应用的提示

### Requirement: 一次发送完成创建与开工

用户发送非空消息后，系统 SHALL 依次完成：在所选仓库基于基准分支新建 worktree（自动生成不冲突的分支名和路径）、以聊天端启动所选 agent、应用预选配置和权限模式、把首条消息作为第一轮提示发送。首条提示由服务端发送，浏览器在过程中断开也不影响。全部成功后，页面在当前标签页进入新会话的聊天视图。

#### Scenario: 成功开工
- **WHEN** 用户输入“修复首页排序”，选择仓库 webmux 和 agent Claude Code 后按发送
- **THEN** webmux 多出一个基于基准分支的新 worktree，新会话以聊天端运行在其中，第一条用户消息已发出，页面进入该会话的聊天视图

#### Scenario: 发送过程中关闭页面
- **WHEN** 用户按发送后、页面跳转前关闭了浏览器
- **THEN** worktree、会话和首条消息照常完成，用户稍后在首页的该仓库下能看到正在工作的会话

#### Scenario: 会话名称
- **WHEN** 快速开始创建会话
- **THEN** 会话不带显式名称，标题按现有规则跟随 agent 报告的标题

### Requirement: 首条消息合并仓库初始化指令

所选仓库设置了初始化指令时，首条提示 SHALL 是初始化指令、一个空行、用户输入，三者按此顺序拼接。输入框上方 SHALL 显示本次会附带初始化指令的提示，点击可查看全文。聊天记录中的第一条用户消息 SHALL 显示实际发送的完整文本。

#### Scenario: 附带初始化指令
- **WHEN** 仓库的初始化指令是“先读 AGENTS.md”，用户输入“修复首页排序”后发送
- **THEN** agent 收到的第一轮提示是“先读 AGENTS.md\n\n修复首页排序”，聊天中第一条用户消息显示同样的文字

#### Scenario: 仓库没有初始化指令
- **WHEN** 所选仓库没有初始化指令
- **THEN** 输入框上方不显示提示，首条提示就是用户输入

### Requirement: 重复提交不产生重复资源

每次快速开始请求 SHALL 带客户端生成的请求 ID。同一请求 ID 在服务进程生命周期内重复提交时，系统 SHALL 等待并返回第一次执行的结果，不得再创建 worktree、会话或提示。发送期间输入框和发送按钮禁用，并显示“正在创建 worktree 并启动 agent”的进行中状态。

#### Scenario: 网络重试
- **WHEN** 首次请求已在服务端执行，响应丢失，前端用同一请求 ID 重试
- **THEN** 服务端返回同一个会话，仓库中只有一个新 worktree

### Requirement: 失败时报告进度并保留输入

任一步骤失败时，系统 SHALL 停止后续步骤，页面保留在快速开始并保留输入文字，说明失败的步骤和原因。已完成步骤创建的资源 SHALL 保留且不自动删除：已创建的 worktree 在错误中可直接打开；会话已启动但首条提示发送失败时，提供进入该会话的入口，文字留在输入框中供手动发送。

#### Scenario: 创建 worktree 失败
- **WHEN** 基准分支已被删除，worktree 创建失败
- **THEN** 页面显示“创建 worktree 失败”和 Git 给出的原因，没有启动会话，输入文字保留

#### Scenario: agent 启动失败
- **WHEN** worktree 已创建，但 agent 的聊天端连接器缺失导致启动失败
- **THEN** 页面说明 agent 启动失败及原因，并显示已创建的 worktree 路径和“在此 worktree 新建会话”入口；worktree 不被删除

### Requirement: 快速开始沿用安全边界

快速开始接口 SHALL 使用现有认证和 Origin 校验。仓库、启动配置、基准分支和配置项都按标识或数据传递，不拼接成命令；请求 SHALL NOT 携带任意命令或环境变量，agent 只能来自已保存的启动配置。

#### Scenario: 未授权请求
- **WHEN** 未通过认证或 Origin 不被允许的客户端提交快速开始
- **THEN** 请求被拒绝，不创建 worktree、会话或提示

#### Scenario: 非聊天启动配置
- **WHEN** 请求的启动配置不支持聊天端
- **THEN** 请求被拒绝并说明原因，不创建 worktree
