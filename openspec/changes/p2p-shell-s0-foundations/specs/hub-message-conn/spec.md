# Spec Delta

## Purpose

在主机端实时流控制器层提供与具体网络协议解耦的面向消息连接契约（`MessageConn`），统一承载终端字节流、会话列表推送、混合聊天事件流、设置同步流与语音识别流，并为现有 HTTP WebSocket 升级入口提供等价适配。

## ADDED Requirements

### Requirement: 传输无关的面向消息流连接契约

主机端实时流控制器 SHALL 通过统一的面向消息连接抽象承载全部五类实时流（终端附着、会话列表、混合聊天、设置同步、语音识别）。该连接契约 SHALL 支持以下能力：

- 区分文本消息与二进制消息的整帧读写，并支持按字节数设置单帧读取上限；
- 受上下文截止时间约束的阻塞写入；
- 携带数值状态码与原因字符串的有序应用层关闭，以及立即中止底层传输的强制关闭；
- 在只写流上监听对端关闭或非法入站数据并取消关联上下文的半关闭读取。

#### Scenario: 只写推送流在对端关闭时及时释放订阅

- **WHEN** 会话列表、混合聊天或设置同步等服务端单向推送流运行在任意符合契约的消息连接上，且客户端主动关闭连接
- **THEN** 半关闭读取立即取消该流的上下文，控制器解除底层服务订阅并在退出前完成强制关闭清理，不遗留泄漏协程

#### Scenario: 超出单帧读取上限的入站消息被拒绝

- **WHEN** 客户端在终端流（上限 `1 MiB`）或语音流（上限 `64 KiB`）上发送超过读取上限的单帧负载
- **THEN** 读取操作返回错误并终止本次流连接，不会在服务端分配无界内存或影响持久化会话本身

### Requirement: 实时流并发不变量与应用层关闭码保真

在抽象消息连接之上，终端附着与各事件流控制器 SHALL 完整保持既有并发与保真契约：

- 回放捕获与实时订阅注册原子衔接不丢字节，每个连接仅由单一写协程串行写出；
- 终端输出按 `16 ms` 窗口或 `64 KiB` 阈值合并发送，启用压缩的回放使用 `zreplay` 帧；
- 单次写操作超过 `10 s` 或实时订阅队列满时，以状态码 `4408` 驱逐慢客户端而不阻塞 PTY 读取；
- 在会话不存在（`4404`）、混合会话移至另一侧（`4409`）、会话已退出（`4410`）、正常结束（`1000`）、服务忙（`1013`）及内部错误（`1011`）时传递一致的关闭码与原因。

#### Scenario: 慢客户端写超时驱逐不终止持久会话

- **WHEN** 某连接上的写入持续阻塞达到 `10 s` 写截止时间或其实时输出队列溢出
- **THEN** 控制器以关闭码 `4408` 断开该慢连接并等待其派生读协程退出，同会话上的其他健康连接与底层 PTY 进程继续正常运行

#### Scenario: 混合会话切换界面时传递 4409 关闭原因

- **WHEN** 终端流或聊天流因混合会话切换到另一交互侧而被服务端取代
- **THEN** 控制器向该消息连接发送关闭码 `4409` 及对应 `session moved: chat` 或 `session moved: terminal` 原因后干净退出

### Requirement: WebSocket 适配器零协议变更与架构分层合规

HTTP 路由层在完成鉴权、Origin 校验、可选 `permessage-deflate` 压缩协商及 WebSocket 握手升级后，SHALL 将底层 WebSocket 连接包装为该抽象消息连接移交实时流控制器处理。

帧编码、子协议选择（`webmux`）与关闭握手在网络线上 SHALL 与既有 WebSocket 协议字节级兼容；该抽象及适配器 SHALL 位于控制器层边界之内，不得向服务层或共享契约层引入任何 WebSocket 或 WebRTC 库依赖。

#### Scenario: 现有浏览器与 CLI WebSocket 客户端无感接入

- **WHEN** 浏览器前端或 `webmux attach` 客户端通过 `/ws/sessions`、`/ws/s/{id}`、`/ws/s/{id}/chat`、`/ws/settings` 或 `/ws/voice` 发起标准 WebSocket 连接
- **THEN** 握手子协议、压缩扩展、首帧快照/回放、增量消息及关闭码与改造前完全一致，所有架构分层守卫检查通过
