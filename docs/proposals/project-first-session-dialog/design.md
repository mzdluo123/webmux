## Context

动机和范围见 [proposal](proposal.md)。现有 `NewSessionDialog.svelte` 同时承载位置、工作树创建、运行方式和首条消息；`LocationPicker` 列举各仓库工作树而非项目。
`AddRepositoryDialog` 只登记现有 Git 仓库，普通文件夹通过 `cwd` 启动；没有克隆及 GitHub 仓库发现接口。不能仅改标题就声称四种来源已经可用。

参考 T3 Code 的 [项目来源列表](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/CommandPalette.tsx) 和 [项目结果行](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/CommandPaletteProjectItems.tsx)。
已查看官方截图与源码，未实机操作 T3；下列布局是 WebMux 的设计，不是 T3 截图复刻。

## Goals / Non-Goals

**Goals:** 用项目作为会话所属对象；在一个弹窗内完成选择、添加和启动；普通目录与 Git 项目使用相同列表；保留现有失败恢复和上下文默认值。

**Non-Goals:** 本次不重做侧栏、不合并 QuickStart 页面、不引入多机器选择、不做 GitHub OAuth 管理、不自动发布远程仓库、不改变 PTY 生命周期。

## Decisions

### 1. 使用同一个可返回的弹窗

采用现有 `ResponsiveDialog` + `Command`，桌面最大宽度约 640px，手机抽屉固定标题、正文内部滚动。标题行只有返回、当前标题和关闭。
不增加嵌套来源弹窗，也不使用大卡片或多层 Tab；列表适合搜索与键盘，且窄屏空间更稳定。
页面状态为「选择项目」「添加来源」「来源详情」「会话设置」；来源详情的目录浏览复用现有选择器。
全局新建先选项目；项目/工作树/分屏的明确上下文直接进入会话设置，普通会话允许通过项目行返回改选，受限入口保留其范围。

### 2. 第一层：选择项目

```text
新建会话                                  ×
选择一个项目，开始新的会话。

⌕ 搜索项目名称或路径…

项目
▱ WebMux                                  ›
  ~/code/webmux
▱ PixAI                                   ›
  ~/code/pixai
▱ 临时脚本                                ›
  ~/scripts
───────────────────────────────────────────
＋ 添加项目                               ›
```

项目图标使用 Tabler；名称 14px，路径 12px、使用 muted 文本，长路径截断并保留 title。不可用行显示具体原因且禁用。
当前上下文项目优先，其余按名称稳定排序；搜索同时匹配名称与路径。已有仓库、已登记普通目录出现在同一组。
最近目录作为独立「最近文件夹」组呈现，规范路径去重，已在项目组的目录不重复出现；选中后进入本地文件夹确认页，明确登记为项目。
没有项目时直接显示来源列表，不用空白页要求再点一次添加。搜索无结果时保留「添加项目」，不自动执行搜索文本。
此层没有绿色确认按钮，选择整行就是进入下一步，避免先选中再点继续。

### 3. 第二层：添加项目

```text
‹ 添加项目                                ×

＋ 新建项目                               ›
  创建一个新的项目目录
▱ 本地文件夹                              ›
  打开 WebMux 服务所在电脑的文件夹
↗ Git URL                                 ›
  从远程 Git 地址克隆
⑂ GitHub 仓库                             ›
  搜索并克隆你有权访问的仓库
```

上图字符只是线框示意，正式图标使用本地打包的 Tabler 图标。四行同高，名称与描述纵向对齐，行尾箭头表示进入子层。
本地文件夹指服务端目录，不是浏览器设备文件上传；原始“本地文件”诉求按文件夹实现，因为会话必须有工作目录。
GitHub 不可用时行内显示「需要配置」，进入详情解释服务端 `gh` 状态，不假装仓库列表为空。

### 4. 第三层：来源详情

| 来源 | 默认展示 | 主操作 | 成功后的去向 |
| --- | --- | --- | --- |
| 新建项目 | 名称、父目录、最终路径预览 | 创建项目 | 会话设置 |
| 本地文件夹 | 路径输入与浏览按钮 | 使用此文件夹 | 会话设置 |
| Git URL | 远程地址、目标目录 | 克隆项目 | 会话设置 |
| GitHub 仓库 | 搜索框、仓库列表；选中后展示目标目录 | 克隆项目 | 会话设置 |

新建项目默认创建普通目录，提供默认关闭的「初始化 Git 仓库」选项；只有勾选才执行 init，不生成初始提交，不要求 Git 用户身份。
名称预填为目录名；克隆目录从远程仓库名建议，用户可修改。GitHub 列表展示 owner/name、描述、私有状态，支持分页与搜索。
来源页只有右下角主操作为绿色，返回使用 ghost；取消统一在标题关闭入口。认证失败、路径冲突和目录权限错误在对应字段附近展示。
未提交返回保留该来源草稿；再次进入恢复输入。成功添加后登记项目，随后关闭弹窗也不删除项目和文件。

### 5. 会话设置层

```text
‹ 新建会话                                ×

项目
▱ WebMux                    ~/code/webmux  ›

工作位置
[ 项目目录 · main                       ⌄ ]

运行
[ Claude Code                           ⌄ ]
[ 从聊天开始      从终端开始 ]

首条消息（可选）
[ 描述这次要做什么…                        ]

› 高级：会话名称
───────────────────────────────────────────
在 WebMux / main 启动 Claude Code
                           [ 开始会话 → ]
```

「项目」行作用于项目选择；「工作位置」只展示该项目的目录、已有工作树和「新建工作树…」。非 Git 项目隐藏工作位置选择，使用项目目录。
工作树创建字段仅在选中该项时原位展开，继续使用现有高级折叠与冲突恢复机制；此处不再放添加其他项目的入口。
启动配置、自定义命令、起始端、初始化指令、首条消息和会话名称复用现有组件及记忆规则。只有支持混合模式的配置显示起始端。
项目内默认使用主工作区，明确的工作树入口继承该树，分屏继承源会话目录与工作区关联；不默认强制新建工作树。
更换项目保留首条消息、名称与启动方式，清除旧项目的工作树选择、分支字段和初始化指令勾选，并重新计算目标项目的默认值。
「新建工作树」专用入口仍直接进入现有工作树配置，保留“创建后启动会话”选项，不强制经过项目列表。

### 6. 视觉与无障碍

使用现有语义令牌、rounded-xl 弹窗和默认 Command 行，中性色背景、细分隔线；不自定义绿色或增加渐变。
列表行整行可点、有 hover 与 focus；选中状态沿用描边/指示，不使用大面积绿色填充。提交按钮是当前层唯一绿色操作。
键盘上下选择、Enter 进入，Esc 先关目录浮层，再退一层，根层才关闭弹窗；每次返回恢复搜索和焦点，前进聚焦新层首个字段。
输入文本框内 Enter 不误触来源行；多行首条消息 Enter 换行，点击主操作启动。进行中的创建或克隆禁用重复提交与关闭，并播报当前状态。
320px 宽度不出现页面横向滚动；长 URL/路径保留完整可访问值，错误文字允许换行。浅色、深色使用相同层级。

### 7. 项目模型与服务边界

新增持久项目记录：稳定 ID、显示名称、规范目录、可选 repositoryId；来源仅作说明，不保存带凭据的远程 URL。
现有仓库通过稳定关联映射为项目，不复制 Git 状态；worktree 属于仓库，不因选入项目而复制登记。非 Git 项目同样持久保存。
新增项目服务在 `cmd` 构造，复用 workspace 归一化与 files 目录逻辑；api 负责认证、Origin 与错误映射，wire 负责契约转换。
现有 `POST /repositories` 保持只登记语义，创建与克隆使用显式项目操作。已有会话继续按 `cwd` 或 `workspace` 启动，无需持久化 PTY。
目录与 Git 操作使用 argv，拒绝作为选项的 URL、控制字符和不支持的 URL 协议；不经 shell。含凭据 URL 明确拒绝，提示使用服务端 Git 凭据配置。
GitHub 发现复用服务端已登录 `gh`，调用有超时、分页和请求取消；不把 token 传到浏览器、不自动登录。读取私有仓库仅在已授权凭据范围内进行。
克隆在同父目录的独占临时目录进行，成功后无覆盖发布；失败仅清理本操作创建的目录。请求重复提交通过操作标识返回已有结果，避免重复克隆。
长操作采用项目操作 ID 和可查询状态；前端断连后重连继续查询，不自动重启。克隆完成但登记失败时保留目录并提供重新登记，不能覆盖或删除已有文件。

## Risks / Trade-offs

- [新增项目概念与仓库清单重复] → 项目只持有目录和仓库关联，Git 状态由 workspace 唯一维护；迁移去重使用规范路径。
- [克隆可能耗时且无交互凭据] → 使用非交互模式、明确超时及状态查询，失败提示配置服务端凭据后重试。
- [分层比旧默认表单多一步] → 明确上下文入口跳过选择层，全局入口优先清晰归属。
- [GitHub 功能依赖 gh] → 只对 GitHub 来源局部降级，本地和 Git URL 仍可用。

## Migration Plan

1. 先实现可恢复、幂等的项目服务与契约，再接入完整四种来源；不交付无功能的占位入口。
2. 读取旧仓库清单生成项目关联，保留仓库 ID 和原持久文件；普通最近目录不擅自批量登记。
3. 替换新建会话弹窗入口，迁移键盘、触屏、默认值和失败恢复测试；不改变 QuickStart 的路由与语义。
4. 新增状态文件保持独立，回滚旧版本忽略新文件；已有仓库文件格式保持兼容，磁盘项目及克隆目录保留。
5. 发布前生成桌面、平板、手机的前后截图和交互 GIF，并完成文档及用户故事核对。
