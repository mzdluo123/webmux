# 页面清单与首页区块

本页列出官网的全部页面、每个页面的任务与主 CTA，并逐区块规定首页与下载页的内容来源。页面不多，但每页只做一件事；需要新页面时先回到 [定位](strategy.md#目标用户) 确认它承接哪类用户。

## 全站框架

- **页头**：左侧 Logo（深浅色两版），右侧导航“功能 · 使用场景 · 对比 · 文档 · 常见问题 · GitHub”（安装由右侧 CTA 按钮承接），GitHub 项显示 star 数；语言切换与主题切换放在最右；小于 640px 折叠为菜单。
- **页脚**：四列——产品（下载、更新日志、对比、安全）、文档（文档中心、使用指南、部署指南、协议，均指向官网 `/docs/`）、社区（GitHub、Issues、安全漏洞报告、参与贡献）、法律（MIT 许可、字体与图标许可、隐私说明）。底部一行写明“WebMux 是开源项目，与 Anthropic、OpenAI 等 agent 厂商无隶属关系”。
- **版本条**：页头或 Hero 下方显示最新版本号、发布日期与平台徽标，数据来自构建期 Release 信息。

## 首页区块

每个区块给出内容来源、CTA 与验收标准。截图一律使用 `docs/images/` 下的真实界面，不做假数据的概念图。

### 1. Hero

- 内容：H1 主标题、一句副标题、主 CTA（带图标复制按钮的命令框）、一行版本与平台元信息、主图 `hero.jpg` 全宽置于文字下方（替代文本沿用 README：同一个 omp 会话，电脑浏览器里是原生 TUI，手机上切到聊天视图继续对话）；次 CTA“安装 WebMux”与 GitHub 链接放在页头。
- 来源：主副标题按 [消息层级](strategy.md#价值主张与消息层级) 撰写。
- 验收：无 JavaScript 时命令仍可见；主图带宽高属性且优先加载；移动端首屏能看到标题、命令与主图上半部分。

### 2. 三步叙事

- 内容：三段左右交替的图文“电脑上开工 → 手机上接管 → 回到电脑审阅”，配图 `desktop-overview.png`、`mobile-omp.png` + `mobile-chat.png`、`desktop-diff.png`；每段一个等宽小标、一个场景式标题、一段正文（版式见 [叙事行与卖点](design.md#叙事行与卖点)）。
- 来源：README 开头的场景叙述与“三步看懂”表格。
- 验收：小屏堆叠为“小标 → 标题 → 正文 → 截图”并保留序号；每张图有替代文本。

### 3. 六个卖点

- 内容：左侧标题与一句总述，右侧两列定义列表，标题 + 一句收益；标题与副句沿用 README“为什么会爱上它”。
- 验收：使用 `<dl>` 语义；不加图标与卡片边框，不做悬停放大等装饰动画。

### 4. 界面一览

- 内容：画廊——混合会话、终端、手机终端与软键栏、聊天视图、Diff 审阅；深浅色用 `<picture>` 跟随系统；可展开“更多截图”（分屏与草稿、终端图形、资源管理器、启动配置）。

### 5. 混合会话

## 下载页

- 顶部：当前版本、发布日期、`SHA256SUMS` 链接、更新日志链接。
- 分区按操作系统标签页：Linux / macOS（脚本、手动下载；Release 含资产时增加 deb / rpm）、Windows（Release 含资产时提供安装程序，另有托盘、控制台客户端，说明依赖 WSL 2）、从源码构建（链接到 CONTRIBUTING）。`v0.10.1` 没有安装程序与 deb / rpm，不显示这些空入口；后续版本按实际资产显示。
- 每个资产一行：名称、架构、大小、SHA-256、下载按钮；资产列表由构建期数据生成，没有任何匹配资产的分组不渲染。
- 升级提示：升级需重启服务，重启会结束所有终端会话，先让 agent 告一段落。
- 国内镜像：脚本的 `ghfast.top` 入口与 `WEBMUX_MIRRORS` 说明，标注镜像是第三方服务且能看到请求者 IP。
- 来源：[安装与升级](../deployment/install-and-upgrade.md)、[Windows（WSL）部署](../deployment/windows-wsl.md)。

## 文档中心

- `/docs/` 首页镜像主仓库 [文档中心](../README.md)：六个分组、每篇一句用途说明，顶部放搜索框与“基于 vX.Y.Z”标注。
- 每篇文档一个 URL，布局为 Starlight 文档布局：左侧分组侧栏、右侧本页目录、底部上一篇 / 下一篇与“在 GitHub 上查看 · 编辑”。
- 同步范围、改写规则与排除列表见 [文档镜像](stack.md#文档镜像)；官网不手工编辑镜像内容。
- 营销页上每个功能描述都链接到对应文档页；文档页页脚链接回下载页与首页。

## 其他页面要点

- **安全页**：安全模型、三种推荐拓扑（仅本机、Tailscale / WireGuard、Cloudflare Named Tunnel 或 Tailscale Funnel）、每种拓扑的 Token 要求与风险、漏洞报告入口。来源：[安全策略](../../SECURITY.md)、[远程访问](../deployment/remote-access.md)。
- **对比页**：规则见 [对比规则](strategy.md#差异化与对比规则)；页底写明核对日期。
- **更新日志**：每个 Release 一节，渲染发布说明 Markdown，标题为版本号与日期；提供 `/changelog.xml` Atom 订阅。
- **Windows 页**：前置条件（Windows 10 22H2+、Store 版 WSL 2）、安装程序与托盘能做什么、控制台客户端 `run` / `attach`、常见故障入口。来源：[Windows（WSL）部署](../deployment/windows-wsl.md)。
- **agent 子页**：每页回答“如何用 WebMux 远程跑 X”：安装 X、预置配置、是否支持混合会话与提醒、已知限制；来源：[CLI agent 接入](../cli-agents.md)、[混合会话](../hybrid-sessions.md)。

## 文案规则

- 用户视角：句子以用户能做的事开头（“在手机上接着回答 agent 的问题”），而不是系统视角（“系统支持移动端”）。
- 每个区块一个主 CTA；按钮文字说明结果（“复制安装命令”“查看全部对比”），不用“提交”“点击这里”。
- 数字必须有来源，并由构建或内容集合提供；中文文案使用全角标点，中英文与数字之间留空格。
- 英文版标题重写而非直译；专有名词（Claude Code、Codex CLI、OpenCode、omp、Tailscale、Cloudflare Tunnel）两种语言写法一致。
- 不出现“简单”“轻松”“只需”等贬低用户难度判断的词；用具体动作代替。
- 产品边界与安全提示在两种语言中都完整保留，不因篇幅删减。
