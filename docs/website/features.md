# 站点功能清单

“有用的功能”指访客在官网上能直接完成的事，而不是装饰。功能按优先级分三档：P0 上线必备，P1 上线后一个月内，P2 视反馈决定。所有功能都遵循 [渐进增强](ux.md#渐进增强)，不依赖服务端，不收集个人数据。

## P0：上线必备

### 1. 安装命令生成器

- 作用：按访客操作系统预选当前 Release 可用的标签页（Linux / macOS、Windows（WSL）、deb / rpm、手动下载），展示可复制的命令；没有匹配资产的标签页不渲染。
- 数据：README“快速开始”与 [安装与升级](../deployment/install-and-upgrade.md) 的命令；版本号来自构建期数据。
- 选项：“国内镜像”开关把 GitHub 直链换成 `ghfast.top` 前缀，并显示“镜像是第三方服务，能看到请求者 IP”的说明；“固定版本”把管道右侧改为 `WEBMUX_VERSION=x.y.z sh`，完整形式为 `curl … | WEBMUX_VERSION=x.y.z sh`，确保变量作用于安装脚本而非 `curl`。
- 验收：无脚本时显示 Linux / macOS 默认命令；复制有“已复制”反馈与 `aria-live` 播报；命令文本与 README 一字不差。

### 2. 下载表

- 作用：列出最新 Release 的全部资产：名称、平台、架构、大小、SHA-256、下载链接；顶部给出 `SHA256SUMS` 与校验命令。
- 数据：构建期 Releases API（见 [构建期数据](stack.md#构建期数据)），失败时用提交的回退副本并显示“可能不是最新版本”。
- 验收：只为 Release 中实际存在的资产建立分组（服务端、Windows 托盘、控制台客户端、安装程序、deb / rpm、脚本）；`v0.10.1` 不显示安装程序与 deb / rpm 空分组；未知资产进入“其他”；每行有可复制的 SHA-256。

### 3. 版本徽标与更新日志

- 作用：页头显示最新版本与日期；`/changelog/` 按版本渲染发布说明，提供 Atom 订阅 `/changelog.xml`。
- 数据：Releases API 的 `body` Markdown；安全处理 HTML（只允许 Markdown 产生的标签）。
- 验收：每个版本有独立 URL；订阅源能被 RSS 阅读器解析；预发布版本标注。

### 4. FAQ

- 作用：解答安装、安全、平台、许可问题；首页展示六条，`/faq/` 展示全部并输出 `FAQPage` 结构化数据。
- 数据：[常见问题](../faq.md) 为基础，补充“收费吗”“数据去哪了”“能多用户吗”等官网特有问题，答案与产品边界一致（单用户、无遥测、会话只在内存）。
- 验收：问题可通过 URL 锚点直达；展开状态可用键盘操作。

### 5. 安全与部署建议页

- 作用：用三种拓扑图说明仅本机、可信 VPN、受控隧道各自的风险与 Token 要求；给出漏洞报告入口。
- 数据：[安全策略](../../SECURITY.md)、[远程访问](../deployment/remote-access.md)。
- 验收：每种拓扑有一句“适合谁”和一句“不要这样做”；公网拓扑注明“Token 是唯一屏障”。

### 6. 对比表

- 作用：事实维度对比，详见 [对比规则](strategy.md#差异化与对比规则)。
- 验收：每格为“是 / 否 / 部分 / 未核实”加一句说明；页底有核对日期与各方文档链接。

### 7. 主题与语言切换

- 作用：深浅色跟随系统并可手动覆盖；中英文切换到对应页面，保留当前路径。
- 验收：切换无闪烁；语言切换是普通链接；`hreflang` 与切换目标一致。

### 8. 短链接重定向

- 作用：`/install.sh`、`/releases`、`/github`、`/docs/*` 的重定向规则，见 [技术方案](stack.md#托管与部署)。
- 验收：`curl -fsSL https://<域名>/install.sh | sh -n` 能取到脚本；重定向目标始终是 GitHub。

### 9. `llms.txt`

- 作用：供大模型与 agent 读取的纯文本产品说明，含安装命令、文档入口与安全边界；文档镜像就绪后同时提供 `/llms-full.txt`。
- 验收：与首页事实一致；每次 Release 自动更新版本号。

### 10. 文档镜像与站内搜索

- 作用：用 Starlight 镜像主仓库 `docs/`，Pagefind 提供全文搜索；每页“在 GitHub 上查看 · 编辑”与版本标注。这是第一阶段的内容主体与 SEO 权重来源。
- 依赖：[文档镜像](stack.md#文档镜像) 中的范围、改写规则与排除列表。
- 验收：`make docs-check` 认可的所有相对链接与锚点在官网上都能解析，未映射者使构建失败；搜索结果包含中文分词；每页 `canonical` 指向官网。

## P1：上线后一个月内

### 11. agent 兼容矩阵与子页

- 作用：十一款 CLI × 终端支持 / 混合会话 / 提醒来源 / 额外依赖（如 ACP 连接器）的矩阵；每款一个子页。
- 数据：[CLI agent 接入](../cli-agents.md)、[混合会话](../hybrid-sessions.md)、[需要你介入的提醒](../usage/attention.md)。
- 验收：矩阵内容与仓库文档同步；子页注明核对日期与已验证版本。

### 12. 演示回放

- 作用：首页“看演示”播放一段录制的真实会话（手机接管 omp 回答问题），静音、可暂停、可跳过。
- 实现：录制 asciinema cast 并用 asciinema-player 回放，或导出 WebM；不调用真实模型。
- 验收：尊重减少动效设置；回放内容不含真实路径或密钥。

### 13. 快捷键速查

- 作用：`Ctrl+B` 前缀分屏操作、`Ctrl+]` 分离、软键栏按键一览，可打印。
- 数据：[终端使用](../usage/terminal.md)、[从终端启动与附着](../usage.md#从终端启动与附着)。

## P2：视反馈决定

### 14. 配置生成器

- 作用：表单生成 `config.toml`：监听地址、Token、Tailscale 模式、隧道、推送、允许的 Origin；每个字段附安全提示。
- 数据：[配置](../deployment/configuration.md)、`deploy/config.example.toml`。
- 约束：纯客户端，不保存、不上传；生成的 Token 用 `crypto.getRandomValues` 且不少于 43 字符。

### 15. Token 生成器

- 作用：隧道与 Serve / Funnel 要求至少 43 字符 Token，提供一键生成（等价于 `openssl rand -base64 32`）。
- 约束：浏览器本地生成，页面不发出任何请求；说明“请复制到配置文件后关闭页面”。

### 16. 站内搜索（营销页）

- 作用：把 FAQ、更新日志与对比也纳入 Pagefind 索引，与文档搜索共用一个入口。

### 17. 用户案例与社区展示

- 作用：展示真实用户的使用方式或博客文章；只收录获得许可的内容，附来源链接。

## 明确不做

- 在线试用 shell 或任何执行命令的演示：违背安全模型。
- 产品遥测或官网账号：产品不收集数据，官网也不引入。
- 邮件订阅弹窗、Cookie 横幅、聊天机器人浮窗：干扰首屏任务。
- 第三方字体、图标或脚本 CDN：与产品“本地打包”原则一致，也避免大陆访问失败。
