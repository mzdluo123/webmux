# 连接、启动与会话总览

## A. 连接、认证与访问边界

- **US-A01 连接服务**：作为使用者，我希望在浏览器中连接自己的 WebMux，以便在不安装终端客户端的情况下操作服务器。
  验收要点：
  - 登录页、工作区、设置页与浏览器标签页使用统一的 WebMux 标志，明暗主题下均可辨认；
  - 打开页面后检查服务可用性；
  - 显示连接中、连接失败或可用状态；
  - 未设置 token 的服务可直接进入；
  - 设置页按需加载，显示加载状态，下载失败时提示刷新重试。
- **US-A02 共享 token 登录**：作为使用者，我希望输入并在本机记住共享 token，以便以后方便地访问自己的会话。
  验收要点：
  - 登录页在共享 Token 右侧提供问号提示，默认收起说明；
  - 鼠标悬停、键盘激活或手机点击可查看，指针可移入说明，Escape 或点击外部可关闭；
  - 说明涵盖共享密码用途、初始化生成与保存、配置路径及启动参数覆盖；
  - 配置路径独立成行、窄屏可换行且无横向溢出；
  - 启用认证后，正确 token 才能访问 HTTP API 与 WebSocket；HTTP 只接受 `Authorization: Bearer`，WebSocket 只接受 Bearer 或 token 子协议，`webmux_token` Cookie 与 URL 参数都不能认证；
  - 端口转发凭据 Cookie `webmux_forward` 独立于 token，只能访问 `/forward/` 网关，不能认证 `/api/` 与 `/ws/`，见 US-R01；
  - 当前浏览器保存 token；
  - 错误或变更后的 token 触发重新认证提示；
  - 本机套接字采用同用户身份校验，见 US-M08。
- **US-A03 可信网络访问**：作为部署者，我希望控制监听地址和允许的浏览器来源，以便只从预期的本机或可信 VPN 入口操作终端。
  验收要点：
  - 默认仅监听本机回环（127.0.0.1:7681），局域网或可信 VPN 访问可改为 0.0.0.0:7681；
  - 未显式指定配置且默认文件缺失时，首次启动生成并保存 256 位随机 token，非隧道启动不打印该 token，可经本机状态显式查询；
  - 已有配置的 token 为空且监听地址不是 loopback 时，每次启动生成临时随机 token 并打印带 `#token=` 的本地链接；
  - 只有 loopback 且未启用隧道时允许无 token；
  - 隧道启动仍输出含 token 的链接，持久 token 不因重启失效；
  - 监听 loopback 时校验请求 Host（防止无 token 下的 DNS 重绑定），非 loopback 监听（强制要求 token）接受任意合法 Host（如局域网主机名或 Tailscale MagicDNS），并始终校验 Origin（同源、allowed_origins 或受控公网来源）；
  - 认证和来源检查同时覆盖终端与文件、仓库、代码接口。
- **US-A04 查看服务与能力**：作为部署者，我希望知道服务是否在线、会话数量及 Git/仓库能力是否可用，以便定位连接或环境问题。
  验收要点：
  - 健康检查返回可用状态和会话数；
  - 配置接口提供默认目录、主机名和工作区能力，不返回 token；
  - 首页展示连接与能力异常。
  - 侧栏底部的主机状态入口可点击查看主机名、连接状态、健康检查往返延时、系统负载（1/5/15 分钟与核心数）和可用/总内存；
  - 往返延时高于 200 毫秒，或 1 分钟负载高于核心数的 50% 时，状态灯变黄并在提示中说明原因；平台无法提供负载或内存时对应行不显示。
- **US-A05 脚本访问**：作为进阶使用者，我希望通过 REST 和 WebSocket 操作会话，以便接入自己的脚本或客户端。
  验收要点：
  - 提供会话、配置、目录、上传、仓库与代码（含文件操作）接口；
  - 列表和终端分别提供实时流；
  - 遵循相同认证、错误和生命周期边界，详见 [协议](../protocol.md)。
- **US-A06 带凭据链接登录**：作为使用者，我希望打开带 token 片段的访问链接就能登录，以便从终端或托盘把入口带到手机。
  验收要点：
  - 前端读取并保存 `#token=` 后立即移除地址栏和当前历史记录中的片段；
  - 片段不发送到服务器；
  - WebSocket 认证通过子协议携带 token，不放入请求 URL 或 Cookie；
  - 链接仍是敏感入口。

## B. 创建会话与选择启动位置

- **US-B01 启动 Shell 或 agent**：作为使用者，我希望通过自定义启动配置或显式命令运行 Shell、Open Code、Claude Code、Codex、omp 等程序，以便快速开始终端工作或遥控 agent。
  验收要点：
  - 新建会话对话框以“位置”与“运行”两个选择行组成一页，“运行”在同一列表中提供保存的启动配置与末尾的“自定义命令…”；新安装预置常见 agent 的启动配置，没有不可修改的内置预设；
  - Claude Code、Codex CLI、Antigravity CLI、Open Code、Qoder、QoderCN、Kimi 与 omp 的预置配置默认自动批准工具调用：
    - Claude Code `--dangerously-skip-permissions`；
    - Codex CLI `--dangerously-bypass-approvals-and-sandbox`；
    - Antigravity CLI `--dangerously-skip-permissions`；
    - Open Code `--auto`；
    - Qoder `--dangerously-skip-permissions`；
    - QoderCN `--dangerously-skip-permissions`；
    - Kimi `--auto`；
    - omp `--auto-approve`；
  - Cursor、Copilot、Qwen、CodeBuddy 使用各自默认授权行为；
  - 十一款 CLI 的启动命令见 [接入说明](../cli-agents.md)；
  - Claude Code、Codex CLI、Antigravity CLI、Open Code、omp、Qoder、QoderCN 与 Kimi 预置配置默认为混合模式（US-Q01）；
  - 命令选择器可用键盘操作（Enter 打开、方向键与搜索、Esc 只关闭选择器），选中行和每个选项同时显示图标、名称与命令，长命令保留完整提示；
  - 保存的配置按 ID 启动，临时命令按完整 argv 启动，均创建真实 PTY；
  - Open Code 可通过“加载 shell 启动文件”保存为 Bash（`~/.bashrc`）或 Zsh（`~/.zshrc`）包装，新安装按服务端 `$SHELL` 预选，其他 shell 回退为不包装或手动选择，不自动安装程序；
  - 勾选了混合模式的配置可选择从终端或聊天开始（US-Q02）；
  - 首页与工作树统一使用“新建会话”，分屏菜单复用同一对话框；
  - 无论哪种启动方式，对话框都有可选的“用户指令”，创建后自动发送：
    - 聊天端作为第一条消息；终端端若所选混合模式 agent 已支持命令行初始提示参数（且启动命令本身未带初始提示），通过首次 TUI 启动参数直接传入（不写入 `SessionInfo.Cmd` 或持久化记录），尚未迁移的 agent、不支持该消息形式的边界情况与自定义命令仍在程序输出安静后输入并自动回车；
    - 未填会话名称的终端启动以该指令为会话名（US-B07）；
    - 位置属于已登记仓库且该仓库设置了初始化指令时，另有默认勾选的“使用初始化指令”，指令先于用户指令发送（模板规则见 US-J12）；
    - 引用无效、临时文件夹不可用等发送前即可发现的问题使创建失败并保留输入，不留下半启动的会话；
  - 底部汇总“将在 X 运行 Y”，默认值齐全时打开即可直接创建；会话名称收在“高级：会话名称”中；
  - 创建成功后按入口进入终端或加入当前布局。
- **US-B02 自定义命令与参数**：作为进阶使用者，我希望填写完整命令及参数，或选用已保存的配置，以便运行自己的 CLI 工作流。
  验收要点：
  - 在启动配置与“自定义命令…”之间切换时保留手动输入和已选配置，但只提交当前方式；
  - 空手动命令不能误用保存配置；
  - 正确保留引号、空参数与参数边界，不进行 shell 展开；
  - 未闭合引号或空可执行程序阻止提交；
  - `configId` 与非空 `cmd`、`env` 互斥；
  - 临时命令不落盘，保存配置不可用或仍在加载时可改选“自定义命令…”。
- **US-B03 选择直接目录**：作为使用者，我希望直接指定任意可访问目录并复用最近使用的位置，以便启动普通项目而不必先登记 Git 仓库。
  验收要点：
  - “位置”选择器在一处列出主页当前仓库的工作树、最近目录、其他仓库的工作树与“输入或浏览目录…”，选中直接目录时显示可编辑的工作目录输入与浏览按钮；
  - 从首页的“新建会话”打开时范围收窄：选中仓库只列该仓库的工作树与“新建工作树…”；选中工作树（或点工作树行的“新建会话”）只列该工作树与“从当前工作树分支新建…”，起始分支默认为该工作树的分支；选中“全部仓库”、“直接会话”或从分屏、会话页打开时不收窄；
  - 默认位置优先级：上下文入口（工作树的“新建会话”、分屏源会话目录）> 主页选中仓库的可用主工作区（否则该仓库其他可用工作树）> 最近目录 > 服务默认目录；
  - 主页选中仓库但没有可用工作区时保留仓库并要求选择，不回退到其他项目；对话框内改选位置不改变主页选中的仓库；
  - 保留最近 10 个启动目录，并在成功创建后记住最近一次启动方案（启动配置及混合起始端，或临时命令），下次打开直接填入，对所有位置通用；
  - 记住的配置已删除或不可用时显示“选择启动方式”并禁止提交，不隐式启动另一配置；创建失败不覆盖记忆；
  - 分屏以源会话的完整启动目录覆盖最近目录，目录未改时保留其工作区归属。
- **US-B04 浏览目录**：作为使用者，我希望逐层浏览和补全服务器目录，以便在手机上也能准确选中启动位置。
  验收要点：
  - 支持路径筛选、主目录、上一级、显示隐藏目录；
  - 支持方向键、Enter/Tab 进入和 Alt+↑ 返回；
  - 显示读取错误并能选择当前目录。
- **US-B05 创建缺失目录**：作为使用者，我希望在目录不存在时确认创建再启动，以便直接为新任务准备工作位置。
  验收要点：
  - 直接目录启动失败且目录不存在时才提示创建；
  - 确认后创建目录并重试；
  - 不因此登记仓库。
- **US-B06 在已有或新工作树启动**：作为使用者，我希望从已有 worktree 启动，或先创建 worktree 再启动 agent，以便在指定的代码副本中工作。
  验收要点：
  - 在“位置”选择器中直接选择已有工作树（显示分支与路径），或在对应仓库分组中选择“新建工作树…”；
  - 不可用仓库、不可用或 bare 工作树显示但禁用；
  - 新工作树在位置行下方展开：“创建新分支 / 使用已有分支”、起始分支与新分支名称，起始提交与存放目录收在“高级：起始提交与存放目录”，位置行摘要显示“新分支 ← 起始分支”；改选其他位置再选回同一仓库的“新建工作树…”时保留已填写内容；
  - 新工作树成功后可启动会话或仅保留工作树；
  - agent 启动失败时保留新工作树与分支，位置自动变为该工作树，重试不重复创建；改选其他位置后仍可在列表中选回它；
  - 侧栏仓库菜单的“新建工作树…”默认只创建工作树，勾选“创建后启动会话”才显示命令并启动；未勾选时改选已有工作树或目录会禁用“创建工作树”并提示，不会无操作地关闭；
  - 启动配置不可用不阻止单独创建工作树。
- **US-B07 命名会话**：作为使用者，我希望给新会话填写名称，以便在多个相似终端中识别任务。
  验收要点：
  - 创建名称优先于首条提示标题与程序标题（终端 OSC 0/2、聊天端 ACP `session_info_update`）；
  - 未命名且从终端视图启动、填写了用户指令时，以该指令为名（折叠空白，最多 80 个字符，超出加“…”；不含初始化指令，去掉 `{{dir}}`、`{{webmux}}` 引用，普通 Shell 命令同样适用），之后程序标题不再覆盖；名称输入框的占位提示“留空则用首条提示，没有则跟随终端标题”；
  - 没有用户指令（含只有初始化指令）时使用程序标题，再回退到目录名；聊天端从首条消息取临时标题，见 US-Q02；
  - 首页、终端、聊天页头与浏览器标签使用会话标题。
- **US-B08 管理启动配置**：作为使用者，我希望把常用的命令、参数和环境变量保存为服务端启动配置，以便在任何设备上一键选用而不必重复输入。
  验收要点：
  - 设置页的启动配置以不带边框的行列表呈现（行高不低于 44px）：图标、名称、一行摘要（终端或混合会话、环境变量数、预览行数；完整命令只在编辑对话框中显示），整行点击编辑，行尾“⋯”菜单提供编辑与删除；
  - 设置页可新建、编辑、删除自定义启动配置，并选择自动匹配、通用终端或 LobeHub 品牌图标；配置最多 100 条且文件总大小不超过 4 MiB，超出时保存被拒绝并提示精简（400），其余配置与功能不受影响；
  - 图标随配置持久保存并在设置列表、新建会话选择器中显示，缺少图标的旧配置按可识别的直接命令或标准 Bash/Zsh 包装自动匹配，不改写原配置；
  - “加载 shell 启动文件”复选框将普通命令安全包裹为所选 Bash 或 Zsh 的交互式 argv，保留空参数、空格和字面量 shell 字符；
  - 重新编辑还原普通命令并保持勾选与所选 shell，保存不重复包裹，取消勾选恢复直接执行；
  - 新建时按服务端只读 `defaultShell` 预选，空值回退 Bash；
  - 包装参数计入 argv 上限；
  - 可为每条配置选择跟随全局默认或单独设置输出预览行数与跳过末尾行数；
  - 新安装首次启动时自动写入 Shell、十一款 CLI agent 与 omp 共 13 条带图标的启动配置（完整列表见 [接入说明](../cli-agents.md)），其中 omp 附带 `PI_FORCE_IMAGE_PROTOCOL=kitty` 以启用 US-D12 图片显示；
    - Shell 为通用终端，agent 使用本地打包的 LobeHub 图标（Antigravity CLI 为 `antigravity`，同时保留旧 `geminicli` 兼容渲染），omp 使用 Pi；
    - agent 预设按服务端 `$SHELL` 经“加载 shell 启动文件”包裹（Bash 或 Zsh，未设置时 Bash，其他 shell 直接执行）；
    - 各命令的授权参数见接入说明，Claude Code、Codex CLI、Antigravity CLI、Open Code、omp、Qoder、QoderCN 与 Kimi 为混合模式，可编辑或删除；
  - 文件已存在时启动服务（包括用户编辑或删空后）不再自动补写或覆盖，但可在设置页「新建启动配置」旁的「添加系统预设」菜单中补回单个或全部缺失的系统预设（已有同名配置时菜单项置灰并标记“已存在”，不覆盖用户已修改的配置）；
  - 配置跨重启与设备共享，环境变量值默认遮挡；
  - 按配置 ID 启动，修改或删除配置不影响运行中会话的命令与环境，会话信息保留配置 ID 供首页解析预览；
  - 存储不可用时显示原因，临时命令仍可用。编辑器可勾选混合模式，可用性由服务端判定并显示原因，列表显示“混合”标记（US-Q01）。
- **US-B09 启动 agent 时不卡在“信任此文件夹”**：作为使用者，我希望 Claude Code、Codex、GitHub Copilot CLI、Antigravity CLI、Qoder、QoderCN 和 Kimi 在新目录启动时不停在信任对话框，以便无人看着的会话也能直接开始工作。
  验收要点：
  - 默认开启 `agent_pretrust`；新建会话的命令被识别为这七款 CLI（直接执行、绝对路径、版本化二进制名或 Bash/Zsh 启动文件包装）时，先把启动目录记入该 CLI 自己的配置，或为 Kimi 注入进程级目录信任，再启动进程；
  - 写入位置优先跟随会话环境变量，其次是服务进程的同名变量，最后回退到主目录下的默认位置：
    - Claude Code：`CLAUDE_CONFIG_DIR` 或 `~/.claude.json`；
    - Codex：`CODEX_HOME` 或 `~/.codex/config.toml`；
    - GitHub Copilot CLI：`COPILOT_HOME` 或 `~/.copilot/config.json`；
    - Antigravity CLI：固定写主目录下的 `~/.gemini/antigravity-cli/settings.json`（`trustedWorkspaces`）；
    - Qoder 与 QoderCN：分别跟随 `QODER_CONFIG_DIR`（默认 `~/.qoder/settings.json`）与 `QODERCN_CONFIG_DIR`（默认 `~/.qoder-cn/settings.json`），写入 `permissions.trustDirectories`（不跟随命令行 `--config-dir`）；
  - Kimi 不写持久配置，只在会话环境补充 `KIMI_CODE_TRUST_WORKSPACE=1`；恢复 TUI 与 ACP 继承同一环境，会话或服务已显式设置该变量（包括 falsy 值）时不覆盖；
  - 已有配置的其他内容与权限保持不变；已经信任时不写；Codex 保留注释且不改写用户显式设为 `untrusted` 的目录；
  - Claude Code、Copilot、Antigravity CLI、Qoder 与 QoderCN 的配置文件缺失、或无法解析时不创建、不改写；Codex 只在 `~/.codex` 已存在时创建 `config.toml`；
  - 主目录、其上级目录与文件系统根永不写入或注入；目录先解析符号链接；
  - 任何失败只记录日志，会话照常启动；`agent_pretrust = false` 时不写任何文件，也不注入 Kimi trust 环境；
  - 其他 CLI 与已运行会话不受影响，说明与限制见 [CLI agent 接入](../cli-agents.md#文件夹信任预写)。

## C. 会话总览、搜索与提醒

- **US-C01 按项目总览**：作为同时处理多个任务的使用者，我希望按仓库、工作树和会话查看工作，以便快速理解每个任务在哪里运行。
  验收要点：
  - 左侧导航切换单仓库、全部仓库或直接会话，每项显示对应范围的会话及等待数（含需要回答、等待授权或出错停止的等待会话时，「待 N」徽章为红色，其余等待为琥珀色），长列表独立滚动；
  - 桌面主屏幕应用中的导航避开实际高度变化的吸顶页头，列表高度随之调整；
  - 窄屏选中后收起并恢复按钮焦点；
  - 首次多仓库进入优先选有会话者，明确选择在当前浏览器记忆，已移除仓库回退全部，读取失败不覆盖偏好；
  - 从终端返回首页立即渲染上次的会话列表、服务端设置和仓库分组，慢速链接上不再显示启动骨架屏，并在后台刷新；刷新结果覆盖缓存，读取失败不清除已显示内容，慢速 Git 读取不显示启动超时错误；缓存只在当前标签页内存中，整页刷新或令牌失效后按冷启动处理；
  - 仓库可折叠；
  - 直接会话按启动目录分组，失效工作树中的会话仍可访问；
  - 仓库级操作都在侧栏仓库行的“⋯”菜单（`仓库操作：<仓库名>`），页面上的仓库标题不再设按钮：
    - “新建工作树…”“主页显示…”（勾选哪些工作树显示在主页，底部有“批量管理…”快捷入口）“管理工作树…”（US-J14）“仓库详情…”；
    - 选中仓库后首页工具栏的“⋯”菜单（`仓库菜单：<仓库名>`）与侧栏共用这些条目并增加“仓库设置…”；选中工作树时再列出该工作树的“工作树详情…”“添加到主页 / 从主页移除”“删除 worktree”，工作树标题下只显示状态徽章，详情改在对话框中查看（US-J02）；
    - 仓库详情对话框显示路径（可复制）、工作树比例、会话计数与读取时间，并提供“从列表移除仓库…”；
    - 仓库或 Git 不可用时该菜单不显示；
  - 手机上各工作树的“新建会话”只显示图标，名称保留为无障碍名称与提示；
  - 聚焦单个仓库时不重复显示仓库标题与“工作树 主页 n/m”行，直接列出工作树；工作树路径及总数、运行/等待/退出计数收在各自的详情按钮中；
  - 首页不展示底部品牌、仓库持久化及可信网络/重启说明栏；
  - 会话与仓库管理表单按需加载，加载中可取消，下载失败可关闭提示，取消后不会迟到弹出。
- **US-C02 实时查看会话摘要**：作为使用者，我希望在首页看到标题、状态、最近活跃时间、连接设备数和输出预览，以便少打开几个终端就能判断进度。
  验收要点：
  - 默认显示输出预览，可切换为只保留会话摘要的紧凑列表，显式选择的显示方式在当前浏览器记忆；
  - 列表先加载快照再处理实时事件；
  - 创建、更新、移除自动反映；
  - 状态标签紧跟标题，下一行依次为所在端（混合会话）、连接设备或“后台会话”与最近活跃时间，状态变化不移动其他内容；
  - 没有客户端的会话显示为后台会话；
  - 高频输出保留未变化会话的对象与创建顺序，不反复排序全表；
  - 最近活跃时间每 30 秒及回到前台时校准；
  - 会话卡片按创建时使用的启动配置显示其预览设置，配置缺失或首页加载时存储不可用则回退全局设置，打开新建会话重新读取期间或失败时保留已加载的预览。混合会话卡片标出所在端，聊天端以最新 agent 消息代替终端预览，回合进行中卡片还显示一行当前工作（当前工具调用或计划步骤，一行截断）；
  - 已关闭或已中断的混合会话不在运行中会话里，而作为已归档记录显示在所属工作树（或直接会话目录、“已不可用工作区”）活动会话下方的“已归档”中；拥有已归档记录的工作树与有会话的工作树一样保留在首页，搜索与“已归档”状态筛选覆盖这些记录（US-Q09、US-Q12）。
- **US-C03 稳定浏览列表**：作为使用者，我希望后台输出不会移动正在点击的会话卡片，以便可靠地选择目标。
  验收要点：
  - 组内会话按创建时间倒序排列；
  - 输出和状态变化不触发活跃度重排；
  - 预览模式始终预留设定高度；
  - 切换仓库与筛选复用会话行并关闭隐藏项菜单；
  - 会话菜单首次打开后，鼠标、方向键、Escape 关闭与焦点恢复均可继续使用。
- **US-C04 搜索与状态筛选**：作为使用者，我希望按名称、目录、仓库或分支搜索，并结合运行、等待、退出筛选，以便从大量会话中找到目标。
  验收要点：
  - 搜索与状态条件在当前仓库范围内叠加，状态计数和辅助技术播报的仓库/会话总数随范围及实时数据更新；
  - 目录匹配包括启动目录和 Shell 报告的目录与主机；
  - 运行筛选包含 running 与 idle；
  - 搜索可展开匹配仓库；
  - 支持清除筛选、无匹配提示和 `/` 聚焦搜索，输入框与弹窗中不抢快捷键；
  - 筛掉的卡片不参与键盘导航或辅助技术浏览，并关闭该卡片已打开的菜单；
  - 手机上状态筛选为单行横向滚动（选中项自动滚入可见，每个页签都显示计数，为 0 时显示 0），搜索框提示缩短为“搜索会话”；首页顶栏同时承载紧凑/预览、刷新与仓库菜单图标，页内不再重复仓库标题，“新建会话”独占一行；
  - 清除筛选恢复卡片顺序，删除会话后移除对应卡片。
- **US-C05 判断运行状态**：作为使用者，我希望区分运行中、可能在等我、空闲和已退出，以便决定先查看哪个任务。
  验收要点：
  - 程序通过 `OSC 7501` 报告状态时以报告为准（工作中、阻塞、完成、空闲），工作中但长时间无输出视为空闲；
  - 否则依据关注信号、近期输出、提示符模式和终端读取给出启发式标签；
  - 曾发出 `OSC 7501` 或 Warp 结构化信号的程序不再触发“可能在等你”的启发式；
  - 计时休眠不直接当作等待输入；
  - 退出后显示退出码；
  - 状态只展示，不自动回答或执行操作。
- **US-C06 接收 agent 介入提醒**：作为遥控 agent 的使用者，我希望明确看到需要回答、等待授权、本轮完成或出错停止，以便及时处理任务。
  验收要点：
  - 支持 `OSC 7501` 程序状态、Warp 结构化 agent 事件、终端通知和 BEL 响铃，按此顺序分层：存在 `OSC 7501` 状态时只由其变化决定提醒，较低层不覆盖或清除较高层；
  - 服务端在无浏览器时也应答 `OSC 7501;?` 探测，使 Claude Code 等需探测的 agent 报告状态，回放不重答，`webmux attach` 不把探测转给本地终端；
  - 具体提醒优先于启发式状态，持续输出和重连不清除；
  - 需要回答、等待授权与出错停止在会话卡片状态徽章、右上角弹窗提醒和会话页顶栏状态圆点显示为红色（`destructive`），本轮完成、有通知、响铃提醒与启发式“可能在等你”保持琥珀色（`warning`）；
  - 使用网站时（首页、快速开始页或任意会话页），默认在页面右上角弹出新的关注提醒（Toast），无需浏览器通知授权或 HTTPS：
    - 弹窗展示状态徽章、会话标题与操作说明，点击直达对应会话 `/s/<ID>`，也可单独关闭、悬停暂停或超时自动收起；
    - 同一会话关注升级时替换前一条，关注解除或会话移除时自动消失；设置页“通知推送”卡片可按当前设备开关该弹窗提醒；
  - 用户输入、agent 报告重新开始或空闲、提示符作废或退出时清除，重复报告不在处理后再次提醒；
  - 只解析状态与种类，不保存正文；
  - 脚本可经 `webmux notify`（来源 `cli`，见 US-S13）发出提醒，附带的消息只在内存中，作为弹窗的说明行。
- **US-C07 调整输出预览**：作为使用者，我希望控制预览行数并跳过 agent 的底部状态栏，以便首页突出有用输出。
  验收要点：
  - 输出预览模式显示 1–50 行、跳过末尾 0–50 行；
  - 默认显示 10 行、跳过 1 行；
  - 提供示例与恢复默认；
  - 有效设置保存在服务端并跨设备同步，无效值不覆盖设置；
  - 启动配置可单独覆盖行数与跳过值并选择跟随全局默认，未配置或配置不可用时使用全局值。
- **US-C08 刷新外部 Git 变化**：作为使用者，我希望终端外发生的工作树变化也能出现在首页，以便总览反映磁盘现状。
  验收要点：
  - 打开首页、回到前台、重连、手动刷新和相关操作后重新读取 Git；
  - 读取时间收在仓库详情浮层，错误始终可见；
  - 较旧的请求结果不能覆盖新结果。
- **US-C09 切换明暗主题**：作为使用者，我希望页面和终端适应自己的明暗偏好，以便舒适阅读。
  验收要点：
  - 未选择时跟随系统主题；
  - 可手动切换并在服务端保存；
  - 已连接设备同步主题选择；
  - 终端颜色随主题更新。
- **US-C10 区分启动与当前目录**：作为在终端里 `cd` 的使用者，我希望首页同时看到会话的启动目录和 Shell 报告的当前目录，以便知道任务实际在哪里而不误判归属。
  验收要点：
  - 接受 OSC 7 `file://主机/绝对路径` 报告，拒绝凭据、端口、查询、控制字符和超长值；
  - 会话仍按启动目录及其工作树分组，报告目录只单独展示；
  - 非本机主机标注「远端」；
  - 菜单复制报告目录，无报告时复制启动目录；
  - 进程退出后清除；
  - 不改写 shell rc、不采集命令正文。
- **US-C11 新标签页打开终端（已退役）**：作为在多个会话间切换的使用者，我希望从会话列表打开终端时保留列表页，以便继续观察其他任务而不用回退或重新加载。
  验收要点：
  - 已退役（2026-10-28）：会话卡片改为在当前标签页打开终端，由 US-C14 取代；
  - 需要新标签页时可用浏览器的中键或 Ctrl/⌘ 点击。
- **US-C12 后台接收推送提醒**：作为离开页面或锁屏的使用者，我希望收到需要回答、等待授权、本轮完成、出错或终端通知的推送，以便及时回到对应会话。
  验收要点：
  - 设置页“通知推送”卡片提供默认开启的本机“页面内右上角弹窗提醒”开关（打开网页时无需授权或 HTTPS 即可提醒），并按设备开启或关闭后台推送，开启后台推送时只请求一次浏览器通知授权，显示服务端订阅数，并可从任一设备向全部设备发送测试通知；
  - 仅安全上下文与支持的来源（已授权的 HTTPS 入口，含 Tailscale Serve/Funnel，或本机回环）提供开关，否则给出 HTTPS 入口、Quick Tunnel、iOS 主屏幕、浏览器能力、权限或服务端配置等可执行提示；
  - 推送标题为会话标题，`include_title = false` 或标题为空时为 WebMux，正文以与会话列表一致的短标签开头并给出下一步；
  - `webmux notify` 带消息时正文改为该消息（US-S13），同样只在 `include_title = true` 时发送；
  - 测试通知说明推送已生效；
  - 点击通知聚焦或打开 `/s/<ID>`，不跟随负载中的其他地址；
  - 负载不含 cwd、命令、预览、OSC 正文或终端输出；
  - 送达为尽力而为，列表状态仍是唯一准确来源。
- **US-C13 浏览器标签页运行指示**：作为切到其他标签页或应用的使用者，我希望标签页图标与标题显示当前是否有任务正在执行，以便一眼看出任务是否仍在运行。
  验收要点：
  - 仅当前终端会话或首页任一会话 `status === "running"` 时，标题增加 `▶` 前缀并循环播放本地生成的 favicon 动画；
  - `waiting`、`idle`、`exited` 不播放“执行中”动画并恢复静态图标与基础标题；
  - 动画约 1–2 fps，不产生逐帧网络请求，不读取或输出终端正文；
  - `prefers-reduced-motion: reduce` 时图标保持静态运行帧、标题仍保留标记；
  - 刷新、断线重连、切换标签页或状态更新后指示与最新 `status` 一致；
  - 状态沿用启发式判定，长时间无输出的命令可能在 `idle_after_seconds` 后停止动画。
- **US-C14 当前标签页打开终端**：作为在会话列表与终端之间来回切换的使用者，我希望点击会话卡片直接进入终端，以便不在浏览器中堆积标签页。
  验收要点：
  - 点击会话卡片在当前标签页进入 `/s/<ID>`，不打开新标签页、不整页重新加载；
  - 链接不带 `target`，悬停不再提示“在新标签页打开”，标题旁的箭头改为向右的 chevron；
  - 中键或 Ctrl/⌘/Shift 点击保留浏览器默认的新标签页或新窗口行为；
  - 宽屏终端页的返回按钮回到当前模式的主页（工作台为首页，聊天为快速开始），列表继续实时更新；窄屏改由顶栏左侧的“打开侧栏”导航（US-C16）；
  - 主屏幕应用同样在应用内导航。
- **US-C15 手动修改会话标题**：作为使用者，我希望在首页会话卡片菜单里手动给会话起名，以便在 agent 不自动更新标题时仍能分辨会话。
  验收要点：
  - 卡片菜单的“修改标题”打开对话框，预填当前标题，Enter 或“保存”提交，取消不改动；
  - 手动标题优先于终端 OSC 与 agent 报告的标题，之后的自动标题不再覆盖它；
  - 保存成功后标题经会话列表同步到所有设备，混合会话归档后恢复仍保留该名称；
  - 留空保存则恢复自动标题：普通会话在终端或 agent 再次报告前显示启动目录名（首条提示为名的会话也回到目录名，因其写入的是创建名称，不是独立一层），混合会话立即恢复其上一个自动标题（如聊天端首条提示标题）；
  - 含控制字符或超过 512 字节的名称被拒绝并在对话框内显示原因，原标题不变；跨 Origin 请求同样被拒绝；
  - 侧栏的聊天历史与工作台导航树中，会话行有“⋯”按钮（`会话操作：<标题>`）：
    - 鼠标设备上行尾不留空位，悬停、聚焦或菜单打开时按钮出现在状态圆点的位置并暂时替代圆点（仓库行的“⋯”同样替代计数）；触屏上按钮常驻在圆点右侧；
    - 菜单对运行中会话提供“修改标题”（同一个对话框、规则相同）与“关闭会话”“停止会话并归档”或“移除会话”（与首页卡片共用对话框）；
    - 对已归档聊天提供以下操作：
      - “恢复聊天”；
      - “释放空间”（位于可用 linked worktree 且未释放时，US-J13）；
      - “删除记录”：确认后只删除记录，工作树保持不变；
      - “删除记录和工作树”：仅在关联的 linked worktree 可删除时出现，打开删除 worktree 确认流程，成功后同时删除该记录；
    - 已释放的聊天恢复前先确认重建 worktree；
- **US-C16 侧栏与模式切换**：作为在多个会话之间来回的使用者，我希望首页、快速开始页和会话页都有同一个左侧侧栏，并能在聊天与工作台两种模式间切换，以便不回首页就能跳到其他会话。
  验收要点：
  - 侧栏左上角两个带图标的按钮切换聊天模式（侧栏为聊天历史，主区域为快速开始 `/new`）与工作台模式（侧栏为仓库导航树，主区域为原会话总览 `/`），按钮用 `aria-pressed` 标记当前模式；
  - 本设备记住上次的模式：打开 `/` 且上次是聊天时以替换历史记录的方式进入 `/new`，首次使用或记录无效时进入工作台；直接打开其他地址以地址为准；
  - 侧栏只是导航方式：从任何位置打开会话都不改变模式；在会话页切换模式只更换侧栏内容，终端连接不中断；在首页切换则同时换到另一种主页；
  - 侧栏依次为模式切换、主要操作（聊天为“新聊天”，工作台为“新建会话”）、导航内容和底部全局区；首页原顶栏移除，连接状态与主机名、添加仓库、端口转发、设置和主题切换移到侧栏底部，重连时显示“连接已断开，重连中…”；
  - 桌面端侧栏可收起成只含图标的窄栏，收起状态保存在本设备；模式切换仅在侧栏展开时显示，终端随可用宽度重新计算列数：
    - 窄栏保留展开按钮和主要操作（聊天为“新聊天”，工作台为“新建会话”）；
    - 其下依次列出进程仍在运行的会话（已退出的不显示）以便快速切换，只显示 agent 或启动配置图标，右下角是与侧栏会话行相同的彩色状态指示灯，当前会话标 `aria-current`；
  - 桌面端展开的侧栏右边缘是可聚焦的分隔条（`role="separator"`），拖动或方向键（Shift 加大步长，Home/End 到边界）调整宽度，范围 256–480px，宽度保存在本设备，页面随之让出空间；侧栏顶部的收起按钮、品牌和模式切换在任何宽度下都不重叠；
  - 小于 640px 时侧栏隐藏，从首页、快速开始和会话页顶栏左侧的“打开侧栏”按钮以左侧抽屉打开；只切换模式时抽屉保持打开，导航到其他页面后关闭；
  - 外壳只读取现有的会话列表、仓库清单与混合会话记录，不改变首页、快速开始页和会话页本身的行为。
- **US-C17 工作台导航树**：作为同时运行多个仓库和 worktree 的使用者，我希望在侧栏按“仓库 → worktree → 会话”看到全部运行中的会话及其状态，以便直接跳到目标会话或工作树。
  验收要点：
  - 第一层依次为“全部仓库”、每个已登记仓库和“直接会话”，第二层是首页分组中显示的工作树（顺序与首页一致），第三层是运行中的会话（按创建时间从新到旧，输出不改变顺序）；已归档记录只在“已不可用工作区”节点下出现（见下），不在工作树下；
  - 点仓库或“直接会话”进入工作台首页的对应视图，点工作树进入工作台首页并只显示该工作树下的会话与归档记录；当前视图或会话标记 `aria-current`，当前会话所在路径自动展开；
  - 从工作台打开任何会话（含处于聊天端的混合会话）都保持工作台模式；会话卡片同样如此；直接打开地址或刷新不改变模式；
  - 会话行显示 agent 或启动配置图标、标题和彩色状态圆点（绿色工作中、琥珀等待、灰色空闲、空心已结束），状态文字在行的可访问名与悬停提示中；节点显示会话数，收起时仍显示等待数量；圆点与计数在行尾右对齐；
  - 不可用的仓库保留并标出原因，不显示工作树；可用仓库行提供“⋯”操作菜单（`仓库操作：<仓库名>`），包含“新建工作树…”“主页显示…”“管理工作树…”（US-J14）与“仓库详情…”，仓库或 Git 不可用时不显示；
  - 其他客户端（如 `webmux run --new-worktree`）新建的会话指向页面尚未读取的仓库或工作树时，外壳自动重读一次仓库清单，会话直接出现在对应工作树下，不先落入“已不可用工作区”、也不需要点击或刷新；重读后仍找不到的工作树（例如已释放空间）才归入“已不可用工作区”，同一工作树不重复重读；
  - “已不可用工作区”节点在有运行中的会话，或有无法归位到现存工作树的已归档记录（例如删除或释放空间后保留的已释放记录）时出现，与首页该仓库的分组一致；记录是其下的子行，排在运行中的会话之后：
    - 外观与交互沿用聊天历史的已归档行：空心圆点表示已结束，已释放的记录另带“已释放空间”图标，可访问名为“<标题>（已释放空间，已结束）”；
    - 点击已释放的记录先确认重建再恢复，其他记录直接恢复；行尾“⋯”提供“恢复聊天”“删除记录”，以及关联工作树可删除时的“删除记录和工作树”；
    - 节点的会话数与等待数只统计运行中的会话，不计入记录；
    - 记录行同样参与方向键导航、展开状态保存与当前页面路径自动展开；
  - 展开状态保存在本设备；树使用 `tree`/`treeitem` 语义，方向键在可见行间移动、左右键收起或展开，焦点行的“⋯”按钮是下一个 Tab 停靠点。

- **US-C18 快速切换会话**：作为同时处理多个项目的使用者，我希望从当前页面直接找到已有会话，以便接续工作。
  验收要点：
  - 工作台、新聊天、终端和设置均有入口。macOS 用 `⌘+K`，Windows 和 Linux 用 `Ctrl+Alt+K`。
  - 可跨仓库和工作树搜索会话名称、启动目录、仓库名和分支名，结果展示状态并将已退出会话单列。仓库信息加载时仍可按会话名和目录搜索。
  - 在应用外壳中，结果随实时会话列表更新。点击结果或用方向键与 Enter 打开会话，已在当前分屏中的会话直接激活对应窗格。
  - Esc 或关闭按钮取消并恢复焦点。输入法组合、其他已打开的弹窗和菜单期间不触发快捷键。搜索按键不发给终端，Shell 保留 `Ctrl+K`。
