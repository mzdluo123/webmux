# 配置、运行与服务管理

本页描述 K 组故事；L 组（开发、验证与发布支持）已拆到[贡献者工具](contributor-tooling.md)。

## K. 配置、运行与服务管理

| 编号 / 功能                 | User story                                                                                                                                  | 验收要点                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| US-K01 单二进制运行         | 作为部署者，我希望下载一个匹配平台的二进制就能前台运行，以便减少安装成本。                                                                  | 支持 Linux/macOS、amd64/arm64；浏览器资源内嵌，运行端无需 Node、Go、tmux 或数据库；`webmux` 与 `webmux serve` 均可启动；`--log-file` 以 0600 文件保存 stdout/stderr，旧文件保留为 `.1`，启动方关闭管道后仍可运行。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| US-K02 初始化私有配置       | 作为部署者，我希望自动生成带随机 token 的配置，以便快速准备自己的服务。                                                                     | `config init` 使用模板与随机 token 创建私有目录和 0600 文件，不向输出打印 token；默认拒绝覆盖，显式 `--force` 时原文件保留为 `.bak`；支持 `--listen` 和配置路径；`config path` 可显示存在状态或 JSON；未显式 `--config` 且默认文件缺失时，首次 `serve` / `start` 使用同一模板与 token 生成逻辑自动创建，启动输出说明创建/使用的路径并提示用 `webmux status --json --reveal-token` 查看 token；并发首次启动通过原子发布只创建一个文件，已有文件不重写；`service install` 与托盘复用同一逻辑。                                                                                                                                                                                                                                                                                                                                              |
| US-K03 检查与覆盖配置       | 作为部署者，我希望启动前检查配置并用命令行覆盖地址或 token，以便发现配置错误和临时调整运行环境。                                            | `config check`/`validate` 校验而不启动服务，TOML 语法错误带行列号，可输出 JSON；`config show` 只读查看磁盘配置，`--live` 查看已验证运行进程的内存快照；不可达报错、不回退磁盘，凭据仅输出是否配置；字段显式默认值仍保留来源且不含 token；显式指定缺失文件时报错且不会创建，默认文件缺失时 `config show`/`validate` 仍按默认值工作，只有 `serve` / `start` 会自动生成；`--listen`、`--token` 优先且只覆盖本次进程，显式空 token 也能覆盖（非 loopback 地址仍自动生成 token，见 US-A03）；配置修改需重启生效。                                                                                                                                                                                                                                                                                                                              |
| US-K04 调整会话与提醒行为   | 作为部署者，我希望配置默认目录、缓冲和状态判断，并单独管理启动命令，以便适配自己的 agent 与资源预算。                                       | 支持 `default_cwd`、`scrollback_bytes`、`idle_after_seconds`、`prompt_patterns`、`agent_protocol`、`bell_attention`、`program_status`，校验正则；启动命令完全通过自定义配置或显式 argv 提供，原 `shell`/`presets` 配置项不再提供内置命令，新安装首次启动在 `launch-configs.json` 写入常见 agent 预设；提醒集成方式见 [使用指南](../usage.md#需要你介入的提醒)。                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| US-K05 安装后台用户服务     | 作为部署者，我希望以当前用户安装并启动后台服务，以便不需要一直开着前台终端。                                                                | `service install` 使用 Linux systemd 用户服务或 macOS LaunchAgent，无需 sudo；引用二进制和配置的绝对路径；默认配置缺失时与首次 `serve` 共用生成逻辑，创建后重新读取并校验，显式配置必须已存在且有效；保留必要 PATH 与运行环境。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| US-K06 预览与更新服务定义   | 作为部署者，我希望先预览服务定义，并明确覆盖旧定义，以便检查安装位置与启动参数。                                                            | `service install --dry-run` 只打印定义，不写文件或创建配置；定义输出失败时返回错误；已有定义须 `--force` 替换并重启；二进制移动后可重新安装更新路径。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| US-K07 启停、诊断与卸载     | 作为部署者，我希望用统一命令管理后台服务并查看日志，以便维护和排查故障。                                                                    | 提供 start、stop、restart、status、logs、logs --follow/-f、uninstall；停止、重启、卸载会结束会话；卸载保留二进制、配置、日志与状态目录；服务启用不等于端口已监听，应结合状态和日志诊断。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| US-K08 保存仓库清单         | 作为部署者，我希望指定状态目录并保护其内容，以便重启或升级后仍保留项目登记。                                                                | `state_dir` 保存仓库清单、受保护的运行时记录/本机 API 信息及可选 cloudflared 缓存，不持久保存会话或终端输出；支持 XDG 默认路径；各领域 JSON 使用统一私有权限、严格限长解码、持久提交与单实例锁；领域故障保留原文件并隔离，提交不确定时冻结写入；仓库或偏好存储失败不阻止直接终端工作。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| US-K09 可信远程入口与升级   | 作为部署者，我希望通过可信 VPN 或 HTTPS 代理访问，并知道升级的影响，以便维护远程终端。                                                      | `listen`、`token`、`allowed_origins` 配合部署；`listen` 端口无效、`allowed_origins` 条目不是 `scheme://host[:port]` 的精确小写形式（如带尾斜杠、路径或默认端口）时启动即报错；TLS 由外部代理提供，正确保留 Host 并配置 Origin；`version` 与 `help` 提供版本和命令信息，`version --json` 另含控制契约版本且不读取配置；替换二进制后需重启，重启结束会话但保留仓库登记与磁盘工作树。                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| US-K10 定位设置分区         | 作为使用者，我希望通过分区导航快速找到设置项，以便在桌面和手机上减少长页面翻找。                                                            | 桌面左侧显示固定分区导航，手机顶部显示可横向滚动的吸顶导航；提供外观与阅读、快捷指令、启动配置、草稿与暂存、公网访问、Tailscale、安装应用、通知推送、输出预览九个入口；点击或键盘激活滚动到对应分区并转移焦点，滚动时高亮当前分区；Home Screen App 中吸顶导航按实际顶栏高度定位，不遮挡顶栏；支持地址片段直达和浏览器前进后退；定位不卸载表单、不丢失尚未保存的输入。                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| US-K11 一键安装             | 作为部署者，我希望用一条命令安装匹配平台的二进制，并在网络受限时自动尝试镜像，以便不必手动分辨版本、架构和校验步骤。                        | 提供 POSIX `sh` 脚本，支持 Linux/macOS 的 amd64/arm64；Rosetta 终端优先选择 arm64，Windows 明确引导到 exe/托盘；默认最新 Release，`WEBMUX_VERSION` 可固定版本，`WEBMUX_INSTALL_DIR` 覆盖目录且不自动 sudo；先 GitHub 直连，再按 `WEBMUX_MIRRORS`（默认 `ghfast.top`、`gh-proxy.com`，空值只用 GitHub）回退，每源有连接、低速与总时限；二进制和同源 `SHA256SUMS` 校验通过才原子安装，失败保留旧文件并汇总来源错误，`WEBMUX_SHA256` 可固定摘要；安装入口使用 Release 资产、jsDelivr 或 gh-proxy 镜像，不依赖 `raw.githubusercontent.com`，并说明镜像可看到 IP、同源校验不能证明镜像可信；脚本只装二进制，不改配置、服务或 shell。                                                                                                                                                                                                           |
| US-K12 无服务管理器后台启动 | 作为部署者，我希望在容器、WSL 或没有 systemd / launchd 的环境中让 WebMux 脱离当前 shell 运行，并能用客户端停止，以便不必保持前台终端。      | `webmux start` 接受与 `serve` 相同的参数，以新会话启动子进程并把 stdout/stderr 写入 `<state_dir>/webmux.log`（0600，旧文件保留为 `.1`）或显式 `--log-file`；等待运行时记录后输出 PID、不含 token 的本机链接与日志路径并退出；已有实例时幂等打印状态并退出 0；子进程清除继承的 `WEBMUX_SESSION_ID`、`WEBMUX_LAUNCHER`、`INVOCATION_ID`、`XPC_SERVICE_NAME`，避免被启动方会话清理并保持 `manual` 记录，可用 `webmux stop` 停止；启动失败输出日志尾部并返回非 0；生产环境仍推荐 `service install`。                                                                                                                                                                                                                                                                                                                                          |
| US-K13 Linux 安装包         | 作为 Debian / Ubuntu 或 Fedora 等发行版的用户，我希望用 apt / dnf 安装、升级和卸载 WebMux，并能一条命令设置开机自启，以便按系统惯例管理它。 | Release 提供 amd64、arm64 的 `webmux_<版本>-1_<架构>.deb` 与 `webmux-<版本>-1.<架构>.rpm`，计入 `SHA256SUMS`，内含与同版本 `webmux-linux-<架构>` 相同的 `/usr/bin/webmux`（0755）、用户单元 `/usr/lib/systemd/user/webmux.service`（0644）与自动更新的系统单元 `webmux-update.service` / `webmux-update.timer`（0644，见 US-K14），无依赖；安装脚本只管理更新定时器；安装、升级、卸载不为任何用户启用、启动或重启 `webmux.service`，运行中的服务升级后到重启才换新版本；用户执行 `systemctl --user enable --now webmux` 后以默认配置运行（首次启动生成带随机 Token 的配置）并在登录后自启；没有 `~/.config/systemd/user/webmux.service` 时 `webmux service status\|start\|stop\|restart` 作用于包内单元，`uninstall` 只禁用并停止它且不删除文件，两者都没有时仍提示先 `service install`；`service install` 写入的用户定义优先于包内单元。 |
| US-K14 安装包自动更新       | 作为用 deb / rpm 安装的部署者，我希望系统每天自动安装经过签名验证的新版本，同时不打断正在运行的终端会话，以便不必手动跟踪发布。             | 首次安装在运行 systemd 的系统上启用 `webmux-update.timer`（每日、最多 6 小时随机延迟、错过补执行），无 systemd 时只装文件；升级只 `daemon-reload` 并保留管理员的 `disable`，卸载停用定时器；服务以 root、无法访问 `/home` 与 `/root` 运行 `webmux update apply`：仅发布构建、仅 root、单实例锁、仅当 `/usr/bin/webmux` 属于 `webmux` 包，按签名清单下载同格式同架构安装包并用 argv 调用 `dpkg -i` / `rpm -U`，只升级不降级；包管理器被占用等失败时原安装不变、次日重试，下载的包总被删除；journal 记录版本、来源与结果；不触碰任何用户的 `webmux.service`。                                                                                                                                                                                                                                                                               |
| US-K15 检查更新与验证签名   | 作为部署者，我希望随时查看是否有新版本，并能独立验证下载的发布文件来自官方，以便在任何安装方式下判断是否升级以及下载是否可信。              | `webmux update check` 在任意安装方式下输出当前版本、最新版本、是否有更新，`--json` 输出 `{v,current,latest,available,installMethod}`，不下载、不改文件，失败时非零；`install.sh` 或手动安装时提示重新运行 `install.sh`，deb/rpm 时提示定时器与 `sudo webmux update apply`；非发布构建报告“此构建不是发布构建，不支持更新”且不联网；每个 Release 附带 `SHA256SUMS.minisig`，可信注释 `webmux <版本>`，文档公布公钥，`minisign -Vm` 可手动验证；更新程序只信任内置公钥，GitHub 与镜像返回的清单都须验证签名，版本取自签名注释。                                                                                                                                                                                                                                                                                                             |
| US-K16 待生效版本提示       | 作为使用者，我希望在服务端可执行文件被更新后得知新版本需要重启才生效、重启会结束会话，以便自己选择合适的时机重启。                          | 运行中的服务端在状态被查询时（距上次至少 60 秒且文件标识变化）以 argv 运行自身路径的 `version --json` 得到已安装版本；不同于运行版本时 `webmux status` 增加提示行，`status --json` 与本机状态 API 含 `installedVersion`，`GET /api/config` 含 `pendingUpdate{installedVersion,launcher}`；Web UI 主页顶部与设置页显示已安装版本、重启后生效、重启结束所有会话，并按启动方给出 `systemctl --user restart webmux`、`webmux service restart`、托盘菜单重启或重新运行；主页提示可按版本关闭（设备本地），设置页始终显示；不提供重启按钮，服务端从不因此自动重启。                                                                                                                                                                                                                                                                             |
