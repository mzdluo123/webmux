# 草稿编写、保存与发送确认

本页记录草稿与暂存的编辑、保存及提交确认。操作步骤见[草稿模式](../../usage/terminal.md#草稿模式)，其余终端故事见[终端、输入与移动端](../terminal.md)。

- **US-F01 多行编写**：作为向 agent 描述任务的使用者，我希望先在草稿框中整理多行文字，以便写完再统一提交。
  验收要点：
  - 显式开启草稿；
  - 可调整面板高度；
  - 输入、换行、粘贴和编辑留在当前草稿，Enter 不直接提交；
  - 当前草稿与暂存是两个独立编辑目标，暂存只在显式取用时进入当前草稿；
  - 输入法组合期间不发送。
- **US-F02 组合输入素材**：作为使用者，我希望键盘文字、软键字符、代码引用、上传路径和快捷指令汇入同一草稿，以便组织完整上下文。
  验收要点：
  - 按草稿光标或选择范围插入；
  - 支持字素分段的浏览器中，草稿软键左右移动、从终端转入草稿的退格和删除按完整字符处理，包括组合重音和多码位表情；
  - 开启草稿时不直接写入 PTY；
  - 异步输入只进入当前草稿，不串到其他会话或暂存条目；
  - 终端控制键被拦截并提示先退出草稿。
- **US-F03 隐藏、恢复与清空**：作为使用者，我希望暂时隐藏草稿而保留内容，也能明确清空，以便在直接操控和编写之间切换。
  验收要点：
  - 关闭草稿仅隐藏当前草稿和暂存面板，不发送或清空；
  - 隐藏期间收到插入或暂存更新时有提示；
  - 草稿栏以图标和数量徽标打开暂存，清空图标提供名称提示；
  - 清空当前草稿与清空暂存分别确认，删除对应本机保存，不删除已上传文件。
- **US-F04 明确发送与确认**：作为使用者，我希望点击发送后知道正文是否写入终端，以便避免把点击成功误当作任务已执行。
  验收要点：
  - 正文与一次 Enter 作为同一提交；
  - 显示发送、收到、写入等状态；
  - 确认写入后清空并收起；
  - 确认前锁定正文；
  - “已写入终端”不代表 agent 已接受或执行成功。
- **US-F05 处理断线与不确定结果**：作为使用者，我希望发送中断后查询原提交结果，以便避免重复向 agent 下达任务。
  验收要点：
  - 断线显示结果未知；
  - 重连后查询原 ID；
  - 允许按原提交重发并在当前会话有效记录范围内去重，或转为草稿；
  - 失败、部分写入、无记录分别提示；
  - 不自动把未知正文作为新提交重发。
- **US-F06 按会话保存和恢复**：作为使用者，我希望刷新、关闭页面或重新认证后恢复未完成草稿，以便继续编辑而不丢失任务描述。
  验收要点：
  - 当前浏览器按会话保存当前草稿、未确认提交和暂存；
  - 恢复时显示目标会话并查询已有提交；
  - 暂存来自较早会话实例时提示但不自动发送；
  - 恢复不自动发送；
  - 会话实例变化不能沿用旧实例的发送确认。
- **US-F07 管理本机草稿**：作为重视本机数据保留的使用者，我希望关闭草稿保存、查看数量或清除保存内容，以便控制浏览器中的任务文本。
  验收要点：
  - 设置显示 N 个会话的草稿与 M 条暂存；
  - 关闭保存立即删除已存草稿和暂存，之后仅保留页面内存；
  - 清除全部需确认；
  - 7 天未修改或会话不存在时清理；
  - 超出本机保存限制时提示仅保留当前页面。
- **US-F08 离线和退出后继续整理**：作为使用者，我希望终端不可发送时仍能编辑或复制草稿，以便先完成文字整理。
  验收要点：
  - 断线、回放未完成或会话退出时禁用发送并给出原因；
  - 草稿仍可编辑，暂存仍可查看、编辑、排序和取用；
  - 取用不发送；
  - 恢复连接后由用户手动决定发送；
  - 会话已移除时清理其草稿和暂存。
- **US-F09 多条暂存**：作为需要连续安排多个任务的使用者，我希望为同一会话保留多条暂存文本并分别编辑、排序和取用，以便 agent 工作时先记下后续任务而不覆盖当前草稿。
  验收要点：
  - 当前草稿与暂存为不同编辑目标；
  - 列表独立滚动，新建区保持可达；
  - 可直接编辑和通过带名称提示的图标取用，排序、删除位于条目菜单，清空使用图标并二次确认；
  - 显示条数、字符数及满额原因；
  - 取用前处理与当前正文的追加或替换冲突，替换时先把原正文保留为暂存；
  - 未确认提交期间禁止转存和取用；
  - 取用不自动发送或聚焦终端；
  - 存储禁用、损坏或超额时保留页面内编辑并提示。
