# 代码工作区与工作树

## I. 代码工作区、Diff、引用与文件操作

- **US-I01 边用终端边看代码**：作为遥控开发任务的使用者，我希望在会话旁打开代码工作区，以便核对 agent 的工作而不离开终端。
  验收要点：
  - 宽屏并排且可调整分栏；
  - 窄屏切换终端与代码；
  - 导航开关、文件标签、刷新全部与独立窗口同在一行，根路径与导航状态提示在导航面板顶部；
  - 代码导航可折叠、调整宽度；
  - 窄于 640px 时文档栏操作收进“代码菜单”（显示完整路径），文档提示仍直接显示，Diff 内容区不少于 393×851 视口高度的 70%；
  - 切换保留同一 PTY，输出继续接收；
  - 在聊天模式或工作台模式中切换会话时，代码面板的开合与分栏宽度保持不变（保存在本机浏览器）；回到先前的会话时，该会话已打开的文件标签、当前标签、导航与阅读位置按离开时恢复（仅在页面未刷新时保留），各会话的标签互不混用。
- **US-I02 确定阅读范围**：作为使用者，我希望知道代码根目录对应哪份工作树，以便避免把另一个分支的代码当作当前任务。
  验收要点：
  - 根绑定会话启动目录所属 Git worktree，无 Git 时绑定启动目录；
  - 终端内 `cd` 不改变它；
  - 不越过符号链接、嵌套仓库等受保护边界读取。
- **US-I03 浏览与搜索路径**：作为使用者，我希望展开树状目录并按文件名或路径搜索，以便找到要核对的代码。
  验收要点：
  - 目录在原位按需展开，可同时展开多个分支，保留父目录和同级项；
  - 缩进线、目录/文件图标、当前文件高亮和 Git 状态可识别；
  - 支持方向键/Home/End 导航、全部折叠和刷新，刷新、收起导航与切换修改页保留展开分支；
  - 搜索与按路径打开从紧凑工具栏进入，目录定位展开对应祖先路径；
  - 默认隐藏 Git 忽略的未跟踪项，可从菜单显式显示忽略项，切换后目录树与搜索使用相同范围；
  - 根目录和子目录均可分页，搜索或扫描受限时提示缩小范围；
  - 搜索中全部折叠回到真实根目录，不把搜索结果作为目录项；
  - 路径搜索不等同于全仓库正文搜索。
- **US-I04 多标签只读阅读**：作为使用者，我希望同时打开多个文件并查看高亮内容，以便在相关实现间切换。
  验收要点：
  - 最多 20 个文件或 Diff 标签；
  - 标签标明路径和来源，可单独关闭；点击标签或将焦点移到标签会显示对应内容，左右方向键及 Home、End 可在标签间移动；
  - 只读，不保存修改、不操作 Git 索引或配置；
  - 单文件与 Diff 使用同一套 Pierre 渲染器、主题与高亮 worker，按文件名与扩展名识别常见语言并按需加载语法高亮，未识别时按纯文本显示；
  - 不提供编辑或保存。
- **US-I05 文件内定位**：作为使用者，我希望在文件和 Diff 中查找文字、跳转行并调整阅读显示，以便迅速定位细节。
  验收要点：
  - 文件与 Diff 使用同一套查找面板、上/下一个匹配、大小写/正则/全词选项和 Ctrl/⌘+F、F3、Ctrl/⌘+G 键位；
  - 查找定位并选中整行，可关闭面板；
  - 普通文件可切换行号，偏好跨设备同步；
  - 文件的跳转行接受 `N`、`+N`、`-N`、`N%` 与 `N:列`；
  - Diff 换行偏好同样同步；
  - Diff 固定显示行号，保留自动换行和 Ctrl/⌘+Alt+G 跳转行快捷键；
  - 单文件与 Diff 工具栏提供“缩放”按钮，点击展开或收起字号缩放条（10px–24px，默认 13px，非默认时可一键重置），也支持桌面端 `Ctrl + 鼠标滚轮` 缩放与触摸设备双指捏合缩放，代码字号保存在本机浏览器；
  - 单文件与未自动换行的 Diff 在代码行超出可视宽度时于视图底部显示横向滚动条，与代码区横向滚动保持同步。
- **US-I06 总览 Git 修改**：作为使用者，我希望按未暂存、已暂存、未跟踪查看修改，并筛选路径，以便了解 agent 改了什么。
  验收要点：
  - 修改分组、来源和状态可识别；
  - 支持路径筛选、分页与大列表浏览；
  - 无 Git 时说明差异不可用，不阻止普通文件阅读。
  - 可把一项修改标记为已看，列表显示已加载项目的审阅进度。标记保存在当前浏览器，在代码弹出窗口与主窗口之间同步。暂存内容变化，或工作树文件的修改时间、大小、模式等元数据变化后重新列为待看。
- **US-I07 阅读 Diff**：作为使用者，我希望 Diff 自动适配阅读宽度并能展开上下文，以便直接理解增删内容和周边代码。
  验收要点：
  - 显示新增/删除行数；
  - 宽度足够时并排、窄屏统一显示，固定保留行号，无需手动选择布局；
  - 按需展开上下文，区分新增、删除、重命名等变化；
  - 受限或计算失败时提示并提供重试或完整文件入口。
- **US-I08 切换完整文件和比较来源**：作为使用者，我希望从文件查看 Diff，也能打开 Diff 两侧完整文件，以便在变更与完整上下文间切换。
  验收要点：
  - 根据修改组比较工作树、索引与 HEAD；
  - 通过一个“完整文件”菜单打开同一快照修改前或修改后的文件，不提供不存在的版本；
  - 文件与 Diff 切换只展示下一步操作；
  - 窄于 640px 时这些操作在“代码菜单”中；
  - 无差异或来源已变更时保留阅读并提示，不悄悄换成不同版本。
- **US-I09 插入文件和行引用**：作为使用者，我希望把整个文件、某行或连续行范围发送给终端或草稿，以便准确告诉 agent 关注哪里。
  验收要点：
  - 桌面行号选择、Shift 连选，触摸点行后点底部“发送位置”；
  - 文字 Diff 根据选中行自动确定引用版本，无需选择旧侧/新侧；
  - 默认引用修改后版本，已删除文件引用修改前版本；
  - 文件与 Diff 都在选行后才显示“引用整个文件”；
  - 操作栏单行，宽屏左侧显示引用版本和选择方式提示，窄屏省略提示；
  - 生成绝对路径及可选行范围，不回车，路径正确转义；
  - 索引/HEAD 引用注明版本，不能把跨两侧选择伪装成同一来源。
- **US-I10 发现变化后手动刷新**：作为使用者，我希望阅读时收到外部更新提示，再决定何时刷新，以便不被 agent 的写入打断。
  验收要点：
  - 代码可见且页面在前台时约每 5 秒检查，也在恢复可见或连接时检查；
  - 文件、目录、修改列表提示更新、删除或未知状态；
  - 保留旧内容，显式刷新才替换；
  - 状态异常时阻止发送陈旧引用。
- **US-I11 识别不可阅读内容**：作为使用者，我希望二进制、超大文件或不支持的路径给出清楚说明，以便知道为何没有正常代码视图。
  验收要点：
  - 单个文本文件最多 2 MiB / 20000 行，图片与 PDF 另按 US-I15、US-I17 的上限预览，单目录最多检查 10000 项；
  - 非图片、非 PDF 的二进制，空或无法识别的图片，空或缺少 `%PDF-` 签名的 `.pdf`，特殊文件、子模块等按支持范围展示元信息或边界；
  - 其他扩展名的 PDF 内容仍为二进制内容；
  - 受限结果不冒充完整结果。
- **US-I12 隔离快照与会话**：作为使用者，我希望代码快照始终属于当前会话，并在过期时明确提示，以便不发送错误版本的引用。
  验收要点：
  - 上下文与快照按会话校验，不能跨会话复用；
  - 快照过期时保留旧画面并提示刷新；
  - 不把过期快照默认为当前文件。
- **US-I13 独立代码窗口**：作为桌面使用者，我希望把代码工作区弹到独立窗口，以便同时给终端和代码留出更大阅读空间。
  验收要点：
  - 支持时使用置顶画中画，否则回退普通弹出窗口，窗口内只有运行独立代码工作区的同源 iframe；
  - 弹出、收回与直接关闭窗口都保留标签与已加载内容、阅读位置与选择（滚动、选区、查找、Diff 展开与选中、预览位置）、展开的文件夹、待粘贴条目与“有更新”提示；
  - 主页面显示占位，可收回；
  - 右键菜单、对话框与底部面板显示在独立窗口内并定位在触发处，窄窗口按自身宽度布局；
  - 引用经消息通道插入主页面的终端或草稿；
  - 关闭独立窗口恢复原位，离开或刷新主页面会关闭它；
  - 不支持画中画且无精细指针，或在带触摸屏设备的主屏幕 Web App 中时隐藏入口，窄于 640px 时也不显示；
  - 独立窗口内文件与修改视图的行号单击、Shift 范围选择和重新选择照常可用；
  - 弹窗被拦截时提示。
- **US-I14 按路径打开**：作为在终端里 `cd` 的使用者，我希望输入相对当前目录的路径直接打开文件，以便不必从代码根逐层查找。
  验收要点：
  - 相对路径以本机 Shell 报告目录为基点，无报告时用启动目录，也接受绝对路径；
  - 服务端解析符号链接后必须位于代码根内，目录跳转到文件树；
  - 远端报告、根外路径、`.git` 内部、不存在路径和特殊文件给出明确错误；
  - 读取仍走既有边界检查。
- **US-I15 预览与下载图片**：作为远程核对 agent 产物的使用者，我希望在代码工作区直接查看图片并下载到当前设备，以便确认截图、图表等生成结果。
  验收要点：
  - PNG、JPEG、GIF、WebP、AVIF、BMP、ICO 按扩展名加文件头识别并预览，可适应窗口、1:1、缩放、拖动和双指缩放，显示格式、像素尺寸与大小；
  - 图片工具栏单行，窄屏触摸设备只保留适应窗口与 1:1，缩放靠双指；
  - SVG 默认预览、可切源码，脚本与外部资源不生效；
  - 20 MiB 以上只显示元信息，100 MiB 内可下载且字节一致、保留原名；
  - 图片 Diff 显示变更与大小并可切换修改前/修改后版本；
  - 文件变化、快照过期、过大与未认证给出明确错误，token 不进 URL。
- **US-I16 预览 Markdown**：作为阅读 README、设计文档或说明的使用者，我希望在代码工作区直接查看 Markdown 的排版结果，以便确认标题、列表、代码块、链接和图片的呈现，并在文档之间跳转。
  验收要点：
  - 打开 `.md`、`.markdown`、`.mdown` 或 `.mkd` 文本文件时，文档栏（窄屏为“代码菜单”）提供“预览”按钮切换到渲染视图，并可“返回源码”；
  - 渲染标题、列表、代码块、表格和链接；
  - 原始 HTML 经清洗，不执行脚本、不嵌入框架，作者的 `id`/`name` 被移除，外部图片只显示为“图片：说明（地址）”文字，`javascript:` 等协议的链接只剩文字，HTTP(S)/mailto 链接在新标签页打开；
  - 相对链接相对当前文档目录、`/` 开头相对工作区根解析，在代码面板中打开文件标签或在文件导航中定位目录，越界、不存在、符号链接或不可读时就地提示，修饰键点击行为相同且不打开应用路由；
  - 标题生成 `md-h-` 前缀的 GitHub 风格锚点，`#标题` 在预览内滚动且不改地址栏，`文件#标题` 打开该文件预览并定位；
  - 两个及以上标题时提供“目录”（窄屏在“代码菜单”）；
  - 工作区内相对图片（含 SVG 与 `<img>`）进入可视区附近时经快照原始字节端点以认证请求加载，最多同时 2 张、每篇 50 张，失败显示不存在、不在工作区内、不是可预览的图片、超过 20 MiB、传输繁忙（可重试）或内容已变化，点击已加载图片在面板中打开，切换标签或离开预览时取消读取并释放对象 URL；
  - 带语言标注的代码块按 CodeMirror 语言数据高亮并跟随明暗主题，未知语言保持纯文本；
  - 切换文件或 Diff 后回到源码模式，预览状态不写入设置。
- **US-I17 预览 HTML、表格、JSON 与 PDF**：作为核对 agent 产出报告、数据和文档的使用者，我希望在代码工作区直接查看 HTML、CSV/TSV、JSON 与 PDF 的呈现结果，以便不下载到本地也能确认内容，在手机上同样可用。
  验收要点：
  - `.html`、`.htm`、`.csv`、`.tsv`、`.json`（大小写不敏感）的完整文本文件默认显示源码，文档栏（窄屏为“代码菜单”）提供“预览”并可“返回源码”，切换文件、Diff 或刷新后回到源码，状态不写入设置；
  - 超过文本上限、编码不支持或二进制的同名文件以及 Diff 不提供预览；
  - HTML 先在惰性解析中去除脚本、`<base>`、meta 刷新、`<object>`/`<embed>`/`<iframe>`、事件属性、链接地址与表单动作，注入 CSP 后放入无 `allow-*` 的 `sandbox` 框架，白底显示并提示“静态预览，脚本与外部资源已禁用”，保留内联样式与 `data:` 图片，不发起任何请求、不提交、不导航；
  - CSV/TSV 按 RFC 4180 解析引号、转义引号与字段内换行，首行为表头、表头吸顶、可横向滚动，列数不齐补空，最多显示 2000 行并提示“仅显示前 2000 行，共 N 行”，引号未闭合时显示行号并可返回源码；
  - JSON 显示为默认展开两层的可折叠树，显示成员数，超过 200 个成员分批“再显示 200 项”，数字按源码原文显示，非法 JSON 显示“第 L 行第 C 列：JSON 语法错误”；
  - `.pdf` 且前 1024 字节内有 `%PDF-` 时识别为 PDF，打开即预览，渲染器、worker、CMap 与字体随应用打包、首次打开 PDF 时才加载，字节经认证请求读取；
  - 默认适应宽度，单行工具栏提供页码跳转、适应宽度、放大、缩小与下载，触摸设备双指缩放；
  - 只渲染可视区附近页面并释放远处画布，中文可显示并可选择复制，文档内链接跳页，HTTP(S)/mailto 在新标签页打开，脚本与表单不生效；
  - 超过 20 MiB 显示上限、大小与下载，受密码保护显示“PDF 受密码保护，请下载后查看”，损坏显示“PDF 无法解析”，均保留下载；
  - 切换文件或关闭标签时取消读取与渲染。
- **US-I18 查看会话临时文件夹**：作为让 agent 交付文件的使用者，我希望在代码工作区直接浏览本会话的临时文件夹，以便查看上传素材和 agent 生成的截图、报告而不让它们进入项目仓库。
  验收要点：
  - 导航顶部“工作区 / 临时文件夹”切换，默认工作区；
  - 切到临时文件夹时按需创建 `$TMPDIR` 下按实例与会话隔离、权限 0700 的文件夹并显示其路径；
  - 浏览、搜索、按路径打开、预览、下载与资源管理器文件操作（US-I19）同工作区，不跟随符号链接，不提供“修改”页签与 Diff；
  - 两个根的标签可并存并标明来源，变化检测同样生效；
  - 文件夹不可用时显示原因与重试，不以工作区内容替代；
  - 普通会话删除后文件夹删除，混合会话保留到记录删除，服务启动清扫无主文件夹。
- **US-I19 资源管理器文件操作**：作为在浏览器里整理工作区和 agent 产物的使用者，我希望在文件树上用右键菜单上传、下载、重命名、复制、剪切、粘贴和删除文件或文件夹，以便不回到终端敲命令也能管理文件。
  验收要点：
  - 文件树条目、根目录行与路径搜索结果支持右键、Shift+F10/菜单键、触屏长按（约 0.5 秒，移动即取消，不同时展开或打开条目，抬起手指不会误选弹出面板中的操作）和每行“⋯”（悬停或聚焦时显示，触屏常显）打开菜单；
  - 宽度不足 640px 时改为带条目名称与完整路径的底部操作面板，操作项与取消按钮满足触控尺寸，触屏与窄屏下树行加高；
  - 复制或剪切后显示剪贴板提示条，可直接粘贴到根目录或清除；
  - 重命名预选不含扩展名的文件名；
  - 文件可打开、下载，目录可下载为流式 ZIP（按“显示忽略项”决定是否含 Git 忽略文件，跳过 `.git`、嵌套仓库、符号链接与特殊文件）、上传到此目录、新建文件夹与粘贴；
  - 非根文件和目录可重命名、复制、剪切与删除，符号链接只可删除且不影响目标，根目录、嵌套仓库与特殊文件不可修改；
  - 工作区与临时文件夹都可写，但粘贴只限同一根，不能粘贴到自身或子目录，移动跨文件系统时报错；
  - 重名自动取最小可用的 ` (n)` 后缀并提示，从不覆盖已有条目；
  - 名称拒绝空名、`.`、`..`、`.git`、路径分隔符、控制字符与超过 255 字节；
  - 复制与 ZIP 合计不超过 100 MiB / 10000 项，上传单文件不超过 100 MiB，超限返回 413；
  - 上传与下载显示进度并可取消，上传失败或取消不留下半个文件；
  - 删除文件夹前显示条目数与总大小并确认，含 `.git` 或嵌套仓库时拒绝且不部分删除；
  - 操作后刷新目录，并关闭被删除、移走或改名文件的标签；
  - 根不可写时禁用写入项；
  - 沿用认证、Origin 检查与错误状态映射；
  - 可从系统把文件拖到代码工作区上传（主页面与独立窗口相同）：落在文件夹行上传到该文件夹，落在文件行上传到其所在文件夹，其他位置上传到当前根目录，拖动时高亮目标并提示，只读根、包含文件夹或已有上传进行时拒绝并提示。

## J. 仓库登记与 worktree 管理

- **US-J01 登记已有仓库**：作为使用者，我希望通过主仓库、worktree 或子目录登记已有 Git 仓库，以便集中管理项目的工作树。
  验收要点：
  - 同一仓库只登记一次；
  - 只登记可信的现有目录，不 init 或 clone；
  - 登记保存在服务端状态目录，重启后仍在；最多登记 500 个仓库，超出时拒绝并提示先移除不再使用的仓库。
- **US-J02 查看工作树状态**：作为使用者，我希望看到分支、路径和工作树可用性，以便选择正确的代码副本。
  验收要点：
  - 分支直接显示；路径、提交、类型与已跟踪文件干净状态收在“工作树详情”中，详情另有“分支与上游”“最近提交”“修改统计”三节（US-J15），“计算容量”按需统计目录占用（文件字节数与条目数，不跟随符号链接），超出预算时标注“未统计完整”，目录缺失时禁用；
  - 首页工作树分组的详情按钮、侧栏工作树行“⋯”菜单（`工作树操作：<名称>`）的“工作树详情…”打开同一个独立对话框（窄屏底部抽屉）；在仓库面板内则作为面板子视图打开，带“返回”，不叠第二层对话框；
  - bare、锁定及原因、待清理、有修改、未跟踪、不可用和未知/错误状态始终可见，bare 不可启动会话；
  - Git 读取慢时保留上次快照并继续显示读取中，只有真实失败才提示错误，单仓库失败不影响其他仓库或会话。
- **US-J03 选择主页工作树**：作为有大量工作树的使用者，我希望只把关注的工作树放到主页，以便降低总览噪声。
  验收要点：
  - 默认主工作区可见，新建 worktree 自动添加；
  - 可在侧栏仓库菜单“主页显示…”的列表按分支/路径搜索，勾选添加或取消勾选移出主页；
  - 有会话的工作树始终显示，未添加者有标记；
  - 选择保存到服务端并跨设备同步，409 按 ID 重放；
  - 只读展示过滤不自动保存；
  - 移出主页不删除工作树。 从侧栏仓库菜单的“主页显示…”进入，该操作不启动会话；对话框底部提供“批量管理…”快捷入口，与仓库菜单的“管理工作树…”一样打开仓库面板的“工作树”分区（US-J14）；侧栏收窄查看的工作树被删除后回退到所属仓库总览。
- **US-J04 为新任务创建分支工作树**：作为使用者，我希望选择起始分支及其最新上游提交来创建新分支与 worktree，以便隔离新任务的文件变更。
  验收要点：
  - 起始分支是带搜索的选择器，按分支最新提交时间从新到旧列出本地分支与远程跟踪分支（如 `origin/*`），默认是主工作区当前本地分支，可搜索并切换；选择本地分支后立即显示本地提交并异步 fetch 已配置上游，选择远程分支后立即显示其缓存提交并异步 fetch 对应远程，刷新成功后同步更新远程分支列表；
  - fetch 成功后，本地分支仅当本地是上游祖先时默认显示上游提交标题、远程来源和精确 OID（本地领先或分叉时保留本地提交）；远程分支直接使用刷新后的远程最新提交；
  - "起始提交"是下拉框，每行显示标题、短哈希、"本地最新"/"远程最新"标记和相对时间，列出该分支最近 50 条提交（起始提交超出上限时仍会列出），可直接选择更早的提交，不需要输入哈希；刷新上游后远程最新提交也进入列表（本地分叉时同样可选）；提交列表读取失败时仍可使用默认提交创建；
  - 刷新动画和手动“刷新上游”不阻塞编辑或创建；无上游、失败或超时保留本地基线并显示非阻断说明；
  - 分支切换、请求后的手动编辑、关闭面板或切换模式后，晚到响应不得覆盖较新的用户意图；
  - 提供避开已有分支和目录的建议名及“换一个”；
  - 默认放在仓库旁的 worktrees 目录，目录名取分支末段，可修改完整路径，不覆盖已有目录。
- **US-J05 检出现有分支**：作为使用者，我希望搜索并选择未被占用的本地分支创建 worktree，以便继续已有工作。
  验收要点：
  - “已有本地分支”是选择器：点击展开带搜索框的列表，按名称搜索和键盘选择，选定后收起并在选择器中显示分支名；
  - 已被其他工作树占用的分支禁选；
  - 不自动 fetch 远端分支；
  - 仓库面板“分支”分区中，未被任何工作树检出的本地分支和每个远程跟踪分支都有“在新工作树打开…”，点击先关闭面板再打开新建工作树弹窗，屏幕上只有一层，用户确认后才创建：
    - 本地分支：以“使用已有分支”模式选中该分支；
    - 远程分支：以“创建新分支”模式把它作为起始分支，新分支名默认取去掉远程名的短名（`origin/fix/b` → `fix/b`）；
    - 默认路径同样取分支末段；
  - 切换分支（US-J16）因未提交修改受阻，或用户不愿影响运行中的会话时，“改为在新工作树打开”以同样方式预填所选目标；预填只是初始值，之后的操作与普通新建相同。
- **US-J06 单独创建与保留工作树**：作为使用者，我希望工作树独立于会话存在，以便先准备环境或在任务结束后继续使用。
  验收要点：
  - 可只创建工作树；
  - 仅检出版本控制内容，不复制 `.env` 或安装依赖；
  - 启动失败、关闭会话或服务重启不会自动删目录和分支。 侧栏仓库菜单提供独立命名的“新建工作树…”；
  - 默认只创建，启动会话须显式勾选，未勾选时不要求启动命令。
- **US-J07 同一工作树多个会话**：作为使用者，我希望在同一 worktree 启动多个终端，以便同时运行 agent、测试或开发服务器。
  验收要点：
  - 多个 PTY 独立运行但共享同一份工作树文件；
  - 启动目录或其子目录可关联工作树；
  - 关联基于启动位置，不实时跟踪终端里的 `cd`。
- **US-J08 安全删除预览**：作为使用者，我希望删除 worktree 前看到受保护文件和关联会话，以便避免丢失工作。
  验收要点：
  - 安全删除拒绝未提交、未跟踪文件或活动会话；忽略文件只在预览中警告（删除后丢失），不阻止删除；
  - 主工作区、bare、locked、含子模块等目标受保护；未锁定且目录已缺失的 linked `prunable` 工作树可安全清理该失效 Git 登记（不波及未选中的其他 `prunable` 登记，执行前复核路径仍不存在），并回退在主仓库校验已记录的 HEAD 提交以继续保住关联归档会话；
  - 预览显示阻止原因、关联会话以及删除后将保留（并标为已释放，之后可重建恢复）的已归档混合会话、保存的提交与推送检查结果（未推送时警告但不阻止，规则同 US-J13）；detached 工作树只有存在被保留的记录（私有引用保护提交）时才不再提示“提交可能没有分支保护”；
  - 有效确认限时且目标或会话变化后需重新预览。
  - 新建会话对话框的位置列表中，每个 linked 工作树带有删除按钮，打开同一删除预览；删除成功后若其为当前选择则回退到主工作区。
  - 工作台侧栏每个工作树行的“⋯”菜单（`工作树操作：<名称>`）提供“工作树详情…”，linked 工作树另有“删除 worktree…”，打开同一删除预览：
    - 鼠标设备上悬停、聚焦该行或菜单展开时出现在行尾，触屏上持续显示；主工作区的菜单只有“工作树详情…”；
    - 删除对话框右下角提供绿色的“仅从主页隐藏”按钮，一步把工作树移出主页，不删除目录、分支与会话记录（有会话的工作树仍会显示）；已不在主页的工作树、以及随工作树一并删除已归档聊天的流程不提供该按钮。
- **US-J09 明确强制删除**：作为确实要丢弃任务的使用者，我希望在核对路径和相关会话后强制删除，以便清理不再需要的 worktree。
  验收要点：
  - 仅允许可强制删除的目标；
  - 无需输入路径，只须勾选关闭列出会话及删除全部内容的确认后点击确定；
  - 可能丢弃未提交及忽略文件；
  - 保留分支与已退出的普通会话；关闭列出的混合会话后其 shell 离开列表不阻止删除；
  - 安全或强制删除成功后，该目录下已关闭或已中断的混合会话记录（含强制删除时刚关闭的会话留下的）及其临时文件夹保留：
    - 记录与释放空间一样标为已释放（保存原路径、提交与分支，私有引用 `refs/webmux/released/<id>` 保住提交），出现在所属仓库“已不可用工作区”下；
    - 恢复前先确认在原路径重建 worktree（US-J13）；只保留提交，未提交、未跟踪与忽略文件仍随目录丢弃；
  - 删除前预览解析 HEAD 提交并存入确认，执行时提交变化则拒绝并要求重新预览；已释放的记录不被再次处理；
  - HEAD 无法解析（没有提交）时无法保存释放点：不阻止删除，记录保持原样（只能查看或手动删除，不能重建），预览与对话框明确说明；
  - 不能保证处理外部进程或终端 `cd` 后的归属。
- **US-J10 移除仓库登记**：作为使用者，我希望把不再关注的仓库从列表移除，以便整理项目清单。
  验收要点：
  - 确认后仅移除持久登记，不删目录或分支，不关闭会话；
  - 原会话仍可在直接会话中访问。
- **US-J11 局部失败时继续使用**：作为使用者，我希望一个仓库损坏、路径消失或 Git 不可用时仍能使用其他终端，以便局部环境问题不阻断全部工作。
  验收要点：
  - 单仓库失败保留错误和原会话入口；
  - Git 缺失或仓库存储不可用时禁用相关管理能力，直接目录终端仍可用；
  - 损坏清单不被静默覆盖。
- **US-J12 仓库初始化指令**：作为常在同一仓库开新任务的使用者，我希望给仓库保存一段可引用快捷指令的开场要求，并在快速开始时明确选择是否附带，以便不用每次手动粘贴。
  验收要点：
  - 首页工具栏的“⋯”菜单有“仓库设置…”（侧栏选中某个仓库，或只登记了一个仓库时显示），其中的“初始化指令”是一段多行模板，可修改或清空（留空保存即清除）；标题栏与添加仓库弹窗不再有指令入口；
  - 模板中的引用：
    - `{{快捷指令名称}}` 引用设置中的快捷指令；
    - 内置的 `{{user}}` 指定快速开始时你的第一条消息放在哪里（不写则接在指令后面）；
    - 内置的 `{{webmux}}` 在会话创建后换成 WebMux 工具说明（US-S06）；快速开始输入框里手写或由快捷指令菜单插入的 `{{dir}}`、`{{webmux}}` 同样在会话创建后替换（US-Q18），初始化指令展开后插入的用户输入已先替换，不会被再次扫描；
    - 设置页“可插入”列出可引用的名称与“用户输入”“WebMux 说明”按钮，可点击插入；引用不存在的名称时给出提示（不阻止保存）；
  - 最多 4000 个字符，超出时前端禁用提交，服务端拒绝并保留原指令；指令随仓库清单持久保存，服务重启后仍在，旧版清单缺字段视为没有指令；已保存的旧指令按纯文本继续可用；
  - 内置的 `{{dir}}` 换成新会话的临时文件夹路径，与 `{{user}}` 一样不能作为快捷指令名称；
  - 指令只作为快速开始首条消息的前缀（US-Q18）或新建会话对话框中“使用初始化指令”的内容（US-B01），不会被当作命令执行；`PATCH /api/repositories/{id}` 沿用认证与 Origin 校验。
- **US-J13 释放已归档工作树的空间**：作为任务结束后仍想保留聊天的使用者，我希望删除已归档聊天所在的 worktree 来回收磁盘，并在之后恢复聊天时把它重建回来，以便不必在“占着空间”和“永久删除”之间二选一。
  验收要点：
  - 侧栏聊天历史与首页“已归档”区中，位于可用 linked worktree 的未释放记录的菜单提供“释放空间”，以工作树为单位作用于其中全部已归档记录；主工作区、直接目录、worktree 已不存在或已释放的记录不提供；
  - 释放前预览列出阻止原因、将保留的已归档记录与保存的提交；不逐项列出将删除的忽略文件，存在忽略文件时只警告它们随目录永久删除且不可通过重建找回；未提交修改、未跟踪文件、运行中会话、锁定、子模块或嵌套仓库阻止释放，忽略文件不阻止，没有强制模式；
  - 释放以非强制方式删除 worktree，保留分支，用私有引用 `refs/webmux/released/<id>` 保住提交，记录标注“已释放空间”并保存原路径、提交与分支，重启后仍在；确认后目标变化时拒绝并要求重新预览，删除失败时撤销标记与引用；
  - 恢复已释放的记录（含侧栏点击）先二次确认重建：分支尖端仍为保存的提交且未被占用时检出该分支，否则以 detached 方式检出保存的提交并说明原因，原路径被占用或仓库不可用时不可确认；确认后先重建再恢复，取消不做改动；
  - 重建后同一次释放下的记录都回到普通已归档状态并删除私有引用；未经重建直接调用恢复接口返回 409；删除已释放的记录只删除记录，最后一条被删时同时删除私有引用；
  - 预览与确认对话框检查保存的提交是否已推送：只读本地远程跟踪引用（`git for-each-ref --contains`），不联网、不 fetch：
    - 结果为已推送（列出至多 5 个包含它的远程分支）、未推送（有远程但没有任何远程跟踪引用包含它）、未配置远程，或未知（没有提交，或检查失败、超时）；
    - 未推送时警告“该提交尚未推送到任何远程；仓库本地丢失或被清理后将无法重建，请先推送”，并注明以本地远程跟踪引用为准；只警告、不禁用确认；
    - 未配置远程与未知不提示。
- **US-J14 批量管理与清理工作树**：作为在单个仓库中积累了多个任务工作树的使用者，我希望在工作台一次查看全部工作树并批量清理不再需要的副本，以便不必把未放在主页的空闲工作树逐个重新勾选回主页再删除。
  验收要点：
  - 从侧栏仓库行“⋯”菜单的“管理工作树…”或“主页显示…”对话框底部的“批量管理…”打开当前仓库的仓库面板并停在“工作树”分区（桌面端居中对话框，窄屏 `< 640px` 底部抽屉）：
    - 按稳定顺序列出该仓库全部工作树（含未添加到主页的空闲工作树）；
    - 分区默认是浏览状态，点击行在面板内打开工作树详情子视图，选择“批量清理”后进入选择模式；
    - 批量预览或执行期间分区 Tabs 禁用；
  - 支持按分支、提交短哈希或路径搜索，按“全部 / 可安全清理 / 有阻塞 / 受保护”分段筛选，并提供“选中全部可安全清理”与“清空选择”；主工作区、bare、已锁定及状态未知的工作树禁选并说明原因，单次最多选择 50 个工作树；
  - 下一步请求服务端实时批量预览（`POST /api/repositories/{id}/worktrees/batch-removal-preview`，5 分钟有效，确认凭证与单项删除和释放空间隔离），分组展示可安全清理项、有阻塞项与不可删除项，并列出忽略文件警告、归档聊天保留情况与推送检查提示；
  - 默认仅安全删除无阻塞项（含清理未锁定缺失目录的 `prunable` 登记）并自动跳过受阻项；仅当显式勾选默认未选中的强制删除授权（同时确认 `includeForce` 与 `closeSessions`）后，才关闭受阻项列出的活动会话并强制删除受阻目录；预览时干净的项即使开启批量强制仍按安全模式复核，防止预览后产生的新修改被静默丢弃；
  - 本地分支始终保留；可解析提交的已归档混合会话记录（含强制删除刚关闭的聊天）转为“已释放空间”保留；
  - 批量执行（`POST /api/repositories/{id}/worktrees/batch-remove`）预先保留全部拟删路径以拦截并发会话创建，逐项复核身份与会话，单项失败仅记录为 `failed` 而不中断其余项；
  - 全部成功时分区回到刷新后的浏览列表并提示已删除数量，同时清理已删路径的草稿与主页固定项；存在失败项时停留在结果视图并保留失败项勾选以便重新预览重试；
  - 存在未锁定、目录已缺失且没有运行中会话的 `prunable` linked worktree 时，浏览状态显示“清理失效登记（N）”快捷入口，只预选这些条目并直接请求批量预览（US-J17），N 为 0 时不显示。
- **US-J15 查看仓库与工作树的同步详情**：作为同时在多个工作树里推进任务的使用者，我希望在一个仓库面板里看到每个工作树相对上游的领先/落后、最近提交和修改情况，以及仓库的分支与远程，以便不切到终端就能判断哪些分支需要推送、更新或清理。
  验收要点：
  - 侧栏仓库菜单的“仓库详情…”打开仓库面板（桌面对话框，窄屏底部抽屉），以下划线 Tabs 分为“概览”“工作树”“分支”“远程”；“管理工作树…”与“批量管理…”直接停在“工作树”分区；仓库不可用时只有“概览”，说明原因并保留“从列表移除仓库…”；
  - 概览显示路径（可复制）、Git 公共目录、默认分支（detached 时显示提交）、“主页 n / 共 m”、远程数、上次获取远程时间（近似值，从未获取显示“未知”）、会话统计与读取时间；打开面板时触发一次 Git 刷新，期间先显示上次快照并标出“正在重新读取状态…”，失败时保留快照并显示错误；
  - 每个工作树的同步状态全部在本机计算、不访问网络：上游名与领先/落后提交数，或“无上游”“上游已删除”“未计算”（差距过大跳过计算时），状态读取失败显示“未知”，从不把未知或未计算显示成 0/0 或“已同步”；detached 工作树不显示上游；
  - 工作树详情、面板工作树行和首页工作树标题显示最近提交（标题、作者、相对时间，尚无提交时显示“尚无提交”）、已暂存/未暂存/未跟踪/冲突计数，以及进行中的合并、变基、拣选、还原或二分（如“正在变基”）；首页标题只在有上游且未同步时用带可访问名称的箭头指示（如“领先上游 3 个提交”），或显示“上游已删除”；
  - “分支”分区列出本地分支（名称、短哈希、最近提交标题与时间、上游与领先/落后、占用它的工作树路径），远程跟踪分支在单独的折叠组；按名称搜索时两组都显示匹配数量；点击占用路径在面板内打开该工作树详情；
  - “远程”分区列出远程名称与 fetch/push URL（相同时只显示一次），可复制；URL 在服务端脱敏：带密码的 URL 只把密码换成 `***`，只有用户名的 `http(s)` URL 整个用户名换成 `***`，SSH 地址原样显示；没有远程时显示空状态；
  - 面板内的工作树行与侧栏、首页共用同一个“⋯”菜单，面板中的删除只通过“批量清理”完成；
  - `GET /api/repositories/{id}/remotes` 与仓库快照、分支接口的新增字段沿用认证与 Origin 校验；
  - CLI `webmux worktree ls/show`、`webmux repo show/branches` 输出相同的同步状态，`webmux repo remotes REPO [--json]` 列出脱敏后的远程。
- **US-J16 切换已有工作树的分支**：作为在同一个目录里换任务的使用者，我希望把已有工作树（含主工作区）原地切换到另一个分支或提交，并在切换前看清修改、运行会话与分支占用，以便不必新建工作树，也不会丢失未提交的内容。
  验收要点：
  - 首页工作树分组、侧栏工作树行与仓库面板工作树行的“⋯”菜单都有“切换分支…”；bare、不可用或待清理的工作树不显示。从首页或侧栏打开时桌面为对话框、窄屏为底部抽屉；从仓库面板的行菜单或工作树详情子视图（“切换分支…”按钮）打开时是面板内带“返回”的子视图，不叠第二层；
  - 分段控件选择“已有分支 / 新建分支 / 分离到提交”：
    - 已有分支是可搜索、分“本地”“远程”两组的列表；当前分支与已被其他工作树检出的分支标出原因后禁选，同名本地分支已存在的远程分支也禁选并提示改选本地分支；选择远程分支会新建同名本地分支并以它为上游；
    - 新建分支默认填入建议名（可“换一个”），起点默认是当前分支，不设置上游；
    - 分离模式从当前提交的最近历史中选择；
  - 每次选择都会自动请求服务端预览，较早选择的晚到结果被丢弃；预览展示“当前 → 目标”与目标提交，并逐条列出阻止原因（未提交的已跟踪修改、进行中的合并/变基等、目标已被其他工作树检出、目标与当前相同、状态无法验证）和警告（未跟踪文件、锁定、子模块）；
  - 有阻止原因时“切换”禁用：因修改或会话受阻时右下角提供绿色的“改为在新工作树打开”（US-J05），目标已被占用时提供“转到该工作树”（面板中切到其详情子视图，独立弹窗则关闭后打开其详情）；
  - 工作树或其子目录下有运行中的会话时列出会话，有 agent 正在工作时另行提示可能正在写文件，并要求勾选“我已了解”后才能切换；会话不会被关闭或重启，切换后继续运行并看到新分支的文件；
  - 确认 5 分钟内有效，仅用于切换；预览后会话集合、分支或目标提交变化时执行被拒（409），界面说明原因并自动重新预览；未跟踪文件会被目标覆盖时切换失败并列出路径（最多 50 条），工作树不变；
  - 系统不贮藏、不丢弃修改，也不使用强制或合并式切换；客户端断开不会中止 Git，失败或超时后以刷新后的实际状态为准；
  - 成功后重新读取仓库：独立弹窗关闭，面板子视图回到该工作树的详情；首页与侧栏标题更新为新分支，工作树 ID 与主页置顶不变；已打开的代码视图由现有变化检测（约 5 秒）把受影响的标签页标为“内容已更新”；
  - 接口为 `POST /api/repositories/{id}/worktrees/{worktreeId}/switch-preview` 与 `…/switch`，沿用认证与 Origin 校验；CLI `webmux worktree switch` 支持同样的四种目标（见 [Shell 控制](../usage/shell-control.md)）。
- **US-J17 获取远程并清理失效登记**：作为在终端外也会推进分支、偶尔手动删除工作树目录的使用者，我希望在仓库面板里获取全部远程并清理目录已不存在的工作树登记，以便面板里的领先/落后和工作树清单保持准确，而不用切到终端执行 `git fetch` 或 `git worktree prune`。
  验收要点：
  - 仓库面板标题栏常驻“获取远程”（tabler `cloud-download`，窄屏 `< 640px` 只显示图标并保留可访问名称与提示），各分区间不重复放置；仓库没有远程时禁用并说明“这个仓库没有配置远程，无法获取”，不可用仓库不显示；
  - 点击后按钮显示进行中并禁用，再次点击不重复发请求；服务端按名称逐个执行 `fetch --prune --recurse-submodules=no`，每个远程有独立时限、整体最多 3 分钟，客户端断开后仍完成，同一仓库同时只获取一次，重复请求得到同一结果，获取期间不阻塞浏览、创建、删除与切换；
  - 结果以提示框逐个列出在标题栏下方，直到关闭面板或再次获取：成功为“origin：已获取”，失败为认证失败、网络不可达、超时、远端拒绝或其他错误的说明；单个远程失败不影响其他远程，响应附带重新读取的仓库快照，面板与侧栏随之更新上次获取时间与领先/落后，“分支”分区重新读取；
  - 获取以非交互方式运行（不等待终端或图形凭据提示，未自定义 ssh 时加 `BatchMode=yes`），不修改 Git 或凭据配置；错误信息与远程清单同样脱敏（令牌换成 `***`，最多 200 字符），服务日志不记录 URL 与 Git 输出原文；
  - “工作树”分区的“清理失效登记（N）”只计入未锁定、目录已缺失、没有运行中会话的 `prunable` linked worktree，点击后进入批量预览，确认、归档记录保留与逐项结果沿用 US-J14，分支保留；被锁定的失效登记不计入、不预选，行内说明“已锁定，需在终端解锁后清理”；系统从不执行不区分条目的 `git worktree prune`；
  - `POST /api/repositories/{id}/fetch` 沿用认证与 Origin 校验，没有远程时 409；CLI `webmux repo fetch REPO [--json]` 逐行输出每个远程的结果（全部成功 0，否则 1），`webmux worktree prune REPO [--yes] [--json]` 筛出同样的失效登记并走批量预览与删除，确认规则与 `worktree rm` 相同。
