# 官方 Relay 部署与切换

本页说明从旧业务传输切换到受管 frp 的接入条件、就绪判断和维护顺序。配置宿主并配对见[官方 Relay 接入](remote-access.md#官方-relay)。
以下是配套版本的目标行为，不是生产部署或联合验收记录。

## 接入前提

1. 使用与控制面和数据节点匹配的签名 WebMux 发行物。Linux/macOS 的 amd64、arm64 安装件包含固定的 `frpc` v0.72.0；Windows 托盘连接 WSL 内安装的 Linux 宿主，Windows 侧不运行隧道进程。
2. 允许宿主解析 DNS，并直连控制面与已分配节点的出站 TCP/443。HTTPS 代理链须保留二进制 WebSocket Upgrade，端点证书与域名须可验证。基线不需要打开宿主入站端口、UDP 或 frp 原生端口。
3. 按[接入步骤](remote-access.md#官方-relay)配对并确认公网风险。默认控制入口为 `https://webmux-relay.rainbit.net`；自建服务从运营者取得准确的 `control_endpoint` 与 `control_audience`，不手填 connector 或 TURN 地址。

宿主访问公开控制 HTTPS 时使用系统 CA（可追加 RootCA）、域名、有效期和 TLS 1.3，不配置控制 SPKI。已认证分配的节点 WSS 强制校验端点证书与 pin。仅能走显式代理、Upgrade 被拒或端点证书被中间设备替换时，基线保持未就绪；没有明文 WS、原生 frp、UDP 或旧传输线路可降级。

TURN 是浏览器的可选交互优化，不是宿主 WSS 基线的前置条件。自营 TURN 的原监听、公布地址和授权不变：`3478/UDP`、`3478/TCP`、`5349/TCP`（TLS）及节点配置的 UDP 中继端口范围；不使用 `443/UDP`。

## 查看就绪与定位故障

- 在宿主的「连接诊断」、`webmux status --json` 或 `/local/v1/status` 查看管理和业务就绪。`controlReady` 代表当前已认证管理流和租约有效；`dataReady` 代表网关经当前 frp 工作连接和双向 TLS 验证了实际应用回源。两项都就绪时才提供可用的固定 HTTPS 链接。
- 控制台可登录、组件探针成功、`frpc` 已注册及 TURN 可用是不同层次的观察，不能代替应用回源验证。业务故障不影响有效的管理撤权，也不停止本机 PTY；管理断开立即撤销派生访问，未检测到的失联受 30 秒管理租约约束。
- 配置或发行物有误时使用原签名发行渠道修复；宿主不会在运行时下载、改用 `PATH` 中的 frpc 或放宽信任校验。诊断只显示脱敏原因，未知原因不从单个超时推断网络封锁。
- 控制消息签发有效期为 60 秒，管理心跳间隔为 10 秒；应保持节点和宿主时钟准确。保持分配的普通授权续期不重启长连接。业务回源失败不重放已发出的请求。
- 网关统一执行准入，64 个普通流中 bulk 至多 56，为交互留余量；每账号最多 128 个等待者，最长 15 秒。过载返回 `429` 与 `Retry-After`，离线返回 `503`，回源失败返回 `502`。

## 从旧 Relay 传输升级

1. 升级前删除宿主 TOML 的 `[relay].interactive_connections` 和 `[relay].bulk_connections`。新版本拒绝这两个已删除的键，不提供替代参数。保留现有 v3 绑定、独立机器 ID、宿主密钥和固定 HTTPS 地址；无需重新配对。
2. 在维护窗口停用旧公网入口与路由，撤销旧传输代际，核实旧连接关闭。保持入口关闭，安装配套宿主、控制面和节点版本，不按绑定分批切换或混合新旧业务实现。
3. 分别记录管理、组件、实际回源和真实 PTY 收发证据。验证 GitHub 登录、上传下载、转发、TURN/直连和撤权后再恢复公网入口。组件探针、HTTP 101 或成功部署镜像都不代表业务验收。
4. 需要回滚时先关闭整个公网入口与新签发，确认候选路由、连接、进程和注册均已清理。使用经验证的整版制品，以当前数据库的权限与撤销记录发起新代际；不恢复旧快照、旧令牌或旧路由。无法确认隔离或安全回滚时保持入口关闭。

临时 Relay 中断不停止本机终端；宿主服务重启仍遵循[常规升级的会话边界](install-and-upgrade.md#升级)。浏览器登录最长 12 小时，临时断线恢复须重新验证后台会话、邀请、所有者与绑定，保持原到期时间；宿主重启清空内存恢复记录。

## 节点与信息边界

控制面、数据节点和 PostgreSQL 隔离部署。节点经私网直连控制面并校验节点 CA、SPKI 与 mTLS；公开控制 CDN 不参与该信任。frps 只监听回环和受控私有端口范围；公网代理保留精确 Host、WebSocket Upgrade 和 Origin/CSRF 边界。TURN 可独立部署与恢复。

运营者使用配套私有仓库的 `DEPLOYMENT.md` 获取完整步骤、证书与秘密交付要求。公开文档不收录管理入口、节点私钥或传输凭据。Relay 会终止 TLS，并可接触转发内容；启用前阅读[安全边界](../../SECURITY.md#官方-relay)。
