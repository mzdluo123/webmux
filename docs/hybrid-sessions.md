# 混合会话（聊天 ↔ 终端）

混合会话让同一段 agent 对话在原生 TUI（终端视图）与聊天视图之间切换：原生 TUI 适合在电脑上精细操作，聊天视图适合在手机上阅读和回复。

最快上手：切到聊天模式，在快速开始页选好仓库与 agent 并发送首条任务；之后用会话页头部的“聊天 | 终端”控件来回切换。

- 支持 OpenCode、omp、Codex CLI、Claude Code、Antigravity CLI（`agy`）、Qoder 与 QoderCN。
- 切换前后是同一个 webmux 会话与同一个 agent 会话，历史由 agent 自己保存。
- Codex CLI 与 Claude Code 的聊天端需要在服务器上另外安装第三方连接器，见 [支持的 agent 与连接器](hybrid-sessions/agents.md)。
- 接口见 [混合会话协议](protocol/http-hybrid.md)。

## 怎么开启

新安装首次启动时预置的 OpenCode、omp、Codex CLI、Claude Code、Antigravity CLI、Qoder 与 QoderCN 配置已默认勾选 **“混合模式（聊天 ↔ 终端）”**，可通过以下两种方式直接开启：

| 方式                        | 怎么做                                                                                      | 从哪个视图开始                                    |
| --------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| 快速开始（聊天模式 `/new`） | 切到聊天模式，在快速开始页选择仓库、基准分支与支持混合会话的 agent，输入首条任务并发送      | 聊天视图；WebMux 自动创建独立 worktree            |
| 新建会话对话框              | 选择位置与开启了混合模式的启动配置，在两张单选卡片中选 **“从终端开始”** 或 **“从聊天开始”** | 默认终端；浏览器按每个 agent 分别记住上一次的选择 |

- 快速开始的首条任务可附带文件或勾选仓库初始化指令。
- 新建会话对话框也可直接填写首条 **“用户指令”** 与勾选 **“使用初始化指令”**。

为自定义或其他配置开启：

1. 在“设置 → 启动配置”中编辑配置，勾选 **“混合模式（聊天 ↔ 终端）”**。
2. 勾选框是否可用由服务端判定，不可用时旁边会显示原因；命令需满足 [启动命令兼容要求](hybrid-sessions/agents.md#启动命令兼容要求)。

已有安装的配置不会被自动改写。

## 切换

1. 在会话页头部的“聊天 | 终端”控件点击目标视图（窄屏只显示图标）。
2. 原窗格显示切换进度：
   - 切到聊天：依次为中断、退出、启动、加载历史；
   - 切到终端：依次为中断、退出、启动、连接终端，一直显示到新的 TUI 在本页输出第一屏内容（最多等 10 秒），终端不会先显示空白。
3. 切换完成后新窗格淡入。进度至少显示 0.4 秒；系统开启“减少动态效果”时不播放动画。

切换失败会自动回到原来的视图并显示原因。

切换期间所有设备的输入暂时禁用，已附着的原生终端以“已切换到聊天视图”断开。

### 切到聊天时 TUI 正忙

TUI 正在执行回合时，webmux 先发送中断键并等待空闲；10 秒仍未空闲时让你选择继续等待、强制切换或取消。

- 中断键：omp、Codex、Claude Code 与 Antigravity CLI 为一次 Esc；OpenCode 为两次相隔 150 毫秒的 Esc，一次写入的两个 Esc 会被当作 Alt+Esc。
- Codex 启动后的几秒内会报告“工作中”，这段时间不按回合处理。
- Claude Code 没有这段启动静默期，OSC 7501 应答后报告实际空闲或回合状态。
- Claude Code 的取消只中断当前回合，已经启动的后台 Bash 或子任务可能继续运行。
- 强制切换会终止连接器并等待其受管后代退出，但不保证清理任意自行 daemonize、已脱离受管进程树的程序。

### 切到终端时

- 正在运行的回合会被取消（页面会先确认）。
- 排队中尚未发送的消息合并后退回发起切换的设备的输入草稿，不会自动发给 TUI。
- 终端用恢复命令重新打开同一个 agent 会话（Claude Code 为 `claude --resume <ID>`，Antigravity CLI 为 `agy --conversation <ID>`）。
- 只保留模型、配置、批准方式等参数；提示词与 `--continue`/`--resume`/`--conversation`/`--settings` 等会话参数会在页面列出为“未保留”。
- Claude 的 `session/cancel` 不等于后台任务已清理。切换还会结束连接器并等待受管后代退出，自行脱离进程树的任务不在保证范围内。

### 切换按钮不可用的原因

切到聊天需要同时满足下表中的全部条件；不满足时目标端禁用并显示原因。

| 原因                                                                            | 怎么做                                                                                                                                             |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 没有识别出受支持的 agent                                                        | 用 [受支持的 agent](hybrid-sessions/agents.md#支持的-agent-与已验证版本) 启动会话，命令满足 [兼容要求](hybrid-sessions/agents.md#启动命令兼容要求) |
| 需要的第三方连接器未安装（Codex 的 codex-acp、Claude Code 的 claude-agent-acp） | 按 [连接器安装](hybrid-sessions/agents.md) 在服务器上安装，安装后 30 秒内自动重新检测                                                              |
| agent 不是会话 PTY 的根进程（从 shell 里再启动的）                              | 用启动配置直接启动 agent；Codex 与 Claude Code 也接受 npm 安装的 `node` 启动器直接拉起的原生 agent                                                 |
| 还没得到 agent 会话 ID：首条消息发出前 `session/list` 不包含可加载的会话        | 先在 TUI 中发出首条消息；由 webmux 切换或恢复打开的 TUI 沿用已恢复的会话 ID，不必先发消息                                                          |
| agent 的会话列表查不到它                                                        | 检查启动命令没有使用让两端看到不同会话库的参数，见 [兼容要求](hybrid-sessions/agents.md#启动命令兼容要求)                                          |
| 被另一个会话占用                                                                | 先结束占用它的会话；不要在 webmux 之外同时打开同一个 agent 会话（见 [注意事项](#注意事项)）                                                        |

- 读不到会话 ID 时按本次 TUI 启动后更新过的会话判定，有多个候选时让你选择。
- 各 agent 的会话 ID 来源、切换前的核对启动及 Claude Code 注册记录的验证规则见 [识别 agent 会话](hybrid-sessions/agents.md#识别-agent-会话)。

## 聊天视图

### 时间线

- 消息、思考、工具调用、计划、用量、压缩与提示按时间线显示。
- 两段 agent 回复（或用户输入）之间连续的思考与工具调用默认折叠为一行，折叠行显示最新一条调用及其进行中动画（等待授权的调用优先显示）和“共 N 步”，只有思考时显示“已思考”；点击展开后按顺序列出每条思考与每次调用，各自可再展开；diff 显示增删行数并可在代码面板查看。
- 点击 agent 消息中的代码位置链接，或工具调用中的文件位置 / 资源链接，会在当前会话的代码浏览器（或已弹出的独立代码窗口）中打开对应文件或目录并跳转到目标行。
  - 代码位置链接支持 `file://` URI、绝对或相对路径；
  - 支持 `#L10-L20`、`:10-20` 行范围与 `#标题` 片段。
- 权限请求与表单在输入框位置作答；多台设备同时打开时，第一个答复生效，其余设备随即看到结果。
- 手机与平板浏览器标签页中单窗格阅读聊天时（窗格宽度小于 1024px、代码栏关闭且未聚焦输入控件），时间线随整个页面滚动，上下滑动即可触发浏览器自动收起或展开地址栏与工具栏，顶栏与底部输入框保持贴边；点击输入框或打开代码栏、进入分屏、切回终端时自动切回固定视口壳层并保留当前阅读位置。

### 输入框与会话选项

- 输入框上方只读展示当前会话所属的仓库名称与 worktree 分支名（每次进入会话时刷新当前检出分支），直接目录会话不显示。
- 输入 `/` 打开命令菜单。
- 输入框下方一行是会话选项：权限与 agent 提供的配置项（模型、模式等）以图标显示。
  - 悬停提示、可访问名与菜单保留完整名称和当前值；宽度不足时横向滚动而不换行。
  - 窄屏（<640px）不显示这一行，改为上传按钮旁的“会话选项”按钮，点开弹层按 agent 实际提供的选项逐项列出（下拉或开关）。
  - OMP 的模型选项以完整的“提供商/模型”ID 显示，以区分不同提供商的同名模型。
- “权限”选择决定工具调用的授权方式：
  - “全部接受”（默认）：webmux 直接选择允许（优先“允许一次”，其次“始终允许”），不再提醒，时间线也不记录。
  - “每次询问”：逐个显示权限请求。
  - 从每次询问切到全部接受时，正在等待的权限请求也随即批准；没有允许选项的请求和表单仍需作答。
  - 该设置属于会话本身，所有设备共享，切换两端、重连与重启后恢复都会保留。
- 输入框右侧的圆环显示上下文已用比例；点击弹出 Token 使用情况：已用、上下文窗口、剩余 token 与本会话费用（agent 报告时）。

### 排队与插话

- 回合进行中继续发送会进入服务端队列，所有设备共享；`webmux send` 在标准错误报告队列项与位置，标准输出保持为空。
- `webmux send --mode` 可选择 `auto`（默认）、`steer`（插话）、`refuse`（忙时以 1 结束、不排队）或 `now`（取消当前回合后立即发送）。
- 队列可编辑、上移、删除或立即发送。
- 回合被停止或出错时队列暂停，可选择继续或清空。
- omp、Codex 与 Claude Code 还支持“插话”：输入文字后按 Ctrl/Cmd+Enter 注入当前回合（没有单独按钮）。
- 回合进行中、输入框没有文字与附件时，发送键变为停止键，点击即停止当前回合。
- 插话到达时回合恰好结束的，这条消息排到队首作为下一回合发送。

### 附件

- 添加方式：输入框左侧的回形针、拖放到聊天视图或粘贴文件 / 图片，可多选；走与终端相同的上传接口。
- 上传中显示文件名、序号与百分比并可取消。
- 完成后以可移除的 chip 显示在输入框上方（图片附件显示缩略小图与文件名），不改动草稿文本。
- 上传与待发送附件属于会话页，切换两端不会中断或丢失；刷新页面后未发送的附件不保留。
- 发送方式取决于 agent 声明的能力，附件不会静默丢弃：
  - 图片在 agent 声明 `promptCapabilities.image` 时作为原生图片块发送；
  - 其他文件在声明 `embeddedContext` 时作为嵌入资源发送；
  - 不支持时按服务器路径发送，并在时间线提示降级。
- 发送后的用户消息气泡中，图片附件同样显示缩略小图与文件名（无法加载时回退为图片图标）。
- 附件不写入混合会话记录，重启后仅保留上传临时目录的既有清理策略。

### 快捷指令

- 聊天视图的快捷指令（⚡）位于输入框底部、发送按钮左侧。聊天视图没有底部软键栏，顶栏不再显示该入口。
- 菜单标题为“插入消息”，选择指令只把正文插入输入框光标处，不论是否设置了回车都不自动发送。
- 正文含 `{{dir}}` 或 `{{webmux}}` 的指令（如系统预设“WebMux 工具”）会先确保临时文件夹存在，再替换为真实路径或 WebMux 工具说明。

### 登录、提醒与首页卡片

- agent 需要登录时，回合以错误结束并显示“切到终端登录”；聊天视图不执行登录流程。
- 会话卡片与 Web Push 沿用现有的提醒：等待授权、需要回答、本轮完成与出错停止。
- 聊天端回合进行中，首页卡片在最新消息上方显示一行当前工作；等待授权时仍显示（工具尚未执行），回合结束后消失：
  - 优先显示当前进行中的工具调用标题，本轮工具调用刚完成而尚无新工具时保留最近完成的工具调用；
  - 工具没有标题时按种类与首个位置显示（如“编辑 /repo/main.go”）；
  - 本轮尚无工具调用时显示计划中进行中的步骤。

### agent 进程常驻

- 聊天端会话保持 agent 进程常驻，不会因空闲自动休眠，因此 agent 内部的后台命令、子任务与定时任务不会在空闲期间被中止。
- 仅在切换到终端端、显式归档会话或服务停止时结束该进程。

## 关闭、中断与恢复

在会话页、首页卡片或侧栏菜单选择“停止会话并归档”并确认后，agent 进程停止，会话变为已归档记录：

- 位置：首页所属工作树（无仓库时为“直接会话”中的目录分组）活动会话下方的“已归档”，默认折叠并显示数量。
- 归档之后：单窗格会话页自动返回首页，“已归档”保持折叠，不自动展开或定位；分屏时只移除该窗格。从侧边栏或列表归档正在页面中打开的会话时同样如此，不会再显示“可以恢复到聊天或终端”的横幅；只有打开已归档会话的页面（例如恢复失败后）才显示该横幅。普通终端由用户手动关闭时直接移除，不保留“已退出”记录。
- 已中断：TUI 自行退出（包括 `/exit` 与崩溃）、ACP 进程反复崩溃或切换回滚失败时，会话标记为“已中断”。服务重启时仍在运行的会话会自动恢复到原所在端；只有无法自动恢复（工作树已释放空间、启动配置已删除、原 agent 会话不存在等）的才保持“已中断”。用户手动归档的会话不会自动恢复。
  - 已中断的会话同样出现在“已归档”中，折叠标题另外标出已中断条数。
- 操作：每条记录可“恢复到聊天”“恢复到终端”，或在更多菜单中选“删除记录”或“删除记录和工作树”。
  - “删除记录”只删除记录，工作树保持不变；
  - 关联的 linked worktree 仍可删除时，菜单还提供“删除记录和工作树”：先打开删除 worktree 确认流程并列出将删除的聊天，成功删除工作树后再删除该记录；
  - 若工作树已不存在、位于主工作区或属于直接目录，确认后只删除 webmux 的记录与本机草稿，不删除 agent 的会话。
- 查找：首页搜索与“已归档”状态筛选同样作用于这些记录。

恢复时的特殊情况：

- 原 agent 会话已不存在时，页面列出同一目录下的其他会话供选择。
- 启动配置已被删除时，确认后用原命令恢复，但不再带有配置保存的环境变量。
- 服务重启后队列丢失，恢复后的页面会提示丢失的条数；浏览器中的草稿不受影响。

## 命令行

命令行只用会话 ID 操作，不必先判断会话种类或所在视图：输入、中断、切换、恢复与清理由服务端按当前视图分派。

- `webmux run --launch-config <名称>` 引用混合配置时创建混合会话，默认从终端开始；`--view chat` 从聊天开始。
- `webmux view <ID> terminal|chat` 切换视图，`webmux resume <ID>` 恢复已归档会话。

全部命令与选项见 [用脚本和 agent 控制 WebMux](usage/shell-control.md#视图聊天与已归档会话)，完整用法以 `webmux <命令> --help` 为准。

## 注意事项

> [!WARNING]
> **不要在 webmux 之外同时打开同一个 agent 会话。** webmux 保证自己启动的进程不会同时打开它，但无法保证察觉所有外部进程。

- omp 在会话被另一进程占用时写入会把它分叉成新会话。
- Codex 拒绝打开被其他 Codex 客户端（Codex App、IDE、外部终端）占用的会话：切换会回到终端端、恢复返回错误，页面提示“该会话正被另一个 Agent 客户端使用”。
- Claude Code 允许两个 TUI 注册同一 UUID，webmux 依据有效注册记录尽力返回 `occupied_external`。
  - 配置目录不可读、记录不完整或外部客户端不在可验证记录中时，仍可能漏检，不能据此承诺没有外部写者。
  - 注册记录的读取范围、上限与隐私边界见 [会话识别与占用检测](hybrid-sessions/agents.md#会话识别与占用检测)。

其他限制：

- OpenCode 的 TUI 在混合会话中以 `--standalone` 运行，Codex 以 `--no-daemon` 运行（命令中可见），结束 TUI 即停止它的回合。
  - 代价是启动稍慢，并且看不到后台服务中其他客户端的实时事件。
- 记录保存在 `<state_dir>/hybrid-sessions.json`（0600），不含环境变量值、消息、队列或 token；最多 200 条，已满时新建会话先淘汰最近未更新的已关闭或已中断记录，运行中的记录不会被淘汰；淘汰会一并清理该记录的临时文件夹与不再被其它记录共享的释放引用。
  - 文件损坏或被另一实例锁定时只禁用混合会话的创建与恢复。

> [!WARNING]
> **回退到旧版本之前，先关闭混合会话并取消所有启动配置的混合勾选。**
> 旧版本严格读取 `launch-configs.json`，遇到勾选过的配置会报告文件损坏并使启动配置不可用；旧版本会忽略 `hybrid-sessions.json`。
