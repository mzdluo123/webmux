# 混合会话（聊天 ↔ 终端）

混合会话让 OpenCode 或 omp 的同一段对话在两种界面之间切换：原生 TUI（终端端）适合在电脑上精细操作，聊天视图适合在手机上阅读和回复。切换前后是同一个 webmux 会话与同一个 agent 会话，历史由 agent 自己保存。接口见 [混合会话协议](protocol/http-hybrid.md)。

## 开启

1. 新安装首次启动时预置的 OpenCode 与 omp 配置已勾选 **“混合模式（聊天 ↔ 终端）”**，可直接选用。其他配置在“设置 → 启动配置”编辑并勾选；勾选框是否可用由服务端判定，不可用时旁边会显示原因。已有安装的配置不会被自动改写。
2. 新建会话时选择这条配置，再选择“从终端开始”或“从聊天开始”（默认终端，按浏览器记住上一次的选择）。

能开启混合模式的命令：

- 直接执行 `opencode …` / `omp …`，或用“加载 ~/.bashrc”保存的包装；其他 shell 包装与 `env` 前缀不受支持。
- 不能在命令里指定工作目录（OpenCode 的位置参数、omp 的 `--cwd`），请在新建会话时选择目录。
- 不能使用让两端看到不同会话库的参数（omp 的 `--session-dir`、`--no-session`，OpenCode 的 `--server`），也不能使用不启动交互界面的参数（`-p`/`--print`、`--version`、子命令等）。

已验证的版本为 OpenCode 2.1.4（2.2.0 参数相同）与 omp 18.13.1；更低版本只在聊天视图显示提示，不阻止切换。

## 切换

会话页头部的“聊天 | 终端”控件用于切换，窄屏只显示图标。

**切到聊天**需要同时满足：识别出受支持的 agent；它是会话 PTY 的根进程（不是从 shell 里再启动的）；已得到 agent 会话 ID（OpenCode 与 omp 都要在发出首条消息后才把会话写盘；由 webmux 切换或恢复打开的 TUI 直接沿用它恢复的会话 ID，不必先发消息就能切回）；agent 的会话列表能查到它；没有被另一个会话占用。不满足时目标端禁用并显示原因。为了核对，webmux 会短暂启动一次 agent 只列出会话（omp 每次启动会写 presence 文件并可能检查更新，OpenCode 会拉起私有服务），只在会话 ID 变化后与切换前进行。

TUI 正在执行回合时，webmux 先发送中断键（omp 为 Esc；OpenCode 为两次相隔 150 毫秒的 Esc，一次写入的两个 Esc 会被当作 Alt+Esc）并等待空闲；10 秒仍未空闲时让你选择继续等待、强制切换或取消。切换期间所有设备的输入暂时禁用，已附着的原生终端以“已切换到聊天视图”断开。

**切到终端**时，正在运行的回合会被取消（页面会先确认）；排队中尚未发送的消息合并后退回发起切换的设备的输入草稿，不会自动发给 TUI。终端用恢复命令重新打开同一个 agent 会话：只保留模型、配置、批准方式等参数，提示词与 `--continue`/`--resume` 等会话参数会在页面列出为“未保留”。

两个方向的切换都在原窗格显示进度：切到聊天依次为中断、退出、启动、加载历史；切到终端依次为中断、退出、启动、连接终端，进度一直显示到新的 TUI 在本页输出第一屏内容（最多等 10 秒），终端不会先显示空白。进度至少显示 0.4 秒，切换完成后新窗格淡入；系统开启“减少动态效果”时不播放动画。

切换失败会自动回到原来的一端并显示原因。

## 聊天视图

- 消息、思考（默认折叠）、工具调用（可展开，连续的读取与搜索合并为“已浏览 N 项”，diff 显示增删行数并可在代码面板查看）、计划、用量、压缩与提示按时间线显示。
- 权限请求与表单在输入框位置作答；多台设备同时打开时，第一个答复生效，其余设备随即看到结果。
- 输入框下方是 agent 提供的配置项（模型、模式等），输入 `/` 打开命令菜单。
- 输入框下方一行是会话选项：权限与 agent 的配置项（模型、模式等），窄屏时自动换行；其中“权限”选择决定工具调用的授权方式：“自动批准”（默认）由 webmux 直接选择允许（优先“允许一次”，其次“始终允许”），不再提醒，时间线以“已自动批准”提示记录；“每次询问”逐个显示权限请求；从每次询问切到自动批准时，正在等待的权限请求也随即批准。没有允许选项的请求和表单仍需作答。该设置属于会话本身，所有设备共享，切换两端、休眠唤醒与重启后恢复都会保留。
- 输入框右侧的圆环显示上下文已用比例；点击弹出 Token 使用情况：已用、上下文窗口、剩余 token 与本会话费用（agent 报告时）。
- 回合进行中继续发送会进入服务端队列，所有设备共享；队列可编辑、上移、删除或立即发送。回合被停止或出错时队列暂停，可选择继续或清空。omp 还支持“插话”，把文字注入当前回合。
- 输入框左侧的回形针、拖放到聊天视图或粘贴文件 / 图片会走与终端相同的上传接口，可多选；上传中显示文件名、序号与百分比并可取消，完成后以可移除的 chip 显示在输入框上方，不改动草稿文本。上传与待发送附件属于会话页，切换两端不会中断或丢失，刷新页面后未发送的附件不保留。
- 图片在 agent 声明 `promptCapabilities.image` 时作为原生图片块发送，其他文件在声明 `embeddedContext` 时作为嵌入资源发送；不支持时按服务器路径发送并在时间线提示降级，附件不会静默丢弃。附件不写入混合会话记录，重启后仅保留上传临时目录的既有清理策略。
- agent 需要登录时，回合以错误结束并显示“切到终端登录”；聊天视图不执行登录流程。
- 会话卡片与 Web Push 沿用现有的提醒：等待授权、需要回答、本轮完成与出错停止。

聊天端空闲一段时间（没有回合、待答复请求与排队消息）后，webmux 结束 agent 进程以节省资源，打开会话或发送消息时自动唤醒；时长在“设置 → 启动配置”中调整，默认 30 分钟，0 表示不休眠，在设备间同步。

## 关闭、中断与恢复

关闭混合会话后，它出现在首页底部的“可恢复”分组（默认折叠）。服务重启、TUI 自行退出（包括 `/exit` 与崩溃）、ACP 进程反复崩溃或切换回滚失败时，会话标记为“已中断”，同样可以恢复。每条记录可“恢复到聊天”“恢复到终端”或确认后移除；移除只删除 webmux 的记录与本机草稿，不删除 agent 的会话。

- 恢复时若原 agent 会话已不存在，页面列出同一目录下的其他会话供选择。
- 启动配置已被删除时，确认后用原命令恢复，但不再带有配置保存的环境变量。
- 服务重启后队列丢失，恢复后的页面会提示丢失的条数；浏览器中的草稿不受影响。

## 命令行

- `webmux run --launch-config <名称>` 引用混合配置时创建混合会话，从终端开始；本地终端可以照常输入，但切换只能在 Web 端发起。
- `webmux attach <ID>` 在会话处于聊天端、休眠或切换中时拒绝附着，以退出码 1 结束；附着期间被切到聊天视为被动分离，恢复终端、提示后以 0 结束。切回终端后需重新 `attach`。
- `webmux ls` 在状态列附加所在端（终端、聊天、聊天·休眠、切换中），`--json` 原样包含 `hybrid` 对象。

## 注意事项

- **不要在 webmux 之外同时打开同一个 agent 会话。** webmux 保证自己启动的进程不会同时打开它，但无法察觉外部进程；omp 在会话被另一进程占用时写入会把它分叉成新会话。
- OpenCode 的 TUI 在混合会话中以 `--standalone` 运行（命令中可见），结束 TUI 即停止它的回合；代价是启动稍慢，并且看不到后台服务中其他客户端的实时事件。
- 记录保存在 `<state_dir>/hybrid-sessions.json`（0600），不含环境变量值、消息、队列或 token；文件损坏或被另一实例锁定时只禁用混合会话的创建与恢复。
- **回退到旧版本之前，先关闭混合会话并取消所有启动配置的混合勾选。** 旧版本严格读取 `launch-configs.json`，遇到勾选过的配置会报告文件损坏并使启动配置不可用；旧版本会忽略 `hybrid-sessions.json`。
