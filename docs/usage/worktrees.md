# 仓库与 worktree

把仓库登记到 WebMux 后，可以为每个任务新建独立的 Git worktree，让多个 agent 并行工作而互不干扰；任务结束后删除 worktree，或释放空间但保留聊天记录，之后需要时再重建。

最快路径：

1. 点侧栏底部的「添加仓库」，填写服务器上已有仓库的路径。
2. 在仓库行点「⋯」选「新建工作树…」（或仓库标题栏的「新建工作树」），填写分支名并确认。
3. 在新工作树里新建会话，或在 [聊天模式](chat.md) 的快速开始页直接发任务（会自动新建 worktree）。

需要系统安装 Git；没有 Git 时终端功能不受影响。

> [!WARNING]
> 添加的仓库必须可信：Git 会按仓库配置执行 hooks 和 filters。

## 登记仓库

- **添加仓库**只登记已有仓库，不会 clone 或 init。登记信息在服务重启后保留。
- **从列表移除仓库**只移除登记，不删除目录或分支。
- **关闭会话**不会删除工作树。

## 新建工作树

在仓库标题栏点「新建工作树」。默认只创建工作树，可创建新分支或检出未被占用的本地分支。

- **位置**：默认在仓库旁的 `<仓库名>.worktrees/<分支名末段>`。
- **不会**复制 `.env` 或安装依赖。
- **创建后启动会话**：勾选后才显示命令并启动；不勾选时不要求启动配置。
- 同一工作树可新建多个会话，它们**共享同一份文件**。

### 选择起点

创建新分支时选择“起始分支”（可搜索列表，按最近提交时间从新到旧列出本地分支与远程分支，如 `origin/*`），默认是主工作区当前本地分支。

- 选择本地分支后异步 fetch 其已配置上游。仅当本地尖端是上游提交的祖先时，默认使用上游最新提交的精确 OID；本地领先或分叉时保留本地提交；无上游或刷新失败时也保留本地基线。
- 选择远程分支后异步 fetch 对应远程，并以该远程分支的最新提交作为默认基线；刷新成功后也会同步更新可选的远程分支列表。
- 使用已有分支时不自动 fetch，也不会改用其上游提交。

“起始提交”下拉框列出所选分支最近 50 条提交（超出上限的起始提交仍会列出），无需输入提交 ID：

- 每行先显示提交标题，下方是短哈希、“本地最新”/“远程最新”标记和相对时间。
- 点「刷新上游」会 fetch 并把上游最新提交合并进列表；默认仍保留本地提交时，也可直接选择远程最新。
- 刷新动画不阻塞字段编辑或创建；刷新期间确认创建会使用当前可见基线。
- 切换分支或手动选择其他提交后，晚到响应不会覆盖较新的选择。

## 清理工作树：三种方式怎么选

| 方式         | 入口                               | 目录 | 分支 | 已归档聊天               | 前提                                   |
| ------------ | ---------------------------------- | ---- | ---- | ------------------------ | -------------------------------------- |
| **释放空间** | 已归档聊天的“⋯”菜单「释放空间」    | 删除 | 保留 | 保留，标为已释放，可重建 | 没有未提交修改、未跟踪文件或运行中会话 |
| **安全删除** | 工作树菜单「删除」                 | 删除 | 保留 | 保留，标为已释放，可重建 | 没有未提交修改、未跟踪文件或活动会话   |
| **强制删除** | 安全删除被阻止时，在预览中勾选确认 | 删除 | 保留 | 保留，标为已释放，可重建 | 勾选关闭列出的会话并确认丢弃全部内容   |

三种方式都**只保留提交**：未提交修改、未跟踪文件与忽略文件（如 `.env`、`node_modules`）随目录永久删除，重建也找不回。

> [!CAUTION]
> 强制删除会关闭列出的会话，并永久丢弃目录中的全部内容（包括 `.env` 和未提交修改）。

### 释放空间

任务结束后想回收磁盘、又想保留聊天以便之后继续时用它。

1. 在侧栏聊天历史或首页“已归档”区，打开已归档聊天的“⋯”菜单，选「释放空间」。
2. 预览列出阻止原因、将保留的已归档记录、保存的提交与推送检查结果；确认。
3. worktree 目录被删除，该工作树下的全部已归档记录标为已释放（侧栏显示空心三角形）。

- 只对位于可用 linked worktree、尚未释放的记录提供；主工作区、直接目录、worktree 已不存在的记录不提供。
- 释放以工作树为单位，作用于其中全部已归档记录。
- 阻止释放：未提交修改、未跟踪文件、运行中会话、锁定、子模块或嵌套仓库。没有强制模式。
- 忽略文件不阻止释放，预览不逐项列出，只警告它们随目录永久删除。
- 提交由私有引用 `refs/webmux/released/<id>` 保住；记录保存原路径、提交与分支，服务重启后仍在。
- 确认后目标发生变化时拒绝并要求重新预览；删除失败时撤销标记与引用。

### 删除 worktree

在工作树菜单（或新建会话对话框位置列表中 linked 工作树旁的删除按钮）选「删除」，先看预览再确认。

- **安全删除**拒绝存在未提交修改、未跟踪文件或活动会话的工作树。忽略文件只在预览中警告（删除后丢失），不阻止删除。未锁定且目录已缺失的 `prunable` 登记也可安全清理，且不影响未选中的其他工作树。
- 主工作区、bare、locked 及含子模块的工作树不能通过页面删除。
- 预览列出该目录下已归档（已关闭或已中断）的混合会话。删除成功后，这些记录（强制删除时关闭的会话留下的也一样）保留并标为已释放，出现在仓库的“已不可用工作区”。
- 预览确认有时效；目标、会话或 HEAD 提交变化后需重新预览。
- HEAD 无法解析（例如还没有提交）时无法保存提交：不阻止删除，记录保持原样，只能查看或手动删除，不能重建。
- 删除成功后，若它是新建会话对话框的当前选择，则回退到主工作区。

### 批量管理与清理

当仓库累积了多份工作树（包括取消勾选“主页显示”后隐藏的空闲工作树），可从仓库标题栏「管理工作树」、“主页显示”底部的「批量管理…」或侧栏仓库行「⋯」菜单的「管理工作树…」一次查看并清理：

- 弹窗列出该仓库全部工作树，支持搜索、按「全部 / 可安全清理 / 有阻塞 / 受保护」筛选，以及「选中全部可安全清理」（单次最多 50 个）。
- 预览默认**只安全删除无阻塞项并跳过受阻项**；仅当显式勾选强制删除授权后，才会关闭受阻项列出的活动会话并强制删除受阻目录。
- 本地分支始终保留；可解析提交的已归档聊天同样转为已释放。单项状态变化或失败不会中断其余项，失败项会保留勾选以便重新预览重试。

### 重建并恢复

点已释放的记录（侧栏或“已不可用工作区”），先确认在原路径重建 worktree，再恢复聊天：

- 分支尖端仍是保存的提交且未被占用时，检出该分支；否则以 detached 方式检出保存的提交，并说明原因。
- 原路径被占用或仓库不可用时不可确认。取消则不做任何改动。
- 重建后，同一次释放下的记录都回到普通已归档状态，私有引用被删除。
- 删除已释放的记录只删除记录；最后一条被删时同时删除私有引用。

### 推送检查

释放空间与删除的预览都会检查要保留的提交是否已推送。它只读本地远程跟踪引用，不联网、不 fetch：

| 结果       | 显示                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 已推送     | 列出至多 5 个包含该提交的远程分支                                    |
| 未推送     | 警告：仓库本地丢失或被清理后将无法重建，请先推送；只警告，不阻止确认 |
| 未配置远程 | 不提示                                                               |
| 未知       | 没有提交，或检查失败、超时                                           |
