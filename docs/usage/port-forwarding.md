# 端口转发预览

在 WebMux 里开发 Web 应用时，开发服务器（例如 `pnpm dev` 启动的 Vite）通常只监听服务器本机的 `127.0.0.1:5173`。端口转发把它经 WebMux 现有的地址转发到你的浏览器：不新开端口，本机、局域网、Tailscale 与 Cloudflare Tunnel 下都能用。

## 添加转发

- **终端页提示**：会话中的程序开始监听端口后，终端上方会在 3 秒内出现“检测到端口 5173（node）正在监听”，可选择：
  - “转发并打开”：添加转发并在新标签页打开；
  - “转发”：只添加转发，提示变为“端口 5173 已转发到 /forward/5173/”，可打开、复制链接或关闭提示；
  - “忽略”：当前标签页不再提示该端口，直到它停止监听后再次监听。
  - 同时有多个端口时最多显示两条，其余合并为“另有 N 个端口”，点击“查看全部”打开转发对话框。
- **首页“端口转发”按钮**：顶栏“新建会话”右侧的按钮（有转发时显示数量）打开转发对话框，可以手动输入端口添加，也可以从“检测到的端口”中一键转发。

转发地址是 `/forward/{端口}/`，例如 `https://你的主机/forward/5173/`。从对话框复制的链接可以在同一浏览器的新标签页直接打开：浏览器还没有转发凭据时，会先经过 `/forward-auth` 自动认证再回到原地址；没有登录 WebMux 的浏览器会先显示 Token 登录。

转发只保存在服务端内存中：手动移除或服务重启后消失。它与会话无关，会话退出后转发仍然保留。

## 让开发服务器在子路径下工作

网关不改写页面内容，使用绝对路径的应用需要把 base 设为转发前缀，并保留默认的“保留前缀”模式：

```sh
# Vite
pnpm vite --base /forward/5173/
# Next.js：next.config.js 中设置 basePath: "/forward/3000"
```

只使用相对路径的服务（例如 `python3 -m http.server`）可以在转发设置中把路径前缀改为“去除前缀”，不需要改配置。

默认开启的兼容选项让 Vite 等开发服务器开箱可用：

- 改写 Host：上游看到 `localhost:5173`，满足 Vite 默认的 `server.allowedHosts`；
- 改写 Origin/Referer：HMR WebSocket 通过 Vite 的来源检查；
- 添加 `X-Forwarded-*`：需要知道外部地址的框架可以读取；
- 改写重定向和 Cookie：指向 `localhost:5173` 的跳转回到转发地址，Cookie 限定在转发路径下。

每个选项都可以在转发的“设置”中关闭，修改只影响之后的新请求。

## 状态与平台

- 转发行显示“可访问”或“无法连接”，每 3 秒检查一次本机端口。开发服务器没有运行时，打开转发地址显示 502 和端口说明。
- 端口检测支持 Linux 与 macOS，只统计会话进程树中监听在回环或通配地址上的 TCP 端口，不含 WebMux 自身端口。其他平台不显示终端提示，对话框中显示“当前平台不支持自动检测”，仍可手动添加。
- 只能转发服务器本机的端口，不能转发其他主机或 Docker 容器网络命名空间里的端口。

## 安全提示

- 转发页面与 WebMux 同源，页面里的脚本可以读取浏览器中保存的 WebMux Token。只转发你信任的开发服务器，注意页面加载的第三方脚本。
- 转发使用专用 Cookie `webmux_forward`，它独立于 Token，只能访问 `/forward/`，不能操作终端，12 小时后过期。
- 协议细节见 [端口转发 API](../protocol/http-forward.md)。
