# Git 工作台

Git 工作台是独立于终端与混合会话的完整 Git 审阅与交付界面：即使没有任何运行中的会话，也可以直接在桌面或手机浏览器中查看多分支历史图、比较任意提交、按文件或代码块（Hunk）操作真实 Git `index`、固定审阅整个任务的净改动、核对推送预览，或把代码审阅意见安全交回指定会话继续返工。

最快路径：

1. **从会话直接进入**：在会话页打开「代码」，点右上角「在 Git 中查看」，直达该工作树的 `/git/{repositoryId}/worktrees/{worktreeId}`；审完点顶栏「返回会话」，原会话的终端/聊天视图、未发送草稿与代码标签原样恢复。
2. **不启动会话直接进入**：在侧栏仓库行「⋯」、工作树行「⋯」或仓库详情面板右上角点「Git 工作台」（工作树有未提交改动时还可点「提交改动…」直达提交视图）。
3. **完成审阅或交付**：在「提交 (Commit)」中逐块暂存并预览提交，或切到「相对任务起点的变化」审阅任务全量净差异；需要 agent 返工时，点选 Diff 行号加入「返工意见草稿箱」，显式选定目标会话草稿框发送。

## 入口模式与顶栏语义

Git 工作台按 URL 区分只读仓库与可写工作树，并把“当前操作哪份工作树”与“正在过滤哪条分支历史”严格拆开：

| 路由                                         | 模式         | 允许的操作                                                             |
| -------------------------------------------- | ------------ | ---------------------------------------------------------------------- |
| `/git/{repositoryId}`                        | 只读仓库模式 | 浏览多分支拓扑历史、比较任意提交、查看分支与占用状态；不修改任何工作区 |
| `/git/{repositoryId}/worktrees/{worktreeId}` | 工作树模式   | 历史浏览 + 真实 `index` 暂存、提交、任务净变更审阅、分支同步与会话交回 |

- **顶栏左侧**固定展示仓库切换器、工作树切换器与当前检出分支/`HEAD` 状态（如 `当前检出：feat/x`、`游离 HEAD`、`未诞生 HEAD` 或 `只读仓库`）。
- **浏览筛选不切分支**：在历史视图点击任一分支或标签只会加上「历史筛选：…」徽标并过滤列表，**绝不会**后台执行 `git checkout` 或改动磁盘文件；原地切换分支必须通过分支菜单的「检出分支…」走预览确认流程。
- 切换工作树或仓库会立即清空上一次的预览确认凭证与跨工作树草稿；分栏宽度、引用栏收起状态与 Unified / Split 偏好按设备尺寸档位（桌面、平板、手机）独立记忆。

## 历史（Log）：拓扑图、组合筛选与两版本比较

- **引用树与快捷范围**：左侧分组列出收藏分支（默认收录主分支）、当前分支、本地分支、远端跟踪分支与标签（窄屏收进抽屉）。上方支持 `所有历史`、`当前分支`、`当前任务`、`待推送`、`远端新增` 五种范围，以及关键字、作者、起止日期与字面路径组合过滤。
- **真实父提交拓扑图**：按 Git 真实 `%P` 父节点绘制多车道实线、过滤省略中间节点时的虚线（`indirect`）以及分页边界短线，滚动触底按游标加载下一页而不重排已有行；远端或终端更新引用后提示“分支引用已更新，可刷新”。
- **合并父节点切换与快照阅读**：右上列出变更文件（单击在底部阅读 Pierre Diff，双击或按 `Enter` 放大到主工作区，`Escape` 返回），右下显示完整提交说明、作者/提交者元组与父提交链接。合并提交可切换不同父节点查看相对于该父提交的真实变更；Diff 工具栏支持打开变更前/变更后完整文件快照或下载原始字节。
- **任意两版本只读比较**：在任一提交行或分支菜单点「设为比较起点」，再在另一提交或分支点「与起点比较」（或直接点「与当前选中提交比较」），即可只读浏览任意两提交之间的文件列表与差异，支持一键「交换方向」与「退出比较」，全程不触碰 `.git/index`。

## 提交（Commit）：真实 `index` 逐块暂存与三态核对

提交面板左侧的 `未提交改动` 按 `冲突 (Conflicts)`、`已暂存 (Staged)`、`未暂存 (Unstaged)`、`未跟踪 (Untracked)` 四组实时映射工作树的真实 `.git/index`：

- **阅读、已审阅、已暂存三态严格分离**：
  - **正在阅读**：当前在右侧 Diff 打开的文件行高亮（`aria-selected`），仅改变阅读目标；
  - **已审阅**：人工核对进度标记（眼睛图标），保存在服务端并与文件内容身份绑定，不影响提交内容；
  - **已暂存**：真实 Git `index` 状态。部分代码块已暂存的同一文件会同时出现在 `已暂存`（对比 `HEAD → index`）与 `未暂存`（对比 `index → working tree`）中，不提供脱离真实索引的本地勾选框列表。
- **常驻逐块暂存栏**：支持逐块暂存的文本修改在 Diff 上方提供常驻可见的代码块操作条（桌面键盘与手机触屏均可直接点击，不依赖鼠标悬停），可跳转到指定块并执行「暂存此块」或「取消暂存此块」。二进制、重命名、符号链接、含 `.gitattributes` 过滤器或超大文件会说明降级原因，仅开放整文件暂存/取消暂存。
- **全量索引预览与提交后树复核**：
  - 编写标题与正文后按 `Ctrl/Cmd+Enter` 或点「提交…」只会打开**完整 `HEAD → index` 提交预览确认框**（列出全部已暂存文件，包括你在终端里提前 `git add` 的文件，并可逐个展开阅读 Diff，核对生效作者身份、签名与可执行 Hook），确认后才真正执行 `git commit`。
  - 提交完成后服务端按真实 reflog 与树对象复核结果：`matched` 表示与预览完全一致；若 `pre-commit` 等钩子自动格式化并改写了提交树，返回 `needs_review` 横幅提示核对新提交并自动中止串联的推送；若服务重启导致结果待核实（`uncertain`），会保留提交草稿并引导先刷新核实，禁止盲目重复提交。

## 固定任务起点审阅：工作区干净也能审完整任务

当 CLI agent 在任务工作树里已经分多次 `git commit` 提交完代码、未提交列表为空时，切到「提交 (Commit)」顶部的 **「相对任务起点的变化」**（或访问 `?view=commit&scope=task`）：

- **自动固定起点，不随分支漂移**：
  - 通过 WebMux 新建工作树时自动记录起始提交（空仓首个会话记录 `unborn` 起点），并用私有引用 `refs/webmux/baselines/<worktreeId>` 保护对象不被 `git gc` 回收；即使后续 `fetch` 或上游推进，任务基线也不会漂移。
  - 已有工作树可在 `Log` 提交行菜单或任务面板一键将指定提交设为任务起点。
- **单份净变更聚合**：服务端把「任务起点 → 当前工作区」合成为每个路径最多一条净变更——agent 中间反复修改又还原的文件自动归零，多次提交加未提交修改只算一次，即使工作区 100% 干净也能完整逐文件审阅 Diff。
- **任务交付收尾摘要**：面板底部汇总净变更文件数、任务提交数、待推提交与关联会话统计，可直接「返回会话」、打开宽幅「推送提交…」对话框、「归档已完成会话」或对 linked 工作树发起安全的「移除工作树…」（推送成功绝不会自动删除工作树）。

## 分支同步与宽幅双栏推送确认

顶栏分支弹层、`Log` 左侧引用树与 `分支 (Branches)` 视图共享同一套分支模型与动作（行尾 `⋯`、右键菜单与键盘 `Shift+F10` 一致）：

- **工作树占用保护**：已被其他工作树检出的本地分支明确标出占用路径与活跃会话数，不提供原地检出，而是引导「打开所在工作树」或「从该提交新建分支工作树…」。
- **获取远程与快进**：支持非交互 `获取远程 (Fetch)` 与基于本地远程跟踪引用的两阶段 `快进更新 (Update)`（详见 [仓库与 worktree](worktrees.md#快进推送与清理分支)）。
- **宽幅推送确认框**：
  - 点「推送…」在桌面打开约 `900px` 双栏确认框（手机端为全屏确认页）：左栏核对 `源分支 → 远程/目标分支`（首次发布可选远程并改远端分支名）、脱敏推送地址与全部待推提交，右栏直接检视所选待推提交的变更文件与 Pierre Diff。
  - “提交并推送…”若在本地提交成功后取消推送或遭远端拒绝，会明确提示本地提交已保留并提供获取远程/快进入口，全程不提供 `--force` 或 `--no-verify`。

## 跨设备协同与交回会话闭环

当你在电脑上委托 agent 编码、在手机或平板上审阅代码时，Git 工作台保持多端状态一致并闭合返工回路：

1. **服务端审阅进度同步与自动失效**：
   - 点击文件的「标记已审阅」通过服务端 `git-workbench-state.json` 按工作树跨设备共享，同时支持 `未提交改动` 与 `相对任务起点的变化`。
   - 审阅键严格绑定两侧模式、Git blob OID 与工作区内容 SHA-256 摘要（不依赖时间戳）：agent 一旦继续修改该文件或重跑暂存，旧的已审阅标记自动失效回到待审阅，过期的旧页面标记请求也会被安全拒绝而不污染新版本。
   - 顶部常驻「已审阅 X/Y」与一键 **「下一处未审阅」** 按钮，窄屏点击后直接进入下一处未审文件的 Diff 阅读页。
2. **乐观锁跨设备提交草稿**：
   - 提交标题与正文自动防抖同步到服务端，仅在真实提交成功落盘后自动清空；预览过期、钩子报错、遇到锁冲突或取消推送都会完整保留草稿。
   - 若两台设备先后编辑同一工作树的提交草稿，后保存的一端收到 `409` 版本冲突时**绝不静默覆盖**，而是在编写区原位并排展示「本机当前输入」与「另一设备已保存版本」，由你选择「保留本机覆盖保存」、「采用远端版本」或「合并两份内容」。
   - 工作树有活跃会话且存在已暂存文件时，还可点「让会话协助起草说明」把暂存文件摘要发往会话草稿框。
3. **返工意见草稿箱安全交回指定会话**：在 `Commit`、`相对任务起点的变化` 或 `Log` 的任意 Diff 中点选单行/连续行号（或点代码块操作条的「加入意见」），补充修改说明后加入按工作树隔离的 **「返工意见草稿箱」**：
   - **防串行号标注**：来自历史提交、`HEAD`、`index` 或任务起点删除侧的摘录会显式标明版本身份并附带代码片段，绝不伪装成当前工作区实时行号；来自当前工作区的摘录在发送前会向服务端复核文件最新内容身份，若文件已被外部更新会先提示确认。
   - **显式选择目标会话**：编辑或发送返工意见不会覆盖正在编写的提交说明草稿：
     - 仅有 1 个活跃会话时默认预选并标明视图（`终端 TUI` 或 `聊天视图`）；
     - **存在 2 个及以上活跃会话时强制显式单选目标会话**，绝不盲发给最近会话；
     - 无活跃会话时支持一键复制结构化 Markdown，或直接打开预填好该工作树与审阅意见的新建会话流程。
   - **只进草稿框，绝不自动回车执行**：确认发送后跳转到所选会话，把结构化审阅意见放入其输入草稿框（终端会话打开底部草稿编辑器而不注入 `\r` 回车，混合聊天视图填入聊天输入框），由你核对后再决定何时发送。

## 边界与常见排障

- **无工作树或只读上下文**：裸仓库（`bare`）或通过 `/git/{repositoryId}` 打开时所有暂存、提交与返工交回按钮均停用；切换到具体工作树即可启用写操作。
- **合并或变基冲突**：存在冲突文件或进行中的 `merge`/`rebase`/`cherry-pick` 时，提交预览会明确阻塞并提供一键打开该工作树终端入口；请在终端解决冲突后再回到工作台暂存提交。
- **检测到 `.git/index.lock`（仓库正忙）**：外部 `git` 进程持有索引锁时接口返回 `busy` 提示，WebMux **绝不会**强行删除外部 `.git/index.lock`，待外部命令结束后刷新重试即可。
- **持久操作状态与断线恢复**：
  - 底部状态栏实时展示最近一次提交、推送、获取远程、快进与分支切换的执行状态和脱敏输出摘要；页面刷新或网络重连后会自动按操作账本恢复结果，不会重复执行底层 Git 写命令。
  - 相关接口与存储细节见 [HTTP API：仓库与代码工作区](../protocol/http-workspace.md#仓库与工作树-git-接口) 与 [配置与持久化清单](../persistence.md)。
