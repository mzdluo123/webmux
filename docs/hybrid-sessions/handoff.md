# 原生历史交接

在会话菜单选择「更换 Agent…」，或选择「交接到新聊天」，填写当前任务并生成预览。
默认把历史渲染成图片；预览展示逐页图片、历史审阅文本、预算、选中数量、省略数量与来源缺口。

## 选择目标和工作位置

- 「更换 Agent」支持填写已有聊天的会话 ID，也可选择启动配置创建新聊天。
- 「交接到新聊天」支持现有目录、仓库工作树和新的 worktree；位置选择复用新建会话控件。
- 可为新聊天填写模型配置。已有聊天沿用其当前配置。
- 新聊天和 worktree 在确认发送后创建；预览只读取来源和计算投影。

## 检查预览与原文

1. 填写当前用户任务，选择目标和工作位置。
2. 保持默认图片模式，或明确选择文本模式，点击「生成预览」；检查图片页序、覆盖、预算与到期时间。
3. 点击「补查冻结原文」分页读取同一原生范围，长项按 UTF-8 字节边界续读。
4. 修改任务、目标、格式或页数后重新生成预览，确认无阻止原因再点击「发送交接」。

图片采用 Snapcompact 机械投影，保留可导出用户/助手正文及可见工具调用和结果；当前任务单独保留原文，不画入历史图片。
默认最多 8 页。超页时重新选择较新的完整片段再渲染，并明确显示省略数量；发送使用预览中冻结的完整页集。
缺字、覆盖不全、渲染失败、图片能力不足或请求超限会阻止发送，不会自动改发文本。
需要文本时，明确切换格式并重新预览。工具输出仍可能经过机械截断，可用冻结原文补查核对细节。
新目标的图片能力在实际创建后确认；已有目标在预览和发送时检查，连接器声明支持图片不等于模型阅读效果保证。
文本预算与图片页数/字节分别显示；图片不保证节省 token 或费用。
来源身份包含 Agent、原生 session、分支与记录边界。预览之后的新记录属于后续范围。
范围内内容发生变化或来源文件消失时，页面显示来源错误。

## 操作状态

发送状态包括准备中、发送中、成功、明确失败与结果不明。
「查看发送结果」读取同一操作句柄；「取消操作」在准备阶段终止工作，发送后取消确认观察且尚无接收证据时显示结果不明。
结果不明时显示「可能已发送，请检查目标会话」，并提供已知目标与新建资源的位置。
完成后可打开目标会话查看 Agent 的回复。
「成功」表示本轮已出现 Agent 活动、授权/提问或成功 prompt 响应，不代表回合已结束或任务已完成。
发送后仍连接但尚无回复时保持发送中，不因模型超过 30 秒才回复就直接判为结果不明；最终答案仍需在目标聊天核对。

## 有效期与升级

预览在当前服务进程中保留五分钟，最多 32 项，manifest、文本与图片表示共同计入 64 MiB 预算。
操作结果最多 256 项，完成后保留十五分钟；同一预览由一个操作消费。
浏览器刷新后表单重新开始，服务重启后旧句柄返回失效。
原文补查依赖对应原生来源与有效快照。目标 Agent 按其原生规则保存收到的内容。
旧会话数据库保留为离线原件，升级操作见[持久化说明](../persistence.md#旧会话数据库与升级)。
协议见[交接预览与操作](../protocol/http-handoff.md)。
