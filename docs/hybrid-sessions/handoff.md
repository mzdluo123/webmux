# 原生历史交接

在会话菜单选择「更换 Agent…」，或选择「交接到新聊天」，填写当前任务并生成预览。
预览展示将发送的完整文本、历史预算、选中数量、省略数量与来源缺口；确认后发送到目标聊天。

## 选择目标和工作位置

- 「更换 Agent」支持填写已有聊天的会话 ID，也可选择启动配置创建新聊天。
- 「交接到新聊天」支持现有目录、仓库工作树和新的 worktree；位置选择复用新建会话控件。
- 可为新聊天填写模型配置。已有聊天沿用其当前配置。
- 新聊天和 worktree 在确认发送后创建；预览只读取来源和计算投影。

## 检查预览与原文

1. 填写当前用户任务，选择目标和工作位置。
2. 点击「生成预览」，检查历史文本、预算和到期时间。
3. 点击「补查冻结原文」分页读取同一原生范围，长项按 UTF-8 字节边界续读。
4. 修改任务或目标后再次生成预览，再点击「发送交接」。

历史采用 Snapcompact 机械文本投影；工具输出按预算截断，当前任务保持原样。
来源身份包含 Agent、原生 session、分支与记录边界。预览之后的新记录属于后续范围。
范围内内容发生变化或来源文件消失时，页面显示来源错误。

## 操作状态

发送状态包括准备中、发送中、成功、明确失败与结果不明。
「查看发送结果」读取同一操作句柄；「取消操作」取消准备工作，发送阶段由实际结果决定状态。
结果不明时显示「可能已发送，请检查目标会话」，并提供已知目标与新建资源的位置。
完成后可打开目标会话查看 Agent 的回复。

## 有效期与升级

预览在当前服务进程中保留五分钟，最多 32 项，文本与 manifest 共用 64 MiB 预算。
操作结果最多 256 项，完成后保留十五分钟；同一预览由一个操作消费。
浏览器刷新后表单重新开始，服务重启后旧句柄返回失效。
原文补查依赖对应原生来源与有效快照。目标 Agent 按其原生规则保存收到的文本。
旧会话数据库保留为离线原件，升级操作见[持久化说明](../persistence.md#旧会话数据库与升级)。
协议见[交接预览与操作](../protocol/http-handoff.md)。
