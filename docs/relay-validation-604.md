# Relay 真实公网验证报告：issue #604

本轮建议 MVP 采用 **WSS + smux v2、控制/交互与批量两条有界连接、嵌入 Go 库**，A 段保持 HTTPS/WebSocket。
服务器 TCP 使用 BBR；不在 MVP 引入 QUIC 优先探测、UDP 回退或 FEC。此决定针对下述实测路径与工程成本，不能概括所有网络或所有 QUIC 实现。
关联：[issue #604](https://github.com/mzdluo123/webmux/issues/604)、[规划 PR #558](https://github.com/mzdluo123/webmux/pull/558)。

## 验证对象与环境

测试于 2026-11-14 执行，统计时间以 UTC 保存。客户端始终位于当前这台电脑，目标为用户提供的 `172.233.136.221`。
正式流量走本机以太网默认路由；没有用服务器内部回环成绩代替公网成绩，也没有通过本机环境代理转发测试流量。

测量子进程清除所有名称含 proxy 的环境变量，设置 `NO_PROXY=*`；Go HTTP Transport 显式 `Proxy:nil`，SSH 显式禁用 ProxyCommand/ProxyJump。
依赖和发布包下载属于准备阶段，不计入正式吞吐。Hysteria 是被测的显式受管转发器，与环境代理分开记录。
WSL 仅加载 BBR 模块并按测试 socket 设置，不更改用户 WSL 全局默认 CUBIC；其他开发服务不接入本实验。
设置 default_qdisc 不会替换既有网卡队列。本轮保留 eth0 的 mq/fq_codel，不能宣称已经测过物理接口 fq；MVP 的 fq 部署建议仍需核实实际队列。
frpc 未逐 socket 改 BBR，使用 WSL 默认 TCP 策略；Windows OpenSSH 使用原生 TCP 策略。它们是完整产品对照，不混作双端 BBR 组件成绩。
地区、运营商和机房地理位置未独立确认；不发布客户端公网 IP，不把此单出口结果称为全国多运营商验证。

## A、B 与组合路径

```text
A：当前电脑客户端 → 公网 → 远程 HTTPS 入口 → 远程回环 WebMux
B：当前电脑 WSL 宿主 → 公网 → 远程 Relay，宿主主动出站建立反向通道
A+B：当前电脑客户端 → 公网 → 远程入口 → B 反向通道 → 当前电脑 WSL WebMux
```

组件矩阵在同一真实公网路径上测 B 候选的字节流与并发小回显；随后用真实 WebMux 做 A 和 A+B 的 PTY、REST、文件及转发验证。
A 与 B 都跨同一 WAN 时，输入到真正 PTY 输出会经历两段路径；仅优化 B 无法消除 A 的往返时间。
真实 PTY 运行 `stty -echo -icanon min 1 time 0; exec cat`，收到当次随机标记才停止计时；不用本地回显或库 Write 返回替代远端确认。
后端构建嵌入明确标注的测试静态夹具，没有将其描述为完整前端构建或浏览器验收。

版本以 go.mod/go.sum、构建信息及发布 tag 固定；许可证对照固定源码，不据“有新 tag”直接推断长期维护承诺。
旧 `direct`/`kcp-fast` 数据使用 coder v1.8.12、smux v1.5.24、quic-go v0.59.1、kcp-go v5.6.72，保留作调参历史，不与 current 合并统计。

- TLS 使用测试 ECDSA P-256 证书、正常根/主机名校验及测试 mTLS，TLS 1.3；没有 skipVerify，没有开放 0-RTT。
- 测试 mTLS 共用夹具证书，不等于生产逐宿主 Ed25519 nonce、GitHub 授权、SPKI pin、轮换和撤销已经实现；这些生产任务继续待验收。
- smux 每连接接收缓冲 4 MiB、每 stream 1 MiB；yamux stream 窗口 1 MiB。QUIC stream 1 MiB、connection 4 MiB，保活 10 s、idle 60 s。
- smux 保活间隔 10 s、失活 30 s、最大 frame 32 KiB；yamux 沿用保活 30 s、连接写超时 10 s 等固定版本默认值，不声称所有 mux 的心跳与窗口完全等价。
- pool=1 共用连接；pool=2 将交互与批量分开；pool=4 追加筛选。连接数扩大总 cwnd/窗口/内存预算，不能声称各 pool 具有相同总资源。
- KCP MTU=1350，nodelay=1、interval=20 ms、fastresend=2、ACKNoDelay；nc=0/window=256 为保守对照，nc=1/window=1024 为激进对照。
- nc=1 关闭 KCP 自身拥塞窗口，不能称为 BBR；FEC 使用 10 data + 3 parity，理论满组冗余 30%，实际损耗另外测量。
- quic-go v0.59.1 与 v0.65.0 的默认发送器实际启用 Reno；构造器名称含 Cubic 不代表启用了 CUBIC，更不能把结果归因于 BBR。
- Hysteria 自动模式用其用户态 BBR；固定 5/20/50 Mbps 使用 Brutal。内核 BBR 不会改变 QUIC/KCP/Brutal 的算法。
- Hysteria 使用 TLS 服务身份、随机密码与固定目标 ACL，frp 使用 mTLS + Token；SSH 使用独立 host key。产品对照不等同于完全相同身份流程的封装开销实验。

## 网络损伤与统计口径

服务端为被测服务建立专用 relay604 network namespace、veth 与 DNAT；netem 只作用于测试 veth，不修改管理 SSH 路径或公网接口队列。
损伤在真实 WAN 之上叠加，clean 表示无人工注入，不表示物理路径零丢包。

| 档位    | 双向配置 / 实测边界                                                                     |
| ------- | --------------------------------------------------------------------------------------- |
| clean   | 自然 RTT 约 300 ms；UDP 中位数约 307 ms                                                 |
| loss1   | 每方向随机丢包 1%，每方向 20 Mbps；200 次 UDP 探测往返丢包 1.5%                         |
| loss3   | 每方向随机丢包 3%，每方向 5 Mbps；不是端到端仅 3% 丢包的承诺                            |
| burst   | gemodel 1% / 25% / 80% / 0.1%，每方向 5 Mbps                                            |
| asym    | 客户端上传 1 Mbps、下载 20 Mbps                                                         |
| rtt500  | 每方向额外 100 ms、20 ms 正态抖动、1% 丢包、20 Mbps；实测 RTT 中位数 509 ms、p95 555 ms |
| mtu1280 | 测试 veth MTU 1280；QUIC 默认参数与初始包 1200 字节分测                                 |

netem seeds=604/605，队列 limit=1000；未显式开启 duplicate/reorder，但 delay 抖动可能隐式重排，因此 rtt500 不是纯 RTT 单变量实验。
50/150 ms 不能在当前约 300 ms 公网链路上凭空实现；本轮不伪造这两个真实公网档位，也未穷举 0.5/5% 丢包与 50 ms 抖动。

组件每阶段一般 12 s 小回显，clean 双向各 16 MiB、弱网各 8 MiB；个别故障/MTU 样本更小，以原始命令为准。
AES-256-CTR 固定测试流不可压缩，接收方 SHA-256 确认；速度以已确认有效字节/墙钟时间计算，hash 失败不作为有效吞吐。
只将 bulk 仍活动时开始的交互样本纳入并发统计；p50/p95/p99 使用排序后 floor((n-1)*q)，失败数另列。
多数协议/档位只有一次串行筛选，Hysteria 有两轮；数十次回显的 p99 不代表总体极端尾部，不能据此建立置信区间或微小优势排名。
测试顺序轮换/反转，未在同一物理链路并行跑多个测速器；不同操作系统和时间段的波动仍是混杂因素。

A 的空闲 PTY 中位数约 317 ms，A+B 约 585 ms；这说明 A 本身有真实 RTT 成本，两段绕行会叠加，不能将组件小回显当作端到端 PTY。

frp QUIC 默认配置的 8 MiB 上传返回 502，未执行后续下载，不能计作成功吞吐。其原始 upload bytes 是请求量，不证明接收成功；502 根因尚未定位。
frp 的直接 WSS 接入曾 unexpected EOF；补测使用 mTLS 前置 19005 → 回环 frps 19006，后者只监听回环，不为连通而关闭公网身份验证。
frp 使用 tcpMux=true、poolCount=0，内置 yamux stream 窗口 6 MiB 等默认值，与组件矩阵的窗口和双连接不同；仅作为完整产品集成对照。

### 关闭、取消、黑洞与恢复

- TLS 有效证书通过；缺失客户端证书、错误 CA、错误主机名、TLS 1.2 的应用接入均拒绝。测试 ECDSA P-256 检查通过。
- 8 种 TLS/WSS/QUIC/KCP 组合的 half-close 对照均能发送后半关闭并收到接收端 SHA-256 响应。
- QUIC 取消批量 stream 后，兄弟回显 stream 继续成功（约 300 ms）；此优势不等同于连接拥塞预算完全隔离。
- UDP 黑洞下 QUIC 建连约 5.23 s 失败，WSS 直接成功；未实现也未声称完成生产自动回退。
- MTU 1280 下 QUIC 默认初始包握手失败；双方 InitialPacketSize=1200 后 pool 1/2 均连通并通过哈希。WSS 同档也通过。
- Relay/宿主连接器由脚本编排重启，观测到入口不可用约 2.63 s，host ready 约 8.84 s、恢复操作约 10.16 s；离线输入确认、同代际 offset append 与标记恰好一次通过。
- 停止读取批量流 20 s 时，WSS/smux pool 1/2/4 均能回收连接（关闭约 0.4–3.8 ms）；这只是短时背压检查，不能证明任意慢端/任意宿主数量的内存上限。

## 组件嵌入与完整产品成本

MVP 嵌入 coder/websocket、smux 和标准库 ReverseProxy，保持 CGO_ENABLED=0，减少分发二进制、子进程监督、配置/密钥文件及跨进程 readiness。
仍需实现 GitHub 数字账号映射、每账号一机、固定随机 Host、逐宿主认证、角色/代际、总配额、精确回源与撤销；成熟传输库不会自动提供这些控制面语义。
frp 可以减少通用转发开发，但必须封装身份映射/授权插件、限制任意代理和端口、监管进程/版本/凭据，并补交互/批量隔离；直接复用不是“只写登录页面”。
Hysteria 需额外实现反向通道或改造角色；SSH 需维护独立主机密钥信任和限制账户，不能静默复用 TLS pin。此工程差异是选型依据之一。
